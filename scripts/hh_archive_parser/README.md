# hh_archive_parser — Архивные вакансии hh.ru через официальный API

Парсит **АРХИВНЫЕ** (закрытые) вакансии hh.ru за период через
`api.hh.ru/vacancies?archived=true`. Фильтрует под PR-нишу
по тем же словарям что и оригинальный `hh_parser`.

## Чем отличается от `hh_parser` (старого)

| | `hh_parser` (HTML) | `hh_archive_parser` (этот) |
|---|---|---|
| Источник | `hh.ru/search/vacancy` HTML | `api.hh.ru/vacancies` JSON |
| Что отдаёт | Только активные | **Активные ИЛИ архивные** (флаг `ARCHIVED`) |
| Парсинг | Регекс по встроенному в HTML JSON | Чистый JSON-ответ API |
| Стабильность | Сломается при редизайне HH | Стабильнее |
| User-Agent | Любой браузерный | **Обязательно с email** (требование HH ToU) |
| Rate limit | 1 RPS (≥0.8 c) | 2-3 RPS работают стабильно |
| Лимит выдачи | 2000 / запрос | 2000 / запрос (тот же, обходим chunking'ом) |

## Быстрый старт

```bash
# Зависимостей нет — Python 3.10+ stdlib
python run_all.py
```

Что произойдёт:
1. **`scraper.py`** — пройдёт по 12 PR-запросам, режа период по месяцам
   (обход лимита 2000), сложит в `output/vacancies_raw.csv`.
2. **`filter.py`** — отфильтрует по 3-корзинной логике (явно PR / явно
   мусор / пограничные с скрейпом описания), сложит в
   `output/vacancies_filtered.csv`.

## Про лимит 2000

HH **архитектурно режет любой запрос** к индексу на 2000 результатов:
`page × per_page ≤ 2000`. С `per_page=100` это `page=0..19`.

**Это общий потолок** — не зависит от:
- OAuth токена (он даёт стабильный rate limit, но не больше выдачи)
- `archived=true` / без него
- Регистрации приложения на dev.hh.ru

**Обход — splitting**. В этом парсере параметр `CHUNK_STRATEGY` в `config.py`:
- `single` — один запрос на весь период (рискуем потерять >2000)
- `monthly` (дефолт) — режем по месяцам
- `weekly` / `daily` — для широких ниш

Скрипт **сигналит в консоль** если в одном чанке `found > 2000` —
тогда переключаем стратегию на более узкую.

## Настройка под другую нишу

`config.py` — все настройки тут.

### Поисковые запросы
```python
SEARCH_QUERIES = ["PR-менеджер", "пресс-секретарь", ...]
```

### Период (архив)
```python
DATE_FROM = "2025-01-01"
DATE_TO   = "2025-12-31"
ARCHIVED  = True          # ← True = архив, False = активные
```

### Регион
```python
AREA = "113"   # 113=РФ, 1=Москва, 2=СПб. Полный список: https://api.hh.ru/areas
```

### User-Agent
```python
USER_AGENT = "PolzaAgency-HHArchiveParser/1.0 (contact@polzaagency.ru)"
```
**Обязательно с email** — HH блокирует анонимные UA через 403.

### OAuth (опционально)
```python
OAUTH_TOKEN = ""
```
Заполнить, если упираешься в anonymous rate limit. Регистрация:
https://dev.hh.ru → Создать приложение → Client Credentials flow.
На лимит 2000 это не влияет — только на RPS на токен.

### Стратегия обхода 2000
```python
CHUNK_STRATEGY = "monthly"  # single | monthly | weekly | daily
```

### Фильтр ключевых слов
Те же `PR_TITLE_KEYWORDS` / `TRASH_TITLE_KEYWORDS` / `PR_DESC_KEYWORDS`
что и в `hh_parser`. Логика 3-корзинной фильтрации не изменилась.

## Выходные колонки

| Колонка | Источник |
|---|---|
| `Вакансия_URL` | `https://hh.ru/vacancy/{id}` (даже для архивной открывается, баннер «в архиве») |
| `Название_вакансии` | `name` из API |
| `Компания` | `employer.name` |
| `Сайт_компании` | `employer.site_url` (когда есть в search-ответе) |
| `Город` | `area.name` |
| `Работодатель_hh_URL` | `https://hh.ru/employer/{employer.id}` |
| `Дата_публикации` | `published_at` ISO — новое поле, в HTML-парсере было недоступно |

## Если 403

API HH блокирует:
- Запросы без `User-Agent` → проверь что задал свой email в config.
- DDoS-protection по IP → попробуй через VPN/прокси (либо просто подожди 10-15 мин).
- Превышение rate limit → подними `REQUEST_DELAY` до 1.0+ или подключи OAuth.

## Архитектурный план полного покрытия

Если хочешь **всю РФ за весь 2025 год** по широкой нише:

1. `CHUNK_STRATEGY = "weekly"` (52 чанка × до 2000 = до 104k записей).
2. Дополнительно разбить по `AREA` (региону) — список из `https://api.hh.ru/areas`
   подгрузить и итерировать. Тогда лимит 2000 применяется на (запрос × неделя × регион).
3. Параллелить — если 1 RPS мало, использовать несколько OAuth-токенов (разные приложения).

Для PR-ниши в РФ за год обычно достаточно `monthly` — потока в неделю
обычно < 500 PR-вакансий.

## Технические детали реализации

- **Только stdlib**, никаких pip-зависимостей.
- `urllib.request` для HTTP, `json` для парсинга, `csv` для I/O.
- `concurrent.futures` для распараллеливания фильтра.
- `seen_ids.txt` для инкрементальных запусков (как в оригинале).
