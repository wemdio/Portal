# ICP-таргетинг по выгрузке 2GIS

Превращает сырую выгрузку 2GIS (карточки организаций) в базу компаний под
конкретный ICP: схлопывает дубли до юрлиц, отсекает не-ЦА по рубрикам,
добирает email с сайтов и ранжирует по признакам масштаба.

Первый прогон — сегмент «Строительство / Недвижимость / Ремонт» под
Alial Group (Directum RX). Разметка ICP лежит в `lib_icp.py` и меняется под
другой продукт без правки остального пайплайна.

## Зачем отдельный слой

Выгрузка 2GIS — это **карточки объектов, а не компании**. У ПИК 667 карточек
(каждый офис продаж ЖК — своя), у ЛСР 104. Плюс в поле `website` попадают
`t.me`, `jivo.chat`, агрегаторы. Без схлопывания база из 28 тыс. строк
превращается в 28 тыс. «компаний», из которых половина — один и тот же
застройщик.

Второе: email заполнен у 18% карточек, а **уникальных адресов среди них
всего 959** — то есть почта есть примерно у 6% компаний. Основной объём
контактов берётся с сайтов, а не из выгрузки.

## Пайплайн

```bash
export GIS_CSV=/path/2gis_russia.csv
export GIS_WORK=/path/workdir          # промежуточные файлы и результат
curl -o "$GIS_WORK/psl.dat" https://publicsuffix.org/list/public_suffix_list.dat

python3 build_base.py     # карточки -> companies.jsonl (схлопывание + скор)
WORKERS=96 python3 crawl.py   # сайты -> crawl.jsonl (email, ИНН, <title>)
python3 export_base.py    # -> *.csv + report.md
```

`crawl.py` возобновляем: уже обойдённые домены пропускаются, поэтому прогон
можно прервать и продолжить. Обходит в порядке убывания скора — если
остановить на середине, обойдены будут самые ценные.

## Как схлопываются компании

Ключ — регистрируемый домен (eTLD+1), иначе нормализованное название + город.

Тонкость: PSL знает `msk.ru` и `spb.ru`, но не остальные региональные
хостинги. Их пришлось доразметить вручную (`EXTRA_SUFFIXES` в `lib_norm.py`):
под `perm.ru`, `vrn.ru`, `tomsk.ru` сидят **разные** компании, значит
`spk.perm.ru` — самостоятельное юрлицо. И наоборот: `ekaterinburg.brusnika.ru`,
`tyumen.brusnika.ru` — это один застройщик, их обязательно схлопнуть.
Автоматически эти два случая не различаются (у застройщика поддомены тоже
называются по-разному — по имени ЖК), поэтому список размечен глазами и
зафиксирован в коде с комментарием.

## Как выбирается название компании

Карточка застройщика названа именем ЖК («Саларьево парк, жилой комплекс»), а
не компании. Четыре стратегии по убыванию надёжности:

1. общий бренд-префикс до запятой у **разных** карточек («DOGMA, ЖК …»);
2. карточка, чьё название совпадает с меткой домена (через транслит);
3. не-проектное название карточки — только если объектов мало;
4. производное от домена (`lsr.ru` → `LSR`) как плейсхолдер, который
   `export_base.py` заменяет на бренд из `<title>` сайта.

Требование «префикс встречается у разных карточек» существенно: без него у
`a101.ru` побеждала «Скандинавия» — просто самый растиражированный ЖК.

## Скоринг

Аддитивный и прозрачный: каждое слагаемое пишется в колонку `score_reasons`.

| Признак | Вклад |
|---|---|
| Рубрика T1 / T2 | +40 / +20 |
| B2C-рубрика | −8 (у T1) / −15 |
| Объектов в 2GIS: 30+ / 10-29 / 5-9 / 2-4 | +30 / +24 / +16 / +8 |
| Городов присутствия: 4+ / 2-3 | +12 / +6 |
| Свой домен | +10 |
| Почта на своём домене / только free-mail | +10 / +3 |
| Москва-Питер / город-миллионник | +2 / +1 |

**Число объектов и география — это прокси масштаба, а не факт.** В 2GIS нет
ни выручки, ни штата. Чтобы отфильтровать по реальному размеру, нужен ИНН и
данные ФНС (`app/scripts/import-fns-revenue.mjs`). Поэтому `crawl.py` попутно
снимает ИНН/ОГРН с сайтов — по этим компаниям фильтр по выручке делается
сразу, без фаззи-резолва по названию.

## Ограничения

- Сайты на JS-рендеринге и под антиботом (Qrator/Cloudflare) почту не отдают.
  Такие домены видны в `*_no_email.csv` по колонке `crawl_err`.
- ИНН снимается примерно с 12% сайтов — он обычно в подвале страницы
  реквизитов, куда обход не всегда доходит.
- Скор не заменяет квалификацию: он ранжирует, а не подтверждает ЦА.
