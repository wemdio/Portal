# Подсчёт лидов: ДВА КАПКАНА (читать ПЕРЕД любым подсчётом «горячих / заинтересованных / не дожатых»)

Самая частая ошибка. Никогда не считай лидов по тексту входящего или по флагу — только так.

## Капкан 1 — забыть вычесть НАШИ ответы
`raw_emails.ue_type`: **1**=наше исходящее (шаг кампании), **2**=ответ лида, **3**=наш РУЧНОЙ ответ из инбокса.
Если на письмо лида мы УЖЕ ответили (`ue_type=3` позже его последнего ответа) — он НЕ «брошенный».
Источник истины — вьюха **`v_dropped_hot_leads`** (она уже вычитает наши ответы по тредам). НЕ считай «не дожатых» по `body_text`/`positive`/`llm_label='interested'` — насчитаешь лишних.
(Реальный случай: насчитали «6» вместо «2» — четверым уже ответили.)

Готовый запрос «кого не дожали по проекту» (заодно тянет текст для проверки):
```sql
SELECT rc.name AS campaign, d.lead_id AS email, round(d.age_days) AS age_days,
       left(regexp_replace(e.body_text, E'\\s+',' ','g'), 300) AS reply_text
FROM v_dropped_hot_leads d
JOIN raw_campaigns rc ON rc.id = d.campaign_id
JOIN LATERAL (SELECT body_text FROM raw_emails
              WHERE lead_id=d.lead_id AND campaign_id=d.campaign_id AND ue_type=2
              ORDER BY timestamp_email DESC LIMIT 1) e ON true
WHERE d.campaign_id IN ( /* SELECT campaign_id FROM v_campaign_client WHERE client ILIKE '%X%' */ )
ORDER BY d.age_days DESC;
```

## Капкан 2 — поверить авто-метке `interested`/`positive`
`v_dropped_hot_leads` доверяет `llm_label='interested'`, поэтому в список попадают автоквитанции
(«ваше письмо получено, ответим за 1–2 дня»), привратники («пришлите на info@ / на офиц. бланке»)
и секретарь/колл-центр («для начала расскажите»). Это НЕ лиды — это ответы-гигиена.
**ОБЯЗАТЕЛЬНО прочитай `reply_text` каждого** и раздели в ответе: «N кандидатов из вьюхи → M реальных лидов»
(реальный лид = роль/потребность/готовность к шагу). Никогда не отдавай число из вьюхи как «горячие лиды» без чтения текстов.

## Честное ограничение
Вьюха видит только ответы через Instantly (`ue_type=3`); ответ, отправленный с личной почты вне Instantly, в датасет не попадает → лид может ложно остаться «не дожатым». Так же считает счётчик «Брошенные горячие лиды» на странице проекта в Портале (та же логика — ограничение раскрыто в UI).
