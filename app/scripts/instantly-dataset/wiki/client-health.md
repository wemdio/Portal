# Разбор клиента / проекта — как анализировать

Когда тебя просят *«разбери клиента X»*, *«как идёт проект X»*, *«что улучшить у X»* —
прорабатывай вопросы ниже, используя ТОЛЬКО этот read-only датасет. Отвечай с
суждением (не просто числа), копай в *почему*, и честно говори, когда данных мало.

---

## Шаг 0 — найти кампании клиента (внутри датасета)

Лучший путь — **портальный мост** (авто-матчинг Портала, зеркалится в `portal_*`, см. док `portal-data`):

```sql
-- проект клиента → его кампании:
SELECT b.campaign_id FROM portal_projects p
JOIN portal_project_campaigns b ON b.project_id = p.id
WHERE p.client ILIKE '%X%';
```
Запасные пути: `v_campaign_client WHERE client ILIKE '%X%'` (разметка по имени кампании)
или `raw_campaigns WHERE name ILIKE '%X%'`. Ниша кампании — `v_campaign_segment`.

Покрытие клиент-разметки — почти все кампании, но не 100%; если клиент не нашёлся в
`v_campaign_client`, ищи по имени. Какие кампании активны/завершены — `status` +
`lookup_campaign_status` (`1=active`, `3=completed`, `2=paused`, `-1/-2`=проблемы ящиков).

## Базовые вопросы (по кампаниям клиента)

| # | Вопрос | Где смотреть | Что значит «плохо» |
|---|---|---|---|
| 1 | **Объём отправки** | `v_campaign_daily_canonical` (sent по датам) или `v_campaign_summary.sent_lifetime` | 0 за период при >0 раньше = кампании встали |
| 2 | **Open rate** | `v_campaign_summary.open_rate_pct` или `lifetime_unique_opens/lifetime_sent` (health) | <20% слабо; >60% часто артефакт prefetch (см. key-metrics) |
| 3 | **Reply rate** | `v_campaign_health.reply_rate` | <0.5% слабо. ⚠️ знаменатель — см. гоча в key-metrics |
| 4 | **Качество лида (money-метрика)** | `v_campaign_health.lead_rate_labeled` + `interested_repliers` | надёжно ТОЛЬКО при `labeled_repliers ≥ ~20`; иначе выборка мала |
| 5 | **Доставляемость / ящики** | `v_campaign_health.bounce_rate_lifetime`; ящики `v_campaign_mailboxes` JOIN `raw_accounts` | bounce >4% тревога, >8% критично; >30% деградировавших ящиков критично |
| 6 | **Темы писем** | `v_subject_performance` (sent≥50) | мёртвые темы (0% reply) убрать. НО см. playbook: сабджекты — low-leverage для лидов |
| 7 | **Цепочка** | `v_subject_performance` по `step_n` | где гаснет отдача; паттерн датасета: к шагу 3 ~99.7% всех ответов |

Не просто репортить число — **кросс-чек**. Напр.: низкий reply (Q3) + здоровые ящики
(Q5) + равномерно низко по всем темам (Q6) ⇒ проблема в **базе/ICP клиента**, а не в
нашей доставке. Этот синтез — и есть смысл.

## Глубокий разбор («что улучшить / какие ниши брать / как менять цепочку»)

Метод (как делался разбор Bero.pro, 2026-06-30 — см. playbook):

1. **Перформанс vs БЕНЧМАРК.** Сравни каждую кампанию с медианой ЕЁ НИШИ, взяв **обе
   цифры из ОДНОЙ вьюхи** (`v_campaign_health`, `sent_retained ≥ 200`). Money-метрика =
   `lead_rate_labeled`, не reply (playbook: reply >~1% — vanity для лидов).
2. **Ниши.** Какие ниши клиента бьют выше/ниже медианы. Рейтинг ниш по lead-rate — в
   playbook; ниша/ICP — главный рычаг лидов.
3. **Источники.** Источник списка зашит в имя кампании (СБИС/Руспрофайл/HH/2ГИС/ЦИАН/
   Яндекс.Карты…). Рейтинг источников по тёплости — в playbook и `источники.md`.
4. **Цепочка.** Держать ~4 шага (1 cold + 3 follow-up); follow-up'ы НЕ резать (несут
   ~половину лидов), но шаг 5+ почти пуст.
5. **Ответы.** `v_reply_outcomes` (`llm_label`, `positive`, `instantly_interested`).
   Часто ~50% ответов — `auto_reply` (не лиды, не считать). Читать тексты —
   `raw_emails WHERE ue_type=2` (поле `body_text`): возражения, сигналы интереса.
   ⚠️ «Кого не дожали» бери ТОЛЬКО из `v_dropped_hot_leads` (она вычитает наши
   ответы `ue_type=3`), НЕ по тексту/`positive` — иначе насчитаешь лишних, кому
   мы уже ответили. `ue_type`: 1=наше исходящее, 2=ответ лида, 3=наш ручной ответ.
6. **Доставляемость.** Bounce по нишам/источникам: высокий bounce = неверифицированная
   база, а не инфраструктура.

## Стиль ответа

- Отвечай на языке вопроса, показывай SQL и реальные числа.
- Малые выборки (sent<200, labeled_repliers<20) помечай как ненадёжные.
- Никогда не выдумывай: пустой результат — так и скажи.
