# Контекст Для ИИ: API Портала Polza

Этот файл дают ИИ-помощнику или разработчику вместе с API-ключом пользователя.
Цель: помочь правильно пользоваться API портала Polza для кастомизаций,
автоматизаций и собственных скриптов поверх инструментов портала.

API-ключ в этот файл не вставлять.

## Главное

Пользователь получил API-ключ для программного доступа к инструментам портала
Polza.

Базовый адрес API:

```text
https://polza-portal.ru/api/bench/v1
```

Авторизация во всех запросах:

```text
Authorization: Bearer <API_KEY>
```

Альтернативный вариант, если заголовок `Authorization` уже занят:

```text
X-Api-Key: <API_KEY>
```

API-ключ выглядит примерно так:

```text
bench_live_...
```

Не показывай полный API-ключ в ответах, логах, примерах, файлах, issue,
коммитах, pull request, публичных чатах и GitHub. Если нужно показать пример,
пиши `<API_KEY>`.

## Что Умеет API

API позволяет делать из программы то, что обычно делают руками в портале:

- запускать парсеры;
- запускать конструктор баз;
- проверять статус запущенных задач;
- забирать результаты задач;
- искать по уже собранным базам.

API не создаёт отдельную новую систему. Он ставит задачи в те же очереди и
использует те же инструменты, что и интерфейс портала.

## Что API Не Делает

API не даёт:

- удалять задачи или данные;
- смотреть чужие задачи и чужие результаты;
- использовать инструменты, которые не разрешены конкретному ключу;
- заходить во внутренние разделы портала;
- получать финансы, клиентов, задачи команды и другие внутренние данные;
- обходить лимиты.

Если задача или результат принадлежат другому ключу, API отвечает так же, как
если бы задачи не существовало.

## С Чего Начинать

Всегда начинай с:

```text
GET /tools
```

Полный URL:

```text
GET https://polza-portal.ru/api/bench/v1/tools
```

Эта ручка показывает:

- какие инструменты доступны текущему ключу;
- какие из них являются долгими задачами;
- какие являются быстрым поиском;
- какие параметры принимает каждый инструмент;
- можно ли остановить задачу этого инструмента.

Не угадывай доступные инструменты и параметры вручную. Сначала получи каталог
через `/tools`, потом строй запросы по нему.

## Два Типа Инструментов

В API есть два типа инструментов.

### 1. Долгие Задачи

Это парсеры и конструктор баз. Они могут работать минуты или часы.

Порядок работы:

1. Создать задачу.
2. Периодически проверять статус.
3. Когда задача готова, забрать результат.

Ручки:

```text
POST /jobs
GET /jobs/{id}?tool=<tool>
GET /jobs/{id}/results?tool=<tool>
GET /jobs?tool=<tool>
POST /jobs/{id}/stop?tool=<tool>
```

Опрос статуса делать не чаще, чем раз в 10-30 секунд. Частый опрос тратит
лимит запросов и не ускоряет задачу.

### 2. Быстрый Поиск

Это поиск по уже собранным базам. Он отвечает сразу.

Ручка:

```text
POST /search
```

## Доступные Долгие Инструменты

Конкретный ключ может видеть не все инструменты. Проверяй доступность через
`GET /tools`.

Возможные долгие инструменты:

- `base-constructor` - конструктор баз;
- `yandexmaps` - Яндекс.Карты;
- `googlemaps` - Google Maps;
- `googlenews` - Google News;
- `hh` - HH;
- `ats` - поиск компаний по ATS-системам;
- `eng-hiring` - англоязычный hiring-парсер;
- `hh-archive` - архив HH;
- `search` - поисковый парсер;
- `yandex-direct` - Яндекс.Директ;
- `inn-enrich` - обогащение по ИНН.

## Доступные Быстрые Источники

Конкретный ключ может видеть не все источники. Проверяй доступность через
`GET /tools`.

Возможные источники быстрого поиска:

- `company-base` - наша база компаний;
- `2gis` - база 2GIS;
- `our-bases` - наша база баз.

## Создание Долгой Задачи

Ручка:

```text
POST /jobs
```

Тело запроса:

```json
{
  "tool": "<tool>",
  "params": {}
}
```

`tool` - идентификатор инструмента из `/tools`.

`params` - параметры конкретного инструмента. Их нужно брать из ответа
`GET /tools`.

Пример маленькой задачи Яндекс.Карт:

```json
{
  "tool": "yandexmaps",
  "params": {
    "search_urls": [
      "https://yandex.ru/maps/?text=кофейни"
    ],
    "max_results": 10
  }
}
```

Пример ответа:

```json
{
  "id": "15dd57f6-3b89-43bc-826e-45a921a48662",
  "tool": "yandexmaps",
  "status": "queued",
  "progress": {
    "done": 0,
    "total": null
  },
  "rows_found": 0,
  "error": null,
  "created_at": "2026-09-01T17:15:15.698021+00:00",
  "finished_at": null
}
```

Сохрани `id`: он нужен для проверки статуса и получения результатов.

## Статусы Задач

Возможные статусы:

- `queued` - задача в очереди;
- `running` - задача выполняется;
- `done` - задача готова;
- `failed` - задача завершилась с ошибкой;
- `stopped` - задача остановлена.

Если статус `queued` или `running`, нужно подождать и проверить позже.

Если статус `done`, можно забирать результаты.

Если статус `failed`, смотри поле `error`.

## Проверка Статуса

Ручка:

```text
GET /jobs/{id}?tool=<tool>
```

Пример:

```text
GET /jobs/15dd57f6-3b89-43bc-826e-45a921a48662?tool=yandexmaps
```

`tool` обязателен. Не пропускай его.

Не проверяй статус каждую секунду. Нормальный интервал - 10-30 секунд.

## Получение Результатов

Ручка:

```text
GET /jobs/{id}/results?tool=<tool>&limit=200&cursor=<cursor>
```

`limit` - размер страницы. Обычно 100-500. Максимум зависит от API, безопасно
использовать 200.

`cursor` нужен только если предыдущий ответ вернул `has_more: true`.

Пример ответа:

```json
{
  "rows": [
    {
      "name": "Example company"
    }
  ],
  "cursor": "next-cursor",
  "has_more": true
}
```

Если `has_more` равно `true`, повтори запрос и передай `cursor`.

Если `has_more` равно `false`, выгрузка закончена.

Не используй номера страниц и offset. В этом API результаты забираются через
cursor.

## Список Своих Задач

Ручка:

```text
GET /jobs?tool=<tool>
```

Показывает последние задачи текущего ключа по выбранному инструменту.

Можно добавить фильтр:

```text
GET /jobs?tool=<tool>&status=done
```

Другие ключи и другие пользователи в этом списке не видны.

## Остановка Задачи

Ручка:

```text
POST /jobs/{id}/stop?tool=<tool>
```

Остановка поддерживается не у всех инструментов. Проверяй поле
`stop_supported` в ответе `/tools`.

Если инструмент не поддерживает остановку, API вернёт ошибку `conflict` с
понятным объяснением.

Не пытайся останавливать инструмент методом проб. Сначала смотри `/tools`.

## Быстрый Поиск

Ручка:

```text
POST /search
```

Тело запроса:

```json
{
  "source": "<source>",
  "filters": {},
  "limit": 100,
  "cursor": null
}
```

`source` - источник из `/tools`, например `company-base`.

`filters` - фильтры конкретного источника. Их нужно брать из ответа
`GET /tools`.

`limit` - сколько строк вернуть за один запрос.

Пример:

```json
{
  "source": "company-base",
  "filters": {
    "country": ["russia"],
    "name": "test"
  },
  "limit": 100
}
```

Ответ приходит сразу:

```json
{
  "rows": [],
  "cursor": null,
  "has_more": false
}
```

Если `has_more` равно `true`, нужно повторить запрос с `cursor`.

## Частые Параметры Инструментов

Точные параметры всегда смотри через `GET /tools`. Ниже только ориентир.

`yandexmaps`:

- `search_urls` - список ссылок на выдачу Яндекс.Карт;
- `max_results` - сколько результатов запросить.

`googlemaps`:

- `input_lines` - поисковые запросы;
- `limit_per_query` - лимит на запрос;
- `language` - язык;
- `region` - регион;
- `enrich_contacts` - обогащать контактами или нет.

`googlenews`:

- `input_lines` - запросы;
- `limit_per_query` - лимит на запрос;
- `language` - язык;
- `region` - регион.

`hh`:

- `text` - поисковый запрос;

- `salary_from` - зарплата от;

- `fetch_employers` - собирать работодателей или нет.

`hh-archive`:

- `search_queries` - поисковые запросы;

## Лимиты

У ключа есть ограничения. Они нужны, чтобы случайный скрипт не перегрузил
портал и не потратил общий пул ресурсов.

Обычно ограничиваются:

- запросы в минуту;
- новые задачи в сутки;
- строки результатов в сутки;
- одновременные задачи.

Если API вернул лимитную ошибку, не повторяй запрос сразу.

## Ошибки

Формат ошибки всегда одинаковый:

```json
{
  "error": {
    "code": "...",
    "message": "...",
    "details": null
  }
}
```

Коды:

- `unauthorized` - нет ключа, ключ неверный или ключ отозван;
- `tool_not_allowed` - инструмент не открыт этому ключу;
- `invalid_params` - неверные параметры;
- `rate_limited` - слишком много запросов за минуту;
- `quota_exceeded` - закончился суточный лимит;
- `not_found` - задача не найдена или недоступна;
- `conflict` - действие сейчас невозможно;
- `server_error` - ошибка на стороне портала.

Что делать:

- при `unauthorized` проверить ключ;
- при `tool_not_allowed` попросить администратора открыть инструмент;
- при `invalid_params` исправить параметры по `details` и `/tools`;
- при `rate_limited` подождать;
- при `quota_exceeded` ждать обнуления лимита или попросить поднять лимит;
- при `not_found` проверить `id` и `tool`;
- при `conflict` прочитать `message`;
- при `server_error` повторить позже, без частого цикла.

## Правила Безопасного Использования

- Не раскрывай API-ключ.
- Не вставляй ключ в код, который попадёт в GitHub.
- Не пиши ключ в README, документацию, логи или issue.
- Не делай бесконечные циклы.
- Не опрашивай задачи чаще одного раза в 10-30 секунд.
- Не создавай большую задачу без явного подтверждения пользователя.
- Не запускай много задач одновременно.
- Не пытайся обойти лимиты.
- Не пытайся получить чужие задачи или результаты.
- Всегда начинай с `GET /tools`.
- Всегда используй параметры из `/tools`, а не из памяти.
- Если результат большой, забирай его страницами через `cursor`.

## Рекомендуемый Алгоритм Для ИИ

Когда пользователь просит что-то сделать через API:

1. Проверь, есть ли API-ключ.
2. Не показывай ключ в ответе.
3. Сделай `GET /tools`.
4. Найди нужный инструмент в списке доступных.
5. Если инструмента нет, объясни пользователю, что ключу не открыт этот
   инструмент.
6. Построй параметры строго по схеме из `/tools`.
7. Если это быстрый поиск, сделай `POST /search`.
8. Если это долгая задача, сделай `POST /jobs`.
9. Сохрани `id` задачи.
10. Проверяй статус раз в 10-30 секунд.
11. Когда статус `done`, забери результаты через `/results`.
12. Если `has_more: true`, продолжай забирать страницы через `cursor`.
13. При ошибке не повторяй запросы в плотном цикле.

## Минимальный Пример Flow

1. Узнать доступные инструменты:

```text
GET /tools
```

2. Создать задачу:

```text
POST /jobs
```

```json
{
  "tool": "yandexmaps",
  "params": {
    "search_urls": ["https://yandex.ru/maps/?text=кофейни"],
    "max_results": 10
  }
}
```

3. Проверять статус:

```text
GET /jobs/<JOB_ID>?tool=yandexmaps
```

4. Забрать результаты:

```text
GET /jobs/<JOB_ID>/results?tool=yandexmaps&limit=200
```

5. Если ответ содержит `has_more: true`, повторить запрос с `cursor`.

## Как Объяснять Пользователю

Пользователь может не быть техническим специалистом. Объясняй простыми словами:

- "ключ не открыл этот инструмент";
- "задача поставлена в очередь";
- "задача ещё выполняется, проверим позже";
- "задача готова, забираю результаты";
- "лимит закончился, нужно подождать или попросить поднять лимит";
- "параметры не подошли, нужно поправить входные данные".

Не перегружай пользователя названиями внутренних таблиц, серверами, RLS,
воркерами и реализацией портала.
