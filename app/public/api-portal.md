# API Портала Polza: Памятка Перед Работой

Этот файл обязательно прочитать перед тем, как пользоваться API портала через
ИИ, разработчика или собственные скрипты.

API даёт программный доступ к инструментам портала: можно запускать парсеры,
проверять готовность задач, забирать результаты и искать по готовым базам.
Это удобно для кастомизаций и автоматизаций, но требует аккуратности: один
небрежно опубликованный ключ может открыть доступ посторонним людям.

## Что Вам Выдали

Обычно вам дают три вещи:

- API-ключ;
- адрес API;
- файл "Контекст для ИИ-чата".

API-ключ выглядит как длинная строка, начинающаяся с `bench_live_`.

Адрес API:

```text
https://polza-portal.ru/api/bench/v1
```

Файл "Контекст для ИИ-чата" можно прикрепить в ChatGPT, Claude, Cursor или
другой ИИ-инструмент. Он объясняет ИИ, как пользоваться API.

## Самое Важное Про Ключ

API-ключ - это как временный пропуск.

По нему портал понимает:

- кто запускает задачу;
- какие инструменты ему разрешены;
- какие лимиты у него есть;
- какие результаты ему можно показать.

Ключ нельзя публиковать. Если ключ увидит посторонний человек, он сможет
запускать разрешённые вам инструменты в рамках ваших лимитов.

## Что Нельзя Делать С Ключом

Нельзя:

- отправлять ключ в публичные чаты;
- вставлять ключ в сообщения на форумах;
- загружать ключ в GitHub;
- сохранять ключ в открытых документах;
- вставлять ключ в README;
- вставлять ключ в примеры кода, которые увидят другие люди;
- отправлять ключ в скриншотах;
- передавать один общий ключ всем подряд;
- просить ИИ "вставь мой ключ прямо в код проекта".

Если нужно показать пример, вместо ключа пишите:

```text
<API_KEY>
```

## Как Правильно Передавать Ключ ИИ

Если вы работаете через ИИ, лучше писать так:

```text
Вот мой API-ключ. Используй его только для запросов к API портала.
Не вставляй ключ в файлы проекта, README, коммиты, логи и публичные сообщения.
Если пишешь пример кода, бери ключ из переменной окружения PORTAL_API_KEY.
```

Не просите ИИ "зашить" ключ в код. Правильный подход - хранить ключ отдельно,
например в переменной окружения или локальном `.env`-файле, который не попадает
в GitHub.

## Что Такое GitHub И Почему Это Важно

GitHub - место, куда часто загружают код проектов. Если случайно загрузить туда
API-ключ, его могут увидеть посторонние люди или автоматические сканеры.

Даже если репозиторий кажется "личным" или "временным", ключ туда класть нельзя.

Перед публикацией кода убедитесь, что в файлах нет строки `bench_live_`.

## Что Можно Делать Через API

Через API можно:

- запускать разрешённые вам инструменты;
- смотреть статус своих задач;
- забирать результаты своих задач;
- искать по разрешённым готовым базам;
- передавать ИИ файл с контекстом, чтобы он помогал писать запросы.

Доступ зависит от ключа. Если вам не открыли какой-то инструмент, API не даст
им пользоваться.

Возможные инструменты:

| Инструмент | Что делает | Можно остановить |
|---|---|---|
| Конструктор баз | помогает обработать и обогатить базу (`base-constructor`) | да |
| Яндекс.Карты | собирает организации из Яндекс.Карт (`yandexmaps`) | нет |
| Google Maps | собирает организации из Google Maps (`googlemaps`) | да |
| Google News | собирает новости (`googlenews`) | да |
| HH | собирает вакансии и работодателей (`hh`) | нет |
| ATS | ищет компании по системам найма (`ats`) | нет |
| ENG hiring | ищет найм на западных площадках (`eng-hiring`) | нет |
| HH архив | собирает данные из архива HH (`hh-archive`) | да |
| Поисковый парсер | собирает данные из поисковой выдачи (`search`) | нет |
| Яндекс.Директ | ищет рекламодателей (`yandex-direct`) | да |
| Обогащение по ИНН | дополняет компании по реквизитам (`inn-enrich`) | нет |

Возможные быстрые поиски: наша база компаний (`company-base`), 2GIS (`2gis`),
наша база баз (`our-bases`).

Это не значит, что вашему ключу открыто всё из списка. Точный доступ всегда
определяется выданным ключом.

## Что Нельзя Делать Через API

Через API нельзя:

- удалять данные;
- смотреть чужие задачи;
- смотреть чужие результаты;
- получать доступ во внутренние разделы портала;
- трогать финансы, клиентов и задачи команды;
- обходить лимиты;
- запускать инструменты, которые вам не открыли.

Если API говорит, что задача не найдена, это может значить одно из двух:
задачи действительно нет или она не принадлежит вашему ключу.

## Почему Есть Лимиты

Лимиты нужны не для неудобства, а для защиты портала.

Парсеры используют общие ресурсы: прокси, очереди, серверы и платные внешние
сервисы. Если случайный скрипт начнёт запускать слишком много задач, он может
помешать работе всей команды.

Обычно у ключа есть лимиты:

- сколько запросов можно делать в минуту;
- сколько новых задач можно создать за сутки;
- сколько строк результата можно забрать за сутки;
- сколько задач можно держать одновременно.

Если API ответил, что лимит закончился, не надо повторять запросы в цикле.
Нужно подождать или попросить администратора поднять лимит.

## Как Работают Задачи

Некоторые инструменты работают не сразу. Например, парсеру нужно время, чтобы
собрать данные.

Обычный порядок:

1. Создать задачу.
2. Подождать.
3. Проверить статус.
4. Когда задача готова, забрать результат.

Не проверяйте статус каждую секунду. Нормально проверять раз в 10-30 секунд.
Частые проверки не ускоряют задачу, а только расходуют лимит.

## Как Работают Результаты

Если результата много, API отдаёт его частями.

Не нужно пытаться забрать всё одним огромным запросом. Правильный сценарий:
забрать первую часть, посмотреть, есть ли ещё страницы, затем забрать следующую.

ИИ в файле "Контекст для ИИ-чата" знает этот сценарий и должен использовать
его автоматически.

## Какие Файлы Давать ИИ

ИИ стоит дать:

- этот файл с правилами;
- файл "Контекст для ИИ-чата";
- сам API-ключ отдельным сообщением.

Ключ не нужно вставлять внутрь файлов. Так проще потом заменить или отозвать
ключ, не меняя документы.

## Что Делать При Ошибках

Если API пишет, что ключ неверный или отозван, проверьте ключ или попросите
новый.

Если API пишет, что инструмент недоступен, попросите администратора открыть
этот инструмент для вашего ключа.

Если API пишет, что параметры неверные, попросите ИИ сначала посмотреть список
доступных инструментов и их параметров.

Если API пишет, что лимит закончился, подождите или попросите поднять лимит.

Если API пишет, что произошла ошибка на стороне портала, повторите позже. Не
запускайте частый цикл повторов.

## Когда Нужно Писать Команде Портала

Пишите команде портала, если:

- ключ потерялся;
- ключ мог утечь;
- нужен новый инструмент;
- нужен больший лимит;
- задача долго висит без движения;
- API возвращает ошибку, которую ИИ не смог объяснить;
- вы не уверены, можно ли запускать большой объём.

## Перед Первым Запуском

Проверьте:

- вы не вставили ключ в файл, который попадёт в GitHub;
- ИИ получил файл "Контекст для ИИ-чата";
- задача небольшая и безопасная для первого теста;
- вы понимаете, какой инструмент запускаете;
- вы не запускаете много задач одновременно.

Если сомневаетесь, начните с маленького теста.
