# Health-check сервис

Отдельный контейнер для мониторинга портала polza-portal.ru.

## Что делает

- **Health check каждые 5 минут** — проверяет доступность БД и сайта
- **При сбое** — сразу шлёт красный флаг в Telegram
- **Монитор парсеров каждые 5 минут** — алертит, если активная задача не
  обновлялась 15 минут, или если новый запуск завершился реальной ошибкой.
  Ручные остановки не считаются ошибкой; повторные алерты по одному запуску
  подавляются даже после перезапуска health-check.
- **Монитор суточных пайплайнов каждые 5 минут**:
  - *OutreachOS* (`outreachos_pipeline_runs`): 🔴 прогон завис (`running`
    дольше порога) или упал (`failed` + текст ошибки), 🟠 прогон не стартовал
    к дедлайну, 🟢 дневной OK-стат (parsed/new/valid/залито A+B) — чтобы
    «тихий» день отличался от тихой поломки. В алертах — хвосты логов:
    `tail /var/log/portal/outreachos-cron.log`, `docker logs portal-worker-hh`.
  - *Mailganer auto-pipeline* (`client_auto_pipeline_runs`): 🔴 прогон упал
    (с текстом ошибки), 🟠 завис (heartbeat старше порога). Исторические
    failed-прогоны при первом запуске помечаются baseline'ом — старый хвост
    не заспамит чат. Логи: `docker logs portal-worker-autopipeline`.
- **Статистика каждый час** — отчёт по БД (проекты, пользователи, парсеры, задачи и т.д.)

## Конфигурация (.env)

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `DATABASE_URL` | да | Строка подключения к PostgreSQL |
| `TELEGRAM_HEALTH_CHAT_ID` | да | ID чата для алертов и статистики |
| `TELEGRAM_BOT_TOKEN` | да | Токен бота (или `TELEGRAM_HEALTH_BOT_TOKEN` для отдельного) |
| `HEALTH_PORTAL_URL` | нет | URL портала (по умолчанию `https://polza-portal.ru`). В prod-compose для контейнера задаётся `extra_hosts: polza-portal.ru → host-gateway`, чтобы с того же сервера проверялся именно публичный сайт. |
| `HEALTH_INTERVAL_SEC` | нет | Интервал проверки в секундах (по умолчанию 300) |
| `HEALTH_JOB_MONITOR_INTERVAL_SEC` | нет | Интервал проверки задач парсеров (по умолчанию 300 секунд) |
| `HEALTH_JOB_STUCK_MIN` | нет | Через сколько минут без обновлений считать задачу зависшей (по умолчанию 15) |
| `HEALTH_OUTREACHOS_STUCK_MIN` | нет | Через сколько минут `running` считать прогон OutreachOS зависшим (по умолчанию 180) |
| `HEALTH_OUTREACHOS_MISSING_AFTER_UTC_HOUR` | нет | С какого часа UTC алертить «прогон не стартовал» (по умолчанию 4, крон в 02:00 UTC) |
| `HEALTH_AUTOPIPELINE_STUCK_MIN` | нет | Через сколько минут без heartbeat считать прогон Mailganer auto-pipeline зависшим (по умолчанию 30) |
| `STATS_INTERVAL_SEC` | нет | Интервал статистики в секундах (по умолчанию 3600) |

## Команды в чате (чтобы не спамить)

В группе, куда приходят алерты, можно писать боту:

| Команда | Действие |
|---------|----------|
| `/mute`, `/тихо`, `/alerts_off`, `/выкл` | Отключить отправку в чат — проверки продолжают работать, сообщения не приходят |
| `/вкл`, `/unmute`, `/alerts_on`, `/on` | Снова включить уведомления |
| `/alerts`, `/статус`, `/status` | Показать, включены ли уведомления |

Состояние хранится в БД (таблица `health_check_settings`), переживает перезапуск контейнера.

## Как получить TELEGRAM_HEALTH_CHAT_ID

1. Напишите боту любое сообщение
2. Откройте в браузере: `https://api.telegram.org/bot<TOKEN>/getUpdates`
3. Найдите `"chat":{"id":123456789}` — это ваш chat_id

## Запуск

```bash
docker compose up -d health-check
```

Или с остальными сервисами:

```bash
docker compose up -d
```
