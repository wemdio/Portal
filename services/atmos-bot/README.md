# Atmos-bot — анализатор атмосферы в чатах

Отдельный контейнер для мониторинга тональности сообщений в Telegram-чатах с клиентами.

## Что делает

- **Webhook** — принимает все сообщения из чатов, куда добавлен бот, сохраняет в БД
- **Анализ каждые N минут** — берёт новые (необработанные) сообщения, отправляет батч в LLM для тонального анализа
- **При негативе >= порога** — сразу шлёт алерт в командный чат с названием чата и ссылкой
- **Периодическая сводка** — агрегированная статистика по всем отслеживаемым чатам
- **Управление через Telegram** — все настройки можно менять прямо в личке бота

## Команды бота (в личном чате)

| Команда | Что делает |
|---------|-----------|
| `/start` | Приветствие и список команд |
| `/settings` | Показать текущие настройки |
| `/model` | Выбрать модель ИИ (inline-кнопки) |
| `/threshold` | Изменить порог негатива для алертов (10%-50%) |
| `/interval` | Настроить интервалы анализа и сводки |
| `/prompt` | Просмотр и редактирование системного промпта для ИИ |
| `/chats` | Список всех отслеживаемых чатов со статистикой |
| `/status` | Статус бота: счётчики, последняя проверка, конфиг |

Все настройки сохраняются в БД и применяются мгновенно без перезапуска.

### Редактирование промпта

Команда `/prompt` позволяет:
- Посмотреть текущий системный промпт (дефолтный или кастомный)
- Нажать «Редактировать» и отправить новый текст промпта следующим сообщением
- Сбросить к дефолтному промпту кнопкой «Сбросить к дефолту»
- Посмотреть полный текст промпта кнопкой «Показать полный промпт»

Промпт должен требовать JSON-ответ с полями: `total_analyzed`, `negative_count`, `sentiment_score`, `risk_level`, `negative_reasons`, `recommended_action`, `summary`.

## Конфигурация (.env)

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `DATABASE_URL` | да | Строка подключения к PostgreSQL |
| `TELEGRAM_ATMOS_BOT_TOKEN` | да | Токен бота-анализатора |
| `TELEGRAM_ATMOS_TEAM_CHAT_ID` | да | ID командного чата, куда бот шлёт алерты и сводки; этот чат не участвует в анализе на негатив |
| `OPENROUTER_ATMOS_API_KEY` | да | Ключ OpenRouter для LLM-анализа |
| `ATMOS_WEBHOOK_PORT` | нет | Порт для webhook-сервера (по умолчанию 8090) |
| `ATMOS_WEBHOOK_URL` | нет | Публичный URL для авторегистрации webhook |

Настройки модели, интервалов и порога теперь управляются через команды бота и хранятся в таблице `tg_atmos_settings`. Env-переменные `OPENROUTER_ATMOS_MODEL`, `ATMOS_CHECK_INTERVAL_SEC`, `ATMOS_STATS_INTERVAL_SEC`, `ATMOS_NEGATIVE_THRESHOLD` используются только как начальные значения при первом запуске.

## Доступные модели

| Модель | Описание |
|--------|----------|
| `google/gemini-2.0-flash-001` | Дёшево и быстро (по умолчанию) |
| `google/gemini-2.5-flash-preview` | Новее, чуть умнее |
| `meta-llama/llama-3.3-70b-instruct` | Мощнее, дороже |
| `qwen/qwen-2.5-72b-instruct` | Альтернатива |
| `deepseek/deepseek-chat-v3-0324` | Дёшево |

## Как настроить

1. Создайте бота через @BotFather в Telegram
2. Добавьте бота в клиентские чаты и в ваш командный чат
3. Напишите боту в личку `/start` для проверки
4. Укажите переменные в `.env`
5. Бот автоматически регистрирует webhook при старте (если задан `ATMOS_WEBHOOK_URL`)

## Запуск

```bash
docker compose up -d atmos-bot
```

## Таблицы БД

| Таблица | Назначение |
|---------|-----------|
| `tg_atmos_messages` | Входящие сообщения из чатов |
| `tg_atmos_checks` | Результаты анализа (sentiment, risk, reasons) |
| `tg_atmos_chat_state` | Состояние обработки по чатам |
| `tg_atmos_settings` | Настройки бота (модель, интервалы, порог, промпт) |
