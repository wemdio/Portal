# Доверенные корневые сертификаты для отдельных источников

Здесь лежат корневые сертификаты, которых нет в стандартном наборе Python
(`certifi`), но без которых не открыть соединение с конкретным источником.

Набор используется **точечно**, одним источником, а не всем контейнером. Это
принципиально: доверенный корень — это разрешение принимать любой сертификат,
им подписанный, для любого адреса. Разрешать это всему синку ради одного банка
значит расширять доверие туда, где оно не нужно.

## russian_trusted_root_ca.pem

**Кому нужен:** `sources/bank_tochka.py` — Точка Банк, `enter.tochka.com`.

**Зачем:** 24.08.2026 банк переехал на национальный УЦ Минцифры. С 25.08 синк
падал с `[SSL: CERTIFICATE_VERIFY_FAILED] self-signed certificate in
certificate chain` — Python видел корень, которому не выдано доверия. Цепочка,
которую отдаёт сервер:

```
*.tochka.com
  └─ Russian Trusted Sub CA        (Минцифры)
      └─ Russian Trusted Root CA   (Минцифры)   ← этот файл
```

**Откуда взят:** официальная раздача Госуслуг,
`https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer`.

**Отпечаток (SHA-256):**

```
D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31
```

Он совпал с сертификатом, который сервер Точки реально предъявляет в
рукопожатии, — два независимых источника сошлись. Отпечаток продублирован в
коде и проверяется тестом: подменённый файл уронит тесты, а не тихо доедет до
прода.

**Действует до:** 27.02.2032. За несколько месяцев до этой даты сертификат
придётся обновить — иначе синк встанет тем же способом, что и 25.08.2026.
