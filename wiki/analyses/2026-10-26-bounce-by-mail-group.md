# 2026-10-26 — Bounce rate by mail group

> Историческое исследование; данные и выводы актуальны только для описанного среза. Результаты не были повторно проверены при переносе. Полные запросы автора доступны только в указанном scratchpad, поэтому здесь не воспроизводятся.

**Вопрос.** SMTP-проверка не отличает живой ящик от несуществующего на почте группы Mail.ru: все адреса получают `catch_all`. Во что это обходится на настоящих отправках?

**Источник.** `raw_leads` (`status = -1` — отказ; лид считается отправленным, если `timestamp_last_contact` не пуст). Захват лидов идёт с 17.08, поэтому кампании, вычищенные раньше, сюда не попали. Instantly не различает причины отказа: «ящика нет» и отказ по политике получателя считаются одинаково. Вебхук `email_bounced` (`instantly_activity_events`, с 12.10) причину тоже не передаёт. Письма об отказе (from `mailer-daemon`, 1 725 шт.) есть только для доменов компаний.

Столбец «Лидов с контактом» считает лидов по наличию `timestamp_last_contact`, а не отдельные отправленные письма.

## Выводы

- В исследованном наборе 21,9% наблюдённых отказов пришлись на адреса с более ранним контактом со статусом отказа. Потенциальное снижение отказов не измерено: это требует проверки правила и его ошибок на новых данных. На адресах Mail.ru с прошлым отказом повторный отказ наблюдался в 69% случаев (5 426 из 7 893), на доменах компаний — в 57%.
- У Яндекса и Gmail повторный отказ наблюдался в 35–40% случаев. Отказы по политике могут объяснять часть различия, но этот источник их не различает. Проверять правила маркировки `invalid` следует отдельно, в том числе по ложноположительным результатам.
- Домены компаний отбиваются чаще Mail.ru (15%), и по объёму это главный источник отказов: 57 тыс. против 15 тыс. Следующий шаг — разрезать их по нашему вердикту (ok / catch_all / unknown).

```sql
-- доля отказов по группе (сокращено)
select grp, count(*) contacted, count(*) filter (where status = -1) bounced
from (select <группа по домену> grp, status from raw_leads
      where timestamp_last_contact >= '2026-08-01' and timestamp_last_contact < '2026-10-10') t group by 1;
-- повторные отказы
select grp, count(*) filter (where status = -1 and tlc > first_bounce + interval '1 hour')
from (select <группа> grp, status, timestamp_last_contact tlc,
             min(timestamp_last_contact) filter (where status = -1) over (partition by lower(email)) first_bounce
      from raw_leads where timestamp_last_contact is not null) t group by 1;
```

Полные запросы автор указал в scratchpad сессии 6ede4ced: `q_groups.sql`, `q_consistency.sql`, `q_repeat.sql`; они не включены в этот отчёт. Приведённые выше фрагменты содержат заполнители и не являются готовыми воспроизводимыми запросами.
