## Решения владельца (16.10.2026, вечер, облачная сессия)

1. **Выкат трёх доработок ENG (страны, «не писать» по домену, все пояса) — всё включить сразу.** Флаги `HE_ENG_COLLECT_COUNTRIES`, `HE_ENG_DNC_DOMAINS`, `HE_ENG_TIMEZONES_ALL` прописать в прод-настройки вместе с деплоем (днём, не во время ночного добора). Сразу после деплоя: проверить, что все контейнеры на новой версии; быстрая живая проверка поясов в Instantly на одной тестовой кампании на паузе; тест на HST. Причина: система ещё не для настоящих клиентов, HST — тестовый клиент, его всё равно прогоняют заново.
2. **ОТЛОЖЕНО, не забыть: окна отправки по регионам.** Сейчас у кампании одно окно отправки; если в рынке страны в разных поясах (HST: Европа + США), часть писем уходит в неудобные часы. Нужна доработка: (а) знать страну каждой подготовленной компании и при отправке снимать компании вне текущего списка стран проекта; (б) при запуске делить рынок на кампании по регионам, у каждой своё окно. (а) — основа для (б). Пока без кода для смешанных списков — общее окно 13:00–17:00 по Лондону (14–18 Берлин, 8–12 Нью-Йорк).
3. **Правило писем: созвон.** Просить созвон можно, только если клиент этого хочет (созвон есть в его оффере), и только во втором и последующих письмах цепочки, никогда в первом. Сейчас ENG-промпт цепочки запрещает просьбу о созвоне во всех письмах (prompts/chain.ts).
4. **Строку отписки не делаем** — решено ранее (см. no-optout-phrases-rule); вопрос закрыт.
5. **Систему делаем для всех клиентов, не под одного.** Вопросы о содержимом конкретного клиента (цена прототипа HST, Норвегия) — данные клиента, их вводит клиент в кабинете; владельцу их не задавать. HST прогоняется заново как обычный клиент через кабинет; систему чиним там, где она ошибается. Для HST: Норвегию включить в список стран.
