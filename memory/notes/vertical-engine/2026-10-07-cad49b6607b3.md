Повторная проверка изменения общей цели (a2fe8166c) нашла ошибку нового предпросмотра: без outstandingContacts планировщик показывал ненулевую новую загрузку при цели, уже полностью покрытой accepted/attempting/uncertain/reserved. Исправлен contactTargetDailyPlan: покрытие выводится из подтверждённой SQL нижней границы минус факт; искусственный минимум 1 пустого проекта не является обязательством. Период может включать другие кампании, поэтому нельзя просто вычитать committed из actual без сверенного серверного значения.

Проверены ровно минимум, минимум+1, резервы, период и пустой проект в существующем тесте; 298 проверок ветки, strict typecheck, lint, локальная миграция PGlite, браузер с реальным компонентом и фикстурами прошли. SQL записи в production не выполнялись. На read-only проверке Neiraxell 2026-10-07 15:25 UTC активен, цель 2000, accepted38/ready462, автодобор active без ошибки; RPC новой миграции ещё отсутствовал. После обычного деплоя редактирование доступно без пересоздания кампании. Источник: docs/handoff/2026-10-07-ve2-edit-contact-target.md; contactDeliveryTarget.ts и contactDeliveryPlanner.test.ts.
