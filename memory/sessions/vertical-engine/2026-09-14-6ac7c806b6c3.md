## Запрос и подтверждённая причина

Пользователь сообщил, что 144.31.54.166 не оплачен, предоставил открытую панель
Timeweb и затем отдельно разрешил исправить доступ текущего Portal к TCP/3100.
Консоль сервера 6646351 (89.19.209.252) показала работающий smtp-proxy и локальный
HTTP 200, но INPUT разрешал только старый Portal 139.60.162.12. SYN-пакеты
приходили от 139.60.162.24. Источник постоянного правила — ExecStartPre unit,
не /etc/iptables/rules.v4. Баннер аварии ноды Timeweb не заменяет эту диагностику.

## Исправление и проверка

Добавлено разрешение 139.60.162.24/32 -> TCP/3100 в INPUT и одна соответствующая
ExecStartPre в /etc/systemd/system/smtp-proxy.service. Сделана локальная резервная
копия unit с суффиксом .bak-20260914-portal-ip; прежние правила сохранены.
Проверка unit прошла, daemon-reload выполнен, unit enabled/active, сервис не
перезапускался. В 01:59 UTC worker получил health HTTP 200; в 02:01 UTC реальная
SMTP-проба получила code=250, exists=true за 511 мс. В текущем конструкторе
6340785f-1fc1-45d9-b7ac-36c157e96aa7 — 37 OK и 43 Catch-All; пакет VBI
96b59207-defa-4e15-80c1-7fcfc54675a4 завершился с 27 Catch-All и 973 unknown.
Эти числа не равны прошедшим весь отбор контактам. Сохранённые unknown не стали
валидными автоматически. Данные очередей не менялись, новых сборов не запускали.

## Ошибка и открытый вопрос

При предыдущем входе через web-консоль нативная вставка восстановила буфер с
root-паролем, и он попал в командную строку. Пользователь сразу уведомлён,
ему передана самостоятельная ротация через Timeweb. Ротация пока не подтверждена;
секреты/снимок с паролем в Git не сохраняются, история команд не очищалась.
Использовать браузерную Tab.paste для этой консоли; не нативную вставку с
восстановлением системного буфера. Перезагрузка в рамках проверки не выполнялась.
