Пользователь явно уточнил: ежедневные посты VE2 должны идти с production, независимо от включённого ПК, в 11:00 МСК (08:00 UTC, 12:00 Europe/Samara). Публичный формат сохраняет завершения с последнего отправленного поста, текущий сбор/подготовку и очередь; проблемы только владельцу в текущей задаче. Не активировать локальный Codex heartbeat вместо серверного расписания.

В рабочей ветке codex/ve2-preview-recovery-scale (база 59ba709bf, push в ранее явно разрешённую Sergey) подготовлен отдельный deterministic digest в services/changelog-bot, migration 20260928_0002_ve_daily_digests.sql, bootstrap по реально опубликованному посту25.09/message33349. Bootstrap102 выбранных базы/90ready. Read-only prod snapshot28.09 подтвердил102/92ready/10issues; новые готовые стоматологии3+501 и ресторанные холдинги502, active/queue0. Это диагностический снимок, не отправленный пост.

Durable outbox с per-part Telegram receipts, session advisory lock на прямом Postgres, daily uniqueness, catchup после11 и retry известных отказов. Неизвестная отправка/потеря записи receipt блокирует автоматические повторы до отдельной сверки, чтобы не дублировать пост. История/проблемы закрыты RLS; в публичном тексте ошибок нет. Нет LLM, запуска сборов или платных проверок. Существующий09МСК changelog и startup catchup сохранены.

Проверено локально:25 PGlite/pipeline сценариев,11 HTTP transport/timezone проверок,2 startup режима,2 migration suites/5tests, Python compile/help. Telegram замокан; SQLproduction только readonly.
