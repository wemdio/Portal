## Request and result

Added exact email exclusions to the existing per-project INN and domain/site policy. The UI exposes three pasteable lists: INN, domains/sites, exact email. Full website URLs normalize to company domains. An email rule matches only the current canonical recipient, with trim/case normalization; dots and +tags are not folded and public mailbox providers are not blocked wholesale.

## Boundaries and compatibility

- Applied in collection, prepared previews/full verified CSV, initial launch, saved stock/daily supply, refill, and the final provider chunk guard. Already uploaded contacts are not removed from Instantly and historical uploaded counters remain unchanged.
- Company identity metadata still contains only INN/domains. Canonical lead email overrides source aliases. Email-only stock rules avoid heavy source/base identity reads; no enrichment, scraping or paid API calls were added.
- Migration `20261012_0003_ve_project_email_exclusions.sql` adds emails/email_count and `ve_save_project_exclusions_v2`. Old five-argument RPC forwards with NULL to preserve stored emails. Omitted emails preserve, explicit [] clears. Existing revision/project locks, combined 10,000-entry cap and service-role-only RPC ACL remain.
- A UI reading an old GET response must not turn missing emails into a destructive empty PUT list: it disables that field, omits it from writes, and asks to reload. Old writer responses cannot falsely confirm email saves.
- Read failures or corrupt saved policy fail closed. An INN-only rule still cannot identify a company whose INN is unknown and has no other known match; no automatic INN enrichment was introduced.

## Verified regression found during implementation

Filtering every source row could previously finish the round before polling/importing an already dispatched constructor. Existing child ownership now bypasses empty-source termination, imports already found addresses, and applies per-recipient exclusions. Existing running children are awaited without creating new jobs. Unsafe legacy children without split_emails and with no allowed source input are not imported or replaced by paid work.
