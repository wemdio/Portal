Уточнение пользователя после правки 7a6e7be3c: одновременные числа 150 проверенных адресов и 125 засчитанных в цель всё равно путают, даже с разными подписями. Уточняет результат sessions/vertical-engine/2026-09-25-fe10c147aa15.md.

Решение для основного экрана: размер базы всегда checked_ready (в примере 150), отдельно компании (78) и обработанные кандидаты. В заголовке остановки нет дроби 125/500. Правило зачёта не больше 3 адресов компании и счётчик 125 оставлены только в закрытых подробностях расчёта. В PreparationProgress для активных и прерванных сборов число проверенных адресов берётся из ready_contacts с fallback на старые ready_rows при отсутствии поля. CollectionFunnel использует тот же смысл и скрывает зачёт в цель в details. Счётчики для решения о доборе, ограничения, фильтры скачивания и запуска не менялись; готовый резерв запуска после исключений по-прежнему отдельно объясняется текстом.

Проверки поверх 7a6e7be3c: 3 existing Jest suites / 14 tests passed, tsc --noEmit, git diff --check. Локальный Playwright на реальных компонентах без сетевого доступа подтвердил отсутствие видимого 125 в остановленном, активном и ошибочном состояниях; после раскрытия расчёта 125 доступно. Основной показатель 150, компании 78. Также проверены светлая/тёмная тема, узкий экран, ввод цели проекта и закреплённый план. Постоянных тестов не добавлено, обновлено существующее ожидание заголовка. UI-правка направляется в Sergey по поручению пользователя, деплой не выполнялся.
