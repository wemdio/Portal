Продолжение механизма паузы/дозаливки Instantly (5afe7bfe8, bd3e65797). Пользователь разрешил автоматическую сверку после обсуждения сбоя API; целевая ветка по ранее явному указанию — Sergey. Изменение подготовлено поверх 19eae4f3f, production не менялся.

Реализация: новый contactDeliveryReconciliation запускается до supply/delivery в регулярном VE2 sweep. SQL 20260924_0014 сохраняет отдельный журнал наблюдений, не изменяя исходные массивы delivery attempt. Финализированный uncertain выдерживается 10 минут; live getCampaign проверяет campaign/mailboxes/workspace, listLeads использует официальный contacts + campaign (wire) фильтр и валидирует идентичность/пагинацию. Найденные адреса переходят в accepted, два полных отсутствия с интервалом ≥5 минут разрешают retry. API/DB ошибки, неполные/чужие ответы и устаревший claim ничего не освобождают. Внутри дня используется исходный frozen reservation; позже — обычный ready/planner. Capacity pause не сбрасывается. Нетронутый хвост исходной частичной попытки также возобновляется без расширения квоты.

Новый runner использует begin_recoverable_contact_delivery и перед каждым POST продлевает 5-минутное владение через awaitable transport hook. HTTP ограничен 90 секундами вместе с телом, автоповтор 429 в этом режиме выключен. Просроченную lease нельзя продлить. Expired+5m попытка после crash финализируется uncertain, далее выдержка/сверка. До fetch проверяется также фактически истёкшее время: при возобновлении замороженного процесса таймер мог ещё не сработать. Отказ hook до fetch не учитывается как вызов API.

Границы: старые attempting без lease автоматически не снимаются; старые finalized uncertain поддерживаются. Сверка идёт для проектов с активной очередью; не более50 строк/проект/проход и новые проверки не начинаются после60с. Не переписывает общий client_campaign_append_batches; актуальное восстановленное состояние — delivery rows/counters + reconciliation audit. Нужны новая миграция, app и VE2 worker при отдельном согласованном деплое.

Проверено локально: 3177 тестов/289 suites, 21.39с; TypeScript, ESLint, worker esbuild, git diff --check. Существующий PGlite smoke выполняет реальные SQL-функции: живое/истёкшее владение, crash, неизменный replay original attempt, lost-save replay, два отсутствия, stale token, outage, same/next-day quota и сохранение capacity pause. Существующие unit tests дополнены точной кампанией, mailbox mismatch, чужими/неполными страницами, пагинацией, отказом lease перед HTTP, просроченным timer и изоляцией ошибок sweep. Новых test-файлов нет. При добавлении вложенного SQL scenario обнаружена коллизия имени savepoint в smoke-helper; исправлена уникальными именами, production логика не затронута.
