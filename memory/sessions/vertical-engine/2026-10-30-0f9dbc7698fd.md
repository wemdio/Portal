Запрос 31.10.2026 по Тбилиси: добавить собственный браузер русским вертикалям, TinyFish Fetch и затем дополнительно Search — только для сложных гипотез с недобором готовых контактов и только бесплатно. Пользователь предоставил отдельный RU-аккаунт. Ключи не сохраняются в памяти/Git.

Область: внутренний Vertical Engine v2, локальные изменения `Sergey` поверх `1cd4b6697`. Это не выпуск на production. Прежнее отсутствие RU-интеграции описывает состояние до этой задачи. ENG orchestration/выбор ключей сохраняются; новый внутренний сценарий не пишет в `he_*`.

Реализация:
- VE2 передаёт отдельный `ru_page_fallback` в обычный RU-конструктор без подмены locale на en и без ENG contact-first. При `RU_BROWSER_ENABLED=1` успешные пустые/JS страницы дочитываются общим изолированным Chromium с закреплённой русской локалью. Старый broker без locale echo для RU отклоняется. Блокировки/челленджи, неизвестный исход, частные адреса и чужие redirect-boundaries не включают резерв. У полезной исходной почты renderer не вызывается. Rendered HTML не маскируется строковым HTTP-кэшем.
- TinyFish требует законченного обычного раунда, недобора по готовым контактам после email/relevance/name/cap gates, отсутствия pending/error и подтверждённого исчерпания источников или двух окон низкого выхода минимум по 50 компаний. Один атомарный claim `(project, hypothesis)` защищает параллельные preview/supply базы; прежний ID восстанавливается после сбоя до parent receipt. Удаление базы claim не снимает.
- Резерв: до 5 Search-запросов, до 100 компаний суммарно. Курсоры запросов и сайтов сохраняются до IO; неизвестные исходы не повторяются. По три проверяемых сайта на wake, каждый ограничен жёстким 30-секундным deadline. Constructor child ID/отдельный dispatch timestamp устойчивы к повторам и паузе более 6 часов. Истощённая гипотеза с нулём сохранённых сайтов тоже может открыть Search.
- Search возвращает кандидаты-сайты. Организация подтверждается на собственном сайте через Organization/LocalBusiness JSON-LD или OG + видимый бренд; SERP-title и generic labels не становятся компанией. Body-only Fetch использует прежние same-site head metadata лишь при совпадении видимого имени. Неоднозначный ИНН остаётся пустым; подтверждённый taxID и адрес не теряют строковое представление. Затем прежние canonical grid/import, валидация почты, релевантность и name cleanup. Новые непроверенные имена после окончательного сбоя остаются в резерве, прежняя готовая база сохраняется. Дополнительные source rounds/candidate budgets не выдаются.
- Ручной API удаляет внутренние флаги. Worker проверяет родительский receipt/ID, проект RU, владельца и исходные company/site/ИНН; недоступное доказательство отключает только TinyFish.

Настройки: `RU_BROWSER_ENABLED`, `RU_TINYFISH_ENABLED`, отдельные `RU_TINYFISH_API_KEY`/`RU_TINYFISH_ACCOUNT_ID`, дополнительно `RU_TINYFISH_SEARCH_ENABLED`. У RU один отдельный аккаунт; ENG-pool не используется. Секрет локально вне Git в защищённом JSON 0600. Fetch — до 1000/rolling24h на аккаунт и общий RU+ENG 120/min через ранее добавленный RPC v2. Search — отдельный атомарный бюджет 30/min,500/hour,12000/rolling24h; плюс provider usage текущего UTC-дня<12000. Перед каждым запросом свежий нулевой wallet-meter USD/url или USD/query. Missing/unknown/nonzero/over-quota — пропуск, без paid fallback, Agent, TinyFish Browser API или комбинированного Search+Fetch.

Новые миграции: `20261031_0001_ru_tinyfish_search_budget.sql`, `20261031_0002_ve_ru_website_rescue_claim.sql`. Search требует таблицу/RPC, per-hypothesis резерв требует claim-table; старые применённые миграции не редактировались. Документация: `docs/ru-site-fallback.md`, `docs/eng-site-fallback.md`, `deploy/eng-browser/README.md`.

Проверка: 107 existing Jest assertions в 11 suites; затем 17 grant/isolation assertions после claim migration. Все 5 TypeScript 7 конфигураций, ESLint, сборка 4 затронутых worker entries и diff-check прошли. Временные проверки реальных функций вне репозитория: browser transport16, RU core21, Search adapter17 групп, SQL-budget14+wrapper18, lifecycle15; независимый mapping18+reader8+discovery16+claim14. Итоговые SHA сверены. Постоянных тестов/зависимостей не добавляли.

Реальные бесплатные запросы нового RU-ключа: 1 Fetch (HTTP200/completed, usage0→1), 1 Search на русском (HTTP200,3candidateURLs, usage1). Search проверял реальный adapter с локальным тестовым резервом, production RPC не вызывали. Обычный guarded HTTP трёх найденных сайтов подтвердил literal site identities «ООО Ридан», «GRINIK ROBOTICS» и информационный портал: это кандидаты, не готовые контакты; релевантность определяется последующими gates. Кириллица без replacement characters. Источники условий: https://www.tinyfish.ai/pricing и https://docs.tinyfish.ai/search-api/reference.md. В справочнике Search описано платное продолжение сверх дневной квоты, хотя pricing обещает отсутствие списаний; потому live-zero и оба cap обязательны.

Ограничения проверки: transport/DNS/SMTP/LLM в offline harness заменены контролируемыми границами; новую RU Linux sandbox acceptance на этом Mac не переисполняли. PGlite исполняет PostgreSQL WASM и ограничения/права, но не имитирует native multi-session scheduling. Проверка Linux release acceptance остаётся частью будущего выпуска. Production, рассылка, платные запросы, секреты сервера, release Tasks не менялись. Для активации нужен отдельно согласованный обычный выпуск с миграциями и RU-флагами сначала 0, затем защищённая настройка и проверка.
