# Запрос и состояние

Пользователь просит устранить потери контактов, ускорить подготовку и получить готовую базу специалиста к утру. Целевой масштаб очереди: 15 проектов × 25 гипотез. Код готовится в `codex/ve2-preview-recovery-scale` от `origin/Sergey` 7eaa32143; пользователь ранее явно выбрал коммиты и push в Sergey.

# Проверенные результаты

- Read-only production 2026-09-15 22:27 UTC: ProfiAds (M2), гипотеза «Региональные агентские сети», база 77ea93ec-f54d-4f86-a5ad-91e4ff4c8b8b: failed, 44 готовых контакта, ошибка email completeness. Изменений production в этой задаче ещё не выполнялось.
- Причины и диагностика: [предыдущая запись](2026-09-15-86800c6ba0af.md). 1 071 строка без сайта/ИНН повторно выбиралась; завершённый пустой вывод конструктора ошибочно заменялся сырьём. Счётчик 3 056 отражает проходы, не уникальные компании.
- Исправлены same-base receipts с учётом географии/происхождения, пустой валидированный результат, восстановление email из поля сайта, ограниченный поиск официальных сайтов с durable checkpoint, приоритет сохранённых валидных email при продолжении.
- Проверка сайта теперь выбирает ID исходных фрагментов и сохраняет независимую семантическую проверку. Неопределённые старые результаты получают bounded повтор по версии 3; готовые решения массово не инвалидируются.
- VE2 concurrency default 8 / maximum 16, один parent writer на проект. Блокировка всего проекта заменена блокировкой той же гипотезы; дочерние процессы разных гипотез могут идти одновременно. Compose VE2: 8 GB, 4 CPU, heap 6 GB. Общий конструктор не менялся.
- Полный локальный Jest: 213 suites / 2405 tests, ~56 секунд. После завершающих исправлений VE2: 13 suites / 102 tests. Тест очереди завершает 375 задач для 15 проектов при 8 слотах с сохранением project exclusivity. TypeScript и сборка worker проходят. ESLint без ошибок, существующее предупреждение React effect в Step4Base.

# Ограничения и следующий шаг

Миграций, изменений HE/ENG и production-записей нет. Нужен отдельный разрешённый штатный выпуск приложения/VE2/Compose и продолжение существующей подготовки через штатный API/UI. Сохранённый резерв имеет адреса OK/Catch-all, но соответствие гипотезе ещё требуется доказать; 500 контактов не обещаны. Тест очереди не подтверждает получение 187 500 контактов за ночь: нужен production throughput замер.

Архитектура/границы: `docs/design/2026-09-16-ve2-contact-recovery-scale.md`. Старый worker не знает режима >5 раундов после source recovery; не делать слепой откат после его активации. Исходные глобальные таблицы HH/реестра не переписывались.
