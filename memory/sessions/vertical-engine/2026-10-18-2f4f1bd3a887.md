Решение пользователя 2026-10-18: в ENG не показывать клиенту статус каждого email; принимать в готовую базу OK и catch_all, отдавая OK приоритет. Это заменяет прежнее правило ENG «только OK»; русский движок, legacy staff и VE2 сохраняют прежнее поведение. Разрешения на production-записи/отправку/деплой этой просьбой не дано.

Реализация в Sergey после 757ae1cc3: новая engEmailPolicy подтверждает project.market=us и владельца profiles.role=client, market=eng; неизвестный владелец останавливает операцию. Общий heLaunchEmailVerdict сохраняет default OK-only, catch_all допускается только с явным allowCatchAll. Ранг OK > catch_all учитывается до дедупликации и ограничений количества адресов/компаний, при ручном запуске и ночном доливе, включая дубли own/carry и carry/carry. Сохраняются исходные индексы и привязки лидов.

Обычный и поздний импорт ENG сохраняют только допущенные строки; нулевой результат не ставит платный анализ. Исходники конструктора остаются для диагностики. Для уже существующих смешанных баз ENG rows endpoint фильтрует и упорядочивает строки перед pagination; исходные данные production не переписывались. API не отдаёт per-address _email_status и другие служебные поля; таблица и hover-подсказки содержат только видимые данные контакта. ready-счёт принимает OK и catch_all. Устаревший valid_count=0 больше не блокирует запрос ready у исторической catch_all-only базы; UI не угадывает готовность по этому счётчику.

Граница повторной проверки: старые analyzing/analyzed базы сохраняют прежний механизм validationRetry по he_bases.data, счётчики ENG теперь учитывают catch_all. Новые очищенные ENG базы не содержат unknown/error, поэтому эти адреса не являются кандидатами существующего retry по готовой базе. Отдельное восстановление кандидатов из конструктора здесь не добавлялось (нельзя слепо возвращать DNC/межбазовые дубли); это отдельный объём, если потребуется.

Проверки: все 5 TS7-конфигураций, сборка hypothesisEngine worker во временный файл, ESLint без ошибок (одно прежнее предупреждение EngDashboard setState-in-effect), независимые офлайн проверки импорта/caps/профиля/launch/refill/UI; 80 legacy cap случаев совпали с HEAD. Ветка: 34 suites/277 assertions прошли, те же 7 ранее зафиксированных ошибок veContactDeliveryWithoutPeriod.test.ts:508; VE2/SQL/тесты не менялись. Реальный BasePreview визуально проверен локально с синтетическими .test контактами: ровно company/website/email, статусы не присутствуют в HTML и подсказках.

Production, RU, VE2 не менялись. Для применения требуется отдельное явное согласование релиза; отправка писем этим изменением не запускалась.
