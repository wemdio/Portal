Повторный аудит индивидуального запуска поверх 516ffaf23 обнаружил два недочёта UI: новая краткая строка брала row_count (это может включать ещё не готовые контакты), а план проекта/цель оставались редактируемыми во время POST start. В offline-браузере воспроизведено: 150 сохранённых строк при 20 checked_ready; оба поля были enabled во время искусственно задержанного ответа.

Исправлено: краткая строка получает checked_ready из уже существующей загрузки AudienceSummary через стабильный callback с base_id; это общий счётчик с подробной карточкой, без дополнительных запросов и без подмены counted target. При ошибке загрузки число убирается. DeliveryPlanBlock получил необязательный disabled; OutreachLaunchPanel передаёт busy, форма создания клиента также заблокирована fieldset. После ошибки поля снова доступны, повторный POST использует прежний idempotency key.

Новая миграция индивидуального запуска дополнительно исполнена в локальном PGlite: 15 групп, включая два из трёх, последовательные индивидуальные запуски без сброса выбора/одобрений и атомарный отказ группы. Runtime 18 групп. Offline UI: оба исправления, потерянный ответ, запрет повтора в процессе сохранения, изменение настроек/отзыв одобрения, сохранность цели при polling, unsaved contact cap; прежний индивидуальный/групповой сценарий, desktop/mobile. Постоянных проверок не добавляли; разрешение на новые it() остаётся без ответа. Все внешние вызовы тестовой фикстуры отключены; production не меняли, платные API не вызывали.
