Запрос: пользователь разрешил защитить сбор от ночного редеплоя и сообщил,
что страница писем VBI показывает ошибку Serper от сбора базы.

Проверено read-only: nightly deploy вызывает drain, затем force removal;
прежний drain не останавливал VE2, поэтому Compose stop_grace_period не помогал.
Scheduled deploy пропускает выпуск при совпадении main и last_deploy_sha.

Исправление: выбранный VE2 останавливается до дочерних обработчиков, ошибка stop
обрывает скрипт; текущий сбор сохраняет durable checkpoint и оставляет running
job для startup recovery без расхода attempts. Новые jobs/подготовки и следующие
проекты дозагрузки после SIGTERM не начинаются. Нересёрчевая стадия получает
четыре минуты до abort, Compose остаётся внешним пределом пять минут. Research
сохраняет прежнюю немедленную отмену и watchdog. Аварийный kill/потеря ответа
провайдера всё ещё могут оставить неоднозначную операцию.

Важная коррекция: semantic review и citation repair сначала резервируют started,
потом делают платный HTTP. На сохранении такой резервации нельзя штатно yield:
callback помечает canYield=false. После сохранения результата yield разрешён.
Проверка реальной relevance-функции на mock HTTP подтверждает: запрос завершается,
checkpoint хранит finished, возобновление не делает повторный запрос.

VBI: project 5520bec1-4f58-48e6-8094-c8340dfd5348. Четыре письма сохранены в ready
template ed67545c-b40f-4e64-9242-dc8d0f55ce4d для «Сетей частных клиник»
(hypothesis 650dd54a-36c8-4225-8108-e9e09d789f66; base 849d159a-28af-4427-a461-00f18093c29e).
Сохранённая Serper billing ошибка относится к «Эстетической медицине»
(hypothesis c5c81be3-ddef-470b-afed-63f9a6ae9bd9; base 2ae93e75-2241-4d22-aea4-43f6418dda28).
Письма ищутся строго по гипотезе, без supply-баз: текущие редактируются,
последняя ранее созданная готовая версия доступна для просмотра без перепривязки
подготовки/одобрения/запуска. Ошибка failed-базы и продолжение перенесены на шаг
«Базы и объём»; настоящие ошибки генерации остаются ошибками писем.

Node 24.19.0 встретил SIGSEGV в V8 GC на неизменённом leadQualifierPolicy;
