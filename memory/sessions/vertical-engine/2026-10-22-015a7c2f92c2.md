Повторная независимая проверка `84eb6d95c` обнаружила четыре дополнительных случая. Все исправлены локально; production и платные API не затрагивались.

1. Нишевая нормализация вызывается до и после планирования. Защита только в первом call site была недостаточна: после operator geography repair `nameTerms`/`identityCatalog` могли изменить ключ источника, он пропускался в текущем проходе, а следующий wake получал `Invalid bounded geography repair checkpoint`. Локальное воспроизведение подтвердило `rewrite:true → keyMatchesReceipt:false`. Guard поставлен внутрь `applyVeNicheSourceSelection`; расширен существующий repair test.
2. Подтверждённые цитаты «офис в Казахстане/Беларуси» отклонялись из-за отсутствия падежных форм стран. Добавлены только целые формы восьми стран существующего HH-словаря; «Казахстанская улица» и аналоги не подтверждают страну.
3. `Москва\nМО` превращалось в `Москва МО` и не сопоставлялось с каталогом. При фиксации брифа переносы сохраняются как разделители списка, пустые значения/прочерки остаются без ограничения. Старые сохранённые контракты не переписываются автоматически.
4. Для обычного исчерпанного каталога geography repair показывался текст о сайтах платформ. У этой коррекции теперь собственная краткая причина завершения.

Проверки: 49 VE2 suites, 537 passed/1 skipped; полный PGlite SQL smoke; core/tests TypeScript7 и ESLint изменённых файлов. После правки переносов отдельно 23/23 проверок каталога/enqueue и повторная проверка типов. Новых it() и тестовых файлов нет. Широкие утверждения «точно ничего не сломается» не подтверждаются тестами; после деплоя остаётся проверка реального применения к Solo. Текущие лимиты расходов не повышены, дополнительные запросы к API не добавлены.
