## Запрос и результат

Владелец попросил исправить два дефекта из [аудита](../../reviews/vertical-engine/2026-09-24-419b378a7c96.md), отдельно разрешил добавить проверки в существующий `broadHypothesesExisting.test.ts`.

В рабочей ветке `codex/ve2-preview-recovery-scale`, база `40ef24bc4`, реализована миграция `20260924_0012_ve_broad_hypotheses_atomic.sql`: service_role-only RPC записывает вертикали, гипотезы и результат в `ve_jobs.result` одной транзакцией. Блокировки задачи и проекта, повторная проверка статуса, текущих дублей и лимита 5. Существующие данные не удаляются. Идемпотентный результат содержит ID и расход; стадия сначала читает его, поэтому потеря успешного ответа/повтор задачи не вызывают новую генерацию и не создают пустые вертикали. Явный пустой результат тоже фиксируется. Воркер сохраняет result при recovery/failure, а начисление расхода происходит при завершении, поэтому сохранённый суммарный расход возвращается за вычетом уже учтённого.

`VeBroadHypothesesOnlySchema` теперь требует массив корректных кандидатов (включая непустые название, описание, обоснование); неверный/отсутствующий блок вызывает schema retry. Полная генерация сохраняет мягкую обработку необязательного broad-блока. Для отдельной генерации включён requireCompleteJson, чтобы усечённый JSON не превращался в частичный успех.
