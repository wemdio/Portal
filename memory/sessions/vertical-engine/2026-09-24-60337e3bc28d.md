Уточнение к [паузе Instantly](2026-09-24-0ef27bf2efe6.md) поверх `Sergey / 5afe7bfe8`. Пользователь попросил перепроверить частичный отказ из-за workspace blocklist и потребовал загружать адреса, уже присутствующие в других кампаниях.

Найдены и исправлены края первой реализации:
- Предварительное обрезание всей партии по свободным местам могло создать ложную паузу: из первой части блок-лист отклонил адреса, места ещё есть, но остаток входа уже отрезан. Теперь размер каждого запроса ограничен текущим остатком; после ответа учитывается remaining_in_plan (либо вычитаются только accepted), цикл движется по нетронутому остатку исходного дневного резерва.
- При remaining_in_plan=0 полностью объяснённый постоянными причинами остаток больше не становится retryable. Суммируются явные in_blocklist/duplicated_leads/invalid/incomplete/duplicate_email счётчики; exact accepted identities дают безопасный complement. skipped_count не используется как доказательство: старый нормализатор синтезирует его из requested-accepted. Если причины смешанные (blocklist + storage) и адреса отказов неизвестны, сохраняется незагруженный complement для retry, без угадывания конкретных адресов; workspace blocklist всё равно применяется Instantly.
- Для append с явным skipIfInCampaign=false все три provider-флага теперь false: skip_if_in_workspace, skip_if_in_campaign, skip_if_in_list. Legacy VE2 direct refill также передаёт false (для delivery-bound проектов он по-прежнему запрещён). Основная дневная доставка уже передавала false; первичный shared runLaunch уже выключал все три флага.

Официальный контракт сверён 2026-09-24: https://developer.instantly.ai/api-reference/lead/add-leads-in-bulk-to-a-campaign-or-list. Флаг skip_if_in_campaign относится к ЛЮБОЙ кампании workspace, skip_if_in_workspace перекрывает остальные. Blocklist по умолчанию остаётся workspace default.

Проверки: целевые тесты сначала воспроизвели ложную паузу и неверную классификацию; после исправления весь набор 3175 тестов / 289 suites, TypeScript, ESLint и bundle VE2 worker прошли. PGlite проверил следующий рабочий день: skipped не входит в committed_count, готовый запас доступен, accepted/skipped/uncertain не выбираются повторно. Живых загрузок и production-записей не выполняли; новая SQL-миграция к этому уточнению не нужна, исходная feature требует 20260924_0013.
