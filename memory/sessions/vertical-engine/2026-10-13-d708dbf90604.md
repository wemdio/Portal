User requested a re-review of project INN/domain/exact-email exclusions after d3ee0c95d.

Confirmed and fixed a regression: when an aliased column is chosen as recipient while the source row also has an `email` field, `{...row, email: canonicalRecipient}` lost the original corporate email domain. A personal recipient could bypass a company-domain exclusion, particularly when operator mapping renamed the source email. New pure `veProjectExclusionRow` captures original INNs/domains privately before selecting recipient. Exact-email rules still match only the actual recipient, never other source addresses.

Applied to launch, preview, supply/refill, verified CSV and delivery identity creation. Private identity is stripped from provider requests and excluded from CSV columns. No new I/O, paid calls, schema changes or production mutations. Existing legacy identity recovery is unchanged. Full branch tests exposed optional source rows in launch recovery; helper preserves old spread behavior with `row ?? {}` and an explicit optional type.

Verification: existing test bodies extended (no new test files/it); 55 suites, 546 tests passed, 2 pre-existing skips. Five TypeScript partitions, changed-file ESLint and VE2 worker bundle passed. Independent reviewers verified callsites, exact recipient vs domain behavior, CSV/provider metadata stripping. Existing email migration was re-run in local PGlite: 38 assertions passed.
