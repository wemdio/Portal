Исправлен подтверждённый дефект прав RPC добора VE2. На production 2026-10-05 08:56 UTC StaffLine автоматически запросил 356 контактов при остатке 364, но завершился с `permission denied for function ve_require_contact_supply_active`. Проверка ACL подтвердила отсутствие EXECUTE у service_role. Исходная миграция считала guard внутренним helper, а код теперь вызывает его напрямую через Supabase RPC; CREATE OR REPLACE сохранил старые права.

Миграция 20261005_0062 выдаёт EXECUTE только service_role, сохраняя запрет PUBLIC/anon/authenticated. Тело guard, данные, паузы и согласования не меняются. Существующий исполняемый SQL smoke расширен проверками под реальной ролью worker, идемпотентности миграции, явного resume и неизменности delivery ledger. Smoke прошёл, fast branch tests: 33 suites, 255 passed, 2 skipped. Урок: SECURITY DEFINER не заменяет право EXECUTE у вызывающей роли; SQL smoke только от postgres не проверяет работоспособность RPC.

Изменение подготовлено локально для Sergey на базе test d3f3f4b5b; в рамках задачи production не менялся. Нужен обычный деплой с миграцией 0062, затем у StaffLine на «Результатах» нажать «Повторить поиск». Миграция не возобновляет ошибочный план автоматически. Следующий production-сбор пока не подтверждён. Подробнее: docs/handoff/2026-10-05-ve2-supply-eligibility-grant.md.

Предыдущий фикс billing preflight уже подтверждён: 359 новых контактов принято за текущий день, 1 пропущен, capacity block отсутствует. Это загрузка, а не число получателей первого письма; повторная заливка не нужна для исправления ошибки добора.
