## Запрос и подтверждённая причина
Пользователь поручил исправить подтверждённое после жалобы специалиста: для видимого абзаца нужны два Enter. В прежнем VE2 rich editor Enter и Shift+Enter сериализовались одинаково в один LF; CSS обнулял paragraph margins. Один Enter не пропадал, но не давал пустой строки между абзацами. Случайные огромные интервалы в реально доставленных письмах не воспроизведены и не объявлены исправленными.

## Изменение
- `veEmailBodyDocument` трактует двойной LF как границу абзацев, одиночный LF как hardBreak. `veEmailBodyText` сохраняет эту разницу.
- CSS абзацев соответствует одной пустой строке превью; line-height 1.6.
- Step3Content использует тот же LetterBodyEditor, что итоговые письма, вместо textarea. Сохранение, отмена, dirty state и API wire format не менялись.
- Старые тексты не мигрируют и не схлопываются: LF, начальные/конечные пустые строки и безопасные ссылки сохраняются. Shared clientLaunch/ENG транспорт не изменялся.

## Проверка
В локальном браузере на настоящем компоненте проверены Enter, Shift+Enter, undo, повторное открытие из сохранённой строки, 6 вариантов plain-text paste с переносами и их отмена. В редакторе, текстовом превью и HTML toInstantlyHtmlBody отступы совпали. Pure roundtrip 5471 вариантов старого текста — без потерь. Расширен один существующий it в briefInLetterPrompts.test.ts, новых тестовых файлов/it нет.
Первичная проверка: 59 suites, 599 passed / 2 skipped; strict TS5 typecheck и целевой ESLint pass. Перед фиксацией подтянуты два новых коммита origin/Sergey без пересечения с изменёнными файлами; результат итоговой проверки см. handoff.

## Границы
