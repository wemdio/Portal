Пользователь просит все новые VE2 кампании без link tracking и с общим daily limit 1000; ранее уже требовал open tracking off. Теперь VE_CAMPAIGN_SENDING_SETTINGS задаёт daily_limit=1000/open_tracking=false/link_tracking=false при создании кампании и VE-пресета. Общий payload builder и ENG не менялись.

Важное отличие: worker refreshDeliveryRate раньше делил и общий лимит писем на кампании, что отменило бы запрос пользователя. Теперь он держит 1000 у каждой принадлежащей этому VE2-проекту кампании, а daily_max_leads продолжает распределять из ручного/расчётного темпа новых контактов. После PATCH повторный GET должен подтвердить оба лимита и отключение tracking; иначе доставка новых строк откладывается. Mailbox limits остаются общими по всем кампаниям почты (официальный Help: https://help.instantly.ai/en/articles/6248612-account-and-campaign-limits).

Проверки: 30 tests/4 suites, strict types, ESLint, worker bundle. Новых test-файлов/it нет. Изменения в Sergey; деплой/прямые изменения production не выполнялись. Новая миграция не нужна. Существующие кампании проектов с настроенным темпом обновятся после выкладки при успешном обычном пересчёте; без настроенного темпа массовой правки нет.
