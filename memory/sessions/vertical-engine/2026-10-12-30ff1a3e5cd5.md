# VE2: meaningful continuation instead of repeat no-op clicks

User authorized fixing collection continuation, preserving spending limits, verification, commit and push to Sergey. No production writes, deployments or paid provider calls in this task.

Implementation in codex/ve2-editor-sergey-review, based on 6946a82c, destined for Sergey:

- `collectionRecovery.ts:getVeCollectionContinuation` is the full-checkpoint authority. It excludes dry/economically deferred sources, exhausted candidate/absolute round budgets, and already completed saved checks; retains admitted children, bounded recovery and once-only source correction. Do not call this predicate on `public_info`, which deliberately omits the checkpoints.
- Single-card POST preflights one full base and returns queued/already_running/unavailable/ready. Unavailable continuation creates no job and preserves ready base/approval. Actor and outcome are audited without contact data. Enqueue independently rechecks eligibility and claims with timestamp + revision CAS.
- `collectionContinuationCache.ts` stores a small verdict with version/status/timestamp/revision/contact-cap/triage basis. GET uses only this cache and bounded projections, never all `collect_info`. Legacy bases start with «Проверить и продолжить»; one explicit free preflight records a verdict. Bump cache version whenever the predicate/underlying selection rules change so stale negative verdicts do not hide newly available work.
- Migration `20261012_0001_ve_collection_continuation_cache.sql` adds the compact cache and revision invalidation trigger. No heavy backfill. Cache-only updates do not alter timestamp/checkpoints/public_info. Also adds durable `resume_collection_requested`; scoped request RPC has a single four-argument signature with a false default, compatible with existing three-argument auto-recovery. Stopped preparation becomes pending only if no live lease/job and not launched. Intent is consumed upon leaving pending.
- Finishing failed letters or linking an already prepared result carries no acquisition intent, including partial previews. Unknown SMTP results no longer reset on every source resume; only actual failed email recovery can reset inconclusive results. Existing children, conclusive results, source cursors and economic limits are retained.
- UI uses server decisions, counts active jobs beyond the last 30 and paginates them, recognizes durable pending requests/live preparation leases, repairs missing letters/links independently of acquisition availability, and removes stale request notices. Existing launch eligibility for reviewed ready template versions is unchanged.
