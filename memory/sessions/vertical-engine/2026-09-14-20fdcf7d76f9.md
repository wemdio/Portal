Запрос: исправить остановку VBI на 213 из 500 готовых контактов после восстановления SMTP.

Read-only production-диагностика: база `a7d6c650-05f7-480d-8d87-196459c7b12f`, 2 200 компаний, 12 завершённых пакетов, остановка 2026-09-14 08:23 UTC. В checkpoint 412 завершённых независимых смысловых проверок и 3 failed/invalid_response. Число 875 в статистике означает контактные строки с незавершённой проверкой, а не число ошибок API.

Корень: relevanceGate выставлял глобальную остановку на некорректный ответ по отдельной компании; восстановление failed/started повторяло остановку. Изменение: максимум две сохранённые до HTTP попытки на неизменный набор доказательств; повтор по одной компании, успешные решения переиспользуются. Исчерпанные компании остаются needs_review вне готовой аудитории, остальные продолжаются. Транспортные сбои идут через ограниченный backoff; billing/configuration остаются остановкой. Безопасная диагностика схемы добавлена без содержимого ответа модели.

Явное продолжение failed-превью теперь разрешает свежую проверку unknown SMTP: generation входит в детерминированный ID ребёнка. Сохраняются все однозначные результаты и уже активный ребёнок. Обычные пробуждения/повторные нажатия не начинают новые проходы. Это устраняет повторное чтение старого завершённого unknown-пакета после восстановления SMTP.

Проверка: 213 Jest-наборов / 2 402 теста за 55,3 секунды, без новых it() и тестовых файлов; tsc, ESLint и сборка воркера VE2 прошли. Первоначальный пробный запуск с --jitless не поддержал WebAssembly; обычный Node прошёл весь набор. Только VE2, ENG не изменён.

Production не изменялся. После обычного выпуска Portal и VE2 worker требуется «Продолжить подготовку базы» у VBI. Проверить сохранность 213 контактов и рост той же базы. Цель 500 на реальных данных ещё не подтверждена. Также остаются 472 website_identity_unverified и 295 website_evidence_timeout; правила доказательств не ослаблялись.
