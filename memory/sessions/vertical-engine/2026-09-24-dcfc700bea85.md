Пользователь попросил исправить только подтверждённые ошибки сборщика и отдельно разобраться с четырьмя остановившимися базами. Исправления подготовлены поверх 8d233355b для Sergey; production не изменялся, базы не возобновлялись.

Подтверждено по read-only состоянию production и локальному сравнению старого/нового кода:

- Артефакт / ресторанные холдинги (61 контакт) и ProfiAds / малые агентства недвижимости (28): сбор завершился на первом пустом раунде, хотя оставался продолжаемый каталог. В finishCollectionRound ветка candidates=0 перекрывала уже существующий бюджет пяти холостых проходов. При явно установленном idle теперь действует этот бюджет; отсутствие продолжения, исчерпание источника, предел кандидатов и ошибки продолжают останавливать сбор.
- Event&Marketing / остеопатические клиники: сохранённая задача companies_directory оставалась failed после восстановления базы, поэтому база повторно завершалась с тем же таймаутом. Возобновление теперь очищает только распознанный временный сбой каталога, сохраняет harvest и курсоры. При непустом harvest задача становится done, чтобы обработать сохранённый префикс до новой выборки. Это делается ПОСЛЕ открытия следующего раунда, иначе стандартное переоткрытие уничтожает префикс. Работает и для старого, и для конвейерного checkpoint.
- Новый пустой ответ каталога с таймаутом теперь сохраняет курсор по уже просмотренным/исключённым страницам и передаёт ошибку воркеру, оставляя задачу pending. Фраза «The upstream server is timing out» распознаётся как временная: штатные пять попыток с backoff 30–120 секунд. Незавершённый раунд сохраняет collecting, чтобы после исчерпанных попыток восстановление узнавало его checkpoint. Постоянные ошибки авторизации в этот путь не входят.
- Event&Marketing / МРТ/КТ: единственное проблемное исходное название содержало U+00AD внутри слова «исследовательский». Сравнение слов ошибочно отвергало правильно соединённое слово, а исходный fallback отвергался как управляющий символ. Мягкий перенос удаляется только в представлении/сравнении; исходные строки, идентичность и ключи оплаченных checkpoint не меняются. Запрет выдуманных слов, HTML и других управляющих символов сохранён.

Локальный диагностический прогон с подменёнными сетевыми ответами: до исправления 104/105 очищенных компаний; после — 105/105, повторный запрос содержит ровно одну компанию. Пустые проходы: collecting ×4, затем limited. Восстановление сохраняет тот же base id, строки и курсоры. Таймаут после 1000 просмотренных дубликатов сохраняет cursor=1000, готовые строки и pending-задачу.

Экономические пороги намеренно НЕ менялись. Предыдущее ревью 2026-09-24-b86d6deb8624 верно описывает отсутствие обязательного стопа исходного источника после двух смен плана, но этого недостаточно, чтобы объявить безопасным стоп по выходу <5%. Этот порог служит смене источника; известный рабочий источник фондов даёт около 2.6%. Стоп всех источников при <5 контактах на >=1500 компаний и общие пределы кандидатов/раундов сохранены. Неполный учёт расходов не доказывает экономический убыток. Обещать, что три медленные базы завершатся к конкретному времени, нельзя: холостые проходы могут сдвигать бюджет раундов.

Проверка: полный Jest 289 suites / 3143 tests, 0 failures/skips, около 23 секунд; TypeScript, ESLint изменённых файлов и сборка VE2 worker прошли. Существующие тесты не расширялись: отдельный вопрос о разрешении оставался без ответа, дефекты воспроизводились временным локальным диагностическим скриптом. После финального ужесточения сравнения checkpoint повторены 73 проверки сборщика/возобновления и статические проверки.

Дальше: штатный деплой через принятый release-процесс, затем согласованное продолжение этих четырёх существующих баз с сохранённых результатов. Commit/push к Sergey не означают деплой или восстановление production.
