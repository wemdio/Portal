# VE2: исключения клиентов по ИНН и доменам

Пользователь запросил исключения на уровне каждого VE2-проекта для сбора и ежедневных дозагрузок; разрешил commit/push в Sergey, без deployment/production writes. Явное решение: исключать только найденные совпадения, остальные оставлять с видимым ограничением проверки. Нет fuzzy-сопоставления названий, платного поиска ИНН/доменов или обхода сайтов.

Реализованы настройки в шапке проекта, GET/PUT API, атомарное сохранение с revision/CAS, project-scoped таблица и журнал только счётчиков в миграции 20261012_0002_ve_project_exclusions.sql. ИНН — точные текстовые 10/12 цифр (формат, не подтверждение юридической идентичности); домены нормализуются, учитываются поддомены и IDN, общие почтовые/каталожные домены не идентифицируют компанию.

Фильтр применяется перед платными этапами collection, повторно после обогащения/очистки, к preview/launch-ready CSV, новому запуску, запасу, supply и перед каждой HTTP-порцией Instantly. Повторная проверка revision после rate admission останавливает ещё не отправленную порцию при изменении списка. Уже начатый HTTP и исторически загруженные контакты не отзываются. Исключённые оплаченные наблюдения сохраняются приватно с вердиктами; бюджеты, курсоры и ограничения партий не сбрасываются. Снятие исключения не запускает само платную работу или исчерпанную базу.

Важные найденные и исправленные совместимости: SQL supply требует побайтово совместимый с audit payload; recovery повторяет прежний payload без добавления новых metadata. Новые launch rows сохраняют private identity, удаляемую перед провайдером. Для старых delivery rows INN восстанавливается только из собственного сохранённого base по точному email и однозначной идентичности; неоднозначная общая почта не переносит чужой ИНН. Сохраняются оригинальные индексы chunk/ledger, включая целиком исключённые порции. ENG не использует новый опциональный guard.

Проверки: branch-tests 79 suites / 773 passed / 2 skipped; все 5 разделов typecheck:strict; ESLint изменённых TS/TSX; worker bundle; локальный PGlite fixture миграции — 18 проверок CAS/ACL/валидации/публичной проекции. Независимый обзор collection/delivery/UI не нашёл оставшихся блокеров. Новых test files/it() не добавляли. Чужой origin/Sergey b81e85f41 (mailbox-load) нужно сохранить при интеграции; исходная база задачи 8144d4bf7.

Пользователь передал CSV «AUDIT PROFI _ Действующие клиенты по ИНН - Sheet1.csv»: 260 уникальных ИНН, 211 десятизначных и 49 двенадцатизначных; доменов нет. Идентификаторы/контакты не помещались в Git. Локальная нормализация приняла все 260, синтетическая проверка каждого exact match успешна. Это НЕ измерение реального покрытия. Read-only production подтвердил 6 analyzed-баз Аудит Профи; счётчики в сумме 3934 (не уникальные получатели и не повторно проверенная готовность). Подсчёт совпадений только SQL-агрегатами отменён statement_timeout 15s, покрытие неизвестно. Передача полных production contact rows была отклонена automatic approval review, данные не выгружались. Повышать timeout/нагрузку не стали.

Следующий шаг после обычного пользовательского deploy: сохранить список 260 ИНН в исключениях Аудит Профи и скачать готовую выгрузку заново. В production список в этой задаче НЕ внесён, миграция НЕ применялась, кампании/отправки не менялись.
