Это уточнение текущего согласованного сценария; независимость квот не выводится из различия ключей. Публичный Wallet API не сообщает идентификатор владельца квоты.

Локальная реализация в `Sergey` поверх `eb153073c`:
- Пул выключен по умолчанию. `ENG_TINYFISH_POOL_ENABLED=1` включает дополнительные аккаунты из секретного `ENG_TINYFISH_EXTRA_ACCOUNTS_JSON`; основной использует прежние настройки. Постоянные operator accountId обозначают реальные quota accounts и не меняются при замене ключа. Неверная конфигурация, дубли ID/ключей закрывают доступ; максимум 20 аккаунтов.
- Каждый аккаунт отдельно проходит проверку свежей нулевой цены Fetch и usage. Следующий аккаунт разрешён только при подтверждённом дневном исчерпании в metadata или RPC. Ошибки авторизации/metadata, неизвестная/ненулевая цена, общий минутный отказ не вызывают переключение. После любой попытки Fetch URL не повторяется другим ключом. Один таймаут 15 секунд ограничивает весь пул.
- Миграция `20261030_0002_eng_tinyfish_pool_budget.sql` сохраняет reservations, инициализирует общую минутную историю и заменяет RPC с прежним полем granted плюс budget_version=2/причиной отказа. Лимит 1000 за скользящие 24 часа на аккаунт, 120 за скользящую минуту суммарно. Единый порядок блокировок: общий ledger, затем аккаунт. Новый reader требует v2; без миграции TinyFish пропускается.
- При исчерпании всех аккаунтов сохраняется HTTP/browser результат, следующий сайт продолжает читаться своим браузером; платного продолжения и автоматического повтора старых страниц нет. Search и Datasets не менялись.
