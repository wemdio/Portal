Пользователь уточнил, что его интересуют сценарные ошибки непрерывного пополнения: готовый позднее запас должен дозагружаться в тот же день в пределах дневного плана. Старый daily reservation разрешал повторно открыть только пустой день, а частично обеспеченный день после первой попытки возвращал replay.

Реализована 20260929_0061_ve_intraday_contact_refill.sql: тот же run, дополнительное резервирование только остатка исходной квоты и текущей мощности; проектная квота общая для всех гипотез. Attempt history не удаляется. Уже выделенные места, включая unknown/released/skipped, считаются консервативно занятыми. Прежние идентификаторы обслуживаются explicit retry/recovery, не новым отбором.

Особенно проверить потерю ответа БД после резервирования второй партии: старые finalized attempts не должны мешать вернуть новые unattempted reserved rows. Pending provider request останавливает новый отбор; unknown учитывается в headroom. После освобождения старого unknown через recovery необходимо пересчитать сохранённый awaiting_delivery того же дня.

Проверено PGlite: 3 партии в один день; общий лимит двух запусков; пауза одной кампании; изменение темпа; цель/закрытие; lost reply; unknown/skip/release; следующий день; запрет прямого вызова helper. 52 suites / 483 passed / 2 skipped. Код предназначен для Sergey поверх 4511006ec, production не изменён. Подробности: docs/handoff/2026-09-29-ve2-intraday-refill.md.
