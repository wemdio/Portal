## Запрос

22.10.2026: сбор HST Insurance carriers простоял ~47 минут за стадией `evidence` RU-проекта во внутреннем инструменте — единственный HE-процесс выполнял её монопольно. Пользователь попросил отдельный воркер для ENG-сборов; RU и VE2 по поведению не менять, письма не запускать, деплой — сам.

## Что сделано

`HE_WORKER_LANE` (`app/src/lib/hypothesisEngine/heWorkerLane.ts`): не задан/`all` — прежний процесс; `serial` — всё, кроме проверенных ENG-сборов; `eng_collections` — только они; неизвестное значение — отказ старта. В воркере: клейм только своей полосы без барьера по чужим задачам; один проект — одна полоса за раз (учёт расходов проекта сериализован только в процессе); `resetStuckJobs` возвращает в очередь только свои строки; служебные проходы только в `all`/`serial`. Compose: основной HE-воркер `serial`, новый `worker-hypothesis-engine-eng` — `eng_collections`, тот же том кэша Companies House; сервис добавлен в список деплоя и в дренаж. Документ: `docs/handoff/2026-10-22-eng-collection-worker-lane.md`.

## Урок

Второй процесс того же воркера нельзя просто добавить в compose: на старте он возвращал бы в очередь все `running`-строки, включая оплаченную стадию соседа. Любое разделение очереди начинается с разделения сброса зависших строк.

## Проверка

TypeScript, сборка воркеров, полный Jest (298 наборов), тесты проводки деплоя, `bash -n`, разбор compose, офлайн-правила полос. На проде ещё не выкачено.
