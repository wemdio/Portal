## Scope

Read-only audit of existing Portal guest lead-board rows on Sergey 887022390 after the 2026-09-23 data repair. Compared 2,782 automatic rows with qualification records, the current client_campaign_leads cache, reply bodies, board configurations, and current worker code. No production writes or notifications in this audit.

## Verified findings

- All 989 status=lead qualifications with a proven qualified_project_id have a board row in the same project. Historical rows often have no qualification project snapshot, so this count does not describe every old lead.
- Of 2,782 automatic rows, 1,254 have no lead_name, 1,009 no company_name, 2,448 no phone, and 1,871 no website. Empty alone is not an error. Current qualification company_name exists while board company_name is empty in 26 rows (15 projects, dated Sep 8-12); no original guest edits in these 26. In all 26, qualification updated_at was not later than board created_at. The board upsert ignores duplicates and cannot repair existing blanks.
- Current cache client_campaign_leads has first_name, last_name, company_name, website, but **no phone column**. Only 103 board rows currently match cache by campaign+email. In matched rows 5 blank company fields have a nonempty cached company (one cached "company" is actually a person's name, so validation is required), and 26 blank sites have nonempty cached sites (22 from July 26 historical batch). This explains why Instantly API unavailability can leave phone blank unless sender reply has a reliable phone.
- step_number is null in 1,029 rows (all July legacy rows), zero in 252 (including 10 of 59 on Sep 22), and positive in 1,501. Worker calculates count of ue_type=1 outbound messages in fetched thread without rejecting zero. Zero is not a real step. Of the 252 zero rows, 22 are outside-campaign replies; the problem also affects in-campaign replies.
- campaign_name is null in 42 rows, all from the July 26 batch. No recent campaign-name gap found.
- Current sender-display fallback can put generic labels into the name field. A simple pattern audit found 54 stored names containing an email/domain or generic sender label; 9 of those have a different plausible personal name extractable from current reply. This is a review set, not a proven total error rate. A reply-only extractor proposes names for 397 of 1,254 blank-name rows, but some proposals come from old quoted history and must not be auto-applied.
- Two projects have custom columns: c_inn (215 rows) and c_tema_tsepochki_pisem (44 rows). No row has a custom value. Current board writer never maps upload/qualification data to custom columns, and UI exposes them for manual entry.
- 140 old rows belong to 17 projects with no current board token; all 17 projects are marked completed in the main Portal DB and all rows share July 26 creation timestamp. There is no evidence of this happening for current active projects.
- The 102 request_text rows skipped during the previous repair remain a separate review set; the earlier repair did not reclassify them.
