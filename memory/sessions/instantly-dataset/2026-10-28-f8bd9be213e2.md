## Запрос и решение

29 октября пользователь выбрал одну визуальную колонку «Контакты» для телефонов, Telegram, WhatsApp и адреса; Email остаётся отдельно. Это заменяет решение о трёх дополнительных видимых колонках из session `2026-10-28-a0e9d5761cfa.md`. Хранение отдельных значений и ограничения их извлечения не меняются.

## Реализация

- Внутренний ключ `phone` сохранён, reserved JSONB `telegram`/`whatsapp`/`address` показываются внутри него. Старые конфиги сворачиваются при чтении без записи в БД; порядок/видимость остальных и пользовательские `c_*` сохранены. Узкий fallback оставляет колонку видимой, если иначе после сворачивания не осталось бы ни одной видимой колонки.
- Читаемый блок с подписями, безопасными ссылками и переносом адреса; inline-редактор с явными Сохранить/Отмена. Отправляются только изменённые поля одной операцией, ошибка сохраняет черновик; Escape отменяет, Ctrl/Cmd+Enter сохраняет. На мобильном — цели 44 px, колонка не перекрывает остальную таблицу при горизонтальной прокрутке.
- Копирование контактов/строки/таблицы сохраняет контакты одной TSV-ячейкой. Новый импорт «Контакты»/Contacts понимает подписанные значения; прежние singular «Контакт»/Телефон остаются raw. Отдельные столбцы импорта приоритетны даже при явном пустом значении.
- API принимает reserved поля независимо от визуального конфига. CAS, project scope, tombstone очистки мессенджеров/адреса и старое поведение phone=null не меняются. Полный серверный custom после сохранения заменяет локальный объект, чтобы не воскресить удалённое параллельным редактором примечание в UI/копировании.
- Обнаруженные при review края закрыты: action URL в Telegram @fastpath; phone-only текст с меткой «Адрес:»; C0/formula-like начало в копировании; параллельно удалённый custom. Небезопасные ссылки остаются текстом.
