# Подготовленный одноразовый приоритет manual-scoring №24

Пользователь разрешил только код и тесты, без deployment/restart/production writes.
Правка изолирована в managed worktree на собственной ветке
`codex/manual-run24-priority`, база `048da61ab` (main); чужая ветка и её dirty
изменения не затронуты.

Новый opt-in selector выключен по умолчанию. Адресный guard проверяет существующий
run, retry/routing flags, 88 фиксированных исходных IDs/UTC MD5, 12 NULL-bucket
строк, отсутствие ошибок и собственных receipts. Короткая PG-транзакция блокирует
только target/его rows и меняет только status pending→processing; timestamp-правок,
enqueue и migration нет. Тот же serial daemon вызывает неизменённый runner.
Startup cleanup пропускается в opt-in, чтобы не удалить другие expired runs.

Не считать advisory lock глобальной worker lease: требуется один daemon. После
неизвестного COMMIT/crash processing не переоткрывается; нужно отдельное read-only
выяснение и новое человеческое разрешение, а не автоматический повтор handler.
Строгий guard запрещает подменять zero-receipt recovery частичным append recovery.
При guard/DB ошибке нет обходного обычного выбора на той же итерации.

Проверено локально: unit tests для selector/claim, существующие snapshot/append
regressions, scoped lint/typecheck и esbuild worker. SQL выполнен offline на
синтетическом PGlite; только digest позитивной synthetic fixture адаптирован к
фиксированному production baseline, сами SQL/locks/counts/UPDATE/COMMIT/ROLLBACK
исполнялись. Full-project TS5 check достиг heap limit; это не полный зелёный
typecheck. Production не запускался и не менялся.

Источники: app/src/lib/jobs/manualScoringRun24Priority.ts,
app/worker/manualScoringWorker.ts, app/tests/lib/manualScoringRun24Priority.test.ts,
docs/operations/manual-run24-one-shot-priority.md. Новая активация/deploy требует
отдельного одобрения; обычный restart с коротким stop_grace_period посреди пакета
может прервать job несмотря на SIGTERM handler.
