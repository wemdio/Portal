Пользователь попросил «Не лид» в Telegram-карточке передачи, только в ручном режиме: ложные срабатывания не должны быть видны в клиентской таблице, решения специалистов нужны для последующего разбора.

Реализовано в ветке задачи codex/ve2-preview-recovery-scale для push в Sergey: отдельная HMAC-кнопка, общий со send/edit контроль специалиста/PM и чата, повторная проверка текущего handoff_auto_send, атомарный RPC reject_instantly_handoff. Отказ конкурирует с уже существующим manual_send_claimed_at/status CAS; начатая отправка и открытый редактор запрещают отказ. Сохраняются actor/time/rejection_snapshot; исходная классификация ИИ не переписывается. Повторный callback идемпотентен.

Клиентский API переведён на project_client_lead_board_rows: review candidates и rejected скрыты при чтении, редактировании, удалении и импорте. Внутренние строки сохраняются для анализа; выгрузка страницы использует только опубликованные API rows. Флаг specialist_review_required сохраняется до материализации карточки, ошибка чтения конфигурации не разрешает публикацию. Durable handoff job восстанавливает кандидат перед карточкой при сбое первой записи. Новое состояние rejected терминально для handoff recovery. Уже существующие незавершённые ручные передачи тоже скрываются; сами старые Telegram-сообщения автоматически не обновляются.

Проверено: 291 Jest suite / 3230 passed / 2 skipped / 107.868s; core и API typechecks; ESLint; сборка worker-instantly-leads. Реальное применение SQL в локальном PGlite (38 проверок), 45 runtime-проверок с подменой сетевых методов (права, автопередача, callback, подписи, штатная отправка, повторное нажатие). Артефакты: /Users/cybermart/.codex/handoffs/handoff-not-lead-20260926/. Постоянные тестовые файлы не добавлялись: вопрос о расширении существующих тестов остался без ответа.

Нужны пользовательский деплой Portal/worker-instantly-leads и миграция операционной Instantly DB 20260926_0001_handoff_not_lead.sql. Production, Telegram и платные API не вызывались. Статус реальной отправки подтверждается существующим sender; неопределённый исход внешнего запроса не даёт возможности отклонить уже начатую передачу.
