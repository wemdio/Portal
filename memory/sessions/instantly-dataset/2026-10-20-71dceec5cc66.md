Follow-up to `sessions/instantly-dataset/2026-10-20-aecc3ed7a4ec.md` before commit: final review found that `collectCampaignEvidence` discards outgoing messages from campaigns outside the current candidate list. The new missing-send fallback could therefore mistake an actual unmapped historical parent for an absent send. Two additional one-off tests reproduced that risk in fresh and recovery modes.

The final patch retains independently matching actual parents outside mappings as a veto ONLY for the direct same-recipient quote shape used by the new fallback. It does not assign their owner or widen normal candidate-based routing. The new fallback checks all retained evidence keys, not just current/provider candidates. Recovery uses evidenceVersion 5 for this shape so completed older checkpoints which discarded these sends cannot be reused; other quote shapes retain versions 3/4. A second recovery pass was verified to preserve the veto from the checkpoint without rereading provider pages.

Final validation: 53 one-off tests, 313 existing tests in 8 suites, strict TypeScript, targeted ESLint, worker build and scoped diff checks passed. No production writes, notifications, requeues or paid AI calls. The actual incident still resolves Polza locally. All preceding release boundaries remain unchanged.
