Исправление: nullable `send_attempt` JSONB + общий атомарный захват обеих веток; `request_started` сохраняется через onRequestAttempt до POST. Успех reply требует provider ID; receipt и sent сохраняются одним patch с 3 идемпотентными DB-попытками. При потере ответа/5xx/malformed receipt — unknown, без повторного POST; в чате постоянное предупреждение. Ошибка публикации после успешного POST — publicationPending, receipt дублируется в безопасный runtime log, без повторной отправки. Типизированный HTTP 400 допускает прежний Others fallback только для not-part-of-campaign; таймаут fallback также блокирует resend. Явные HTTP-отказы отделены от unknown; доказанный pre-POST failure и429 могут сбросить только свой claim для безопасного retry.

Legacy auto pending И failed без ready-журнала не отправляются: старый процесс мог упасть после POST. Новые строки получают ready при materialize. Manual unclaimed pending требует явного нажатия с прежними правами. Старые held claims не сбрасываются. Active attempt первые5мин возвращает in_progress: worker может только перечитать состояние; UI не перезаписывает результат конкурента. Затем — unknown/manual review, не доказательство неотправки.
