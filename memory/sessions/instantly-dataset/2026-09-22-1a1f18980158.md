Задача: после исправления полей гостевой таблицы проверить остальные колонки и поэтапно устранить подтверждённые дефекты без массовых догадок или рассылок.

В рабочей ветке `Sergey` на базе `641e941f6` исправлены будущие записи: номер шага становится `null`, когда исходящие письма в доступной истории не найдены; отображаемое имя отправителя проходит проверку на служебный ящик/бренд/роль и при наличии явной личной части отделяется от приписанного отдела; `Вы писали <дата>:` служит границей старой переписки и для полей контакта, и для отображаемого запроса; `С уважением:` распознаётся как начало подписи; номер в реестре не считается телефоном; старый список номеров с запятыми разделяется; голое ФИО из поля компании отклоняется, но `ИП <ФИО>` сохраняется. Для кэша `client_campaign_leads` подготовлена миграция колонки `phone`, чтение и запись совместимы с коротким периодом до применения миграции.

Проверка на локальном приватном снимке: из 1468 имён, которые были только фолбэком из заголовка письма, 38 очевидных служебных/email/domain значений новый фильтр отверг все; 17 сохранённых запросов с блоком `Вы писали` новый парсер сокращает без пустого результата; 26 пустых организаций имеют заполненный источник в квалификации, но требуют отдельной адресной сверки/разрешения на production-изменение. Приватный снимок и персональные данные в Git не переносить. Существующие 154 проверки `leadQualificationWorker.test.ts`, ESLint, строгая типизация и сборка воркера прошли; разовые локальные проверки показали корректную подпись и отсутствие номера реестра. Production-данные, деплой и уведомления этой задачей не менялись.

Ограничение: пустые сайт/телефон при отсутствии надёжного источника нельзя автоматически заполнять из цитат, свободного email-домена или названия компании. Кастомные колонки гостевой доски остаются ручными до задания явного источника. Старые строки не меняются сами, потому что вставка доски использует `ON CONFLICT DO NOTHING` для защиты ручных правок.
