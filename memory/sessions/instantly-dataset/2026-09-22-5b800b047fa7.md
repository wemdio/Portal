## Verified findings (2026-09-22 UTC)
- Read-only operational DB audit found 11 unprocessed reply webhook events whose email_id already had a qualification row. drainWebhookQueue fetched /emails before checking that ID; unavailable context/quota requeued already-persisted replies. This wastes shared reads; it is not evidence that ALL quota pressure has one cause.
- Qualification 2be48927-2721-4556-9a0d-eacdb5b32418 was a false positive: its full 147-character response was a duplicated signature. Custom name/contact criteria reached AI despite no authored reply.
- Three active retries showed "thread context unavailable" although the inbound was durably present. resolveEffectiveReplyOwner propagated a null provider search result to qualifyReply instead of retaining the known inbound.
- One additional full acknowledgement format ("письмо получено / мы обязательно на него ответим") fell through the technical filter.
- Read-only mailbox campaign-mapping metadata and local project/period links confirmed current Polza mappings resolve one project, but historical mappings coexist. Roomlink's receiving mailbox has two current Roomlink campaigns while the affected provider replies carry a GATE campaign absent from those current assignments.
- Complete stored evidence scans for several ambiguous replies contain context but no qualifying outbound parent. Two other receiving mailboxes return no campaign mappings and their provider campaign links are automatic/text-only. These are genuine missing/conflicting evidence, not permission to assign an owner by name or delete pending data.

## Implemented
- Early webhook dedup by event.email_id before API reads/pacing; failed DB lookups reopen the event. Post-fetch lookup failure cannot replace a possibly terminal qualification with pending.
- Null search context retains the known inbound with historyFetchFailed=true. Only complete evidence clears the flag; missing history is not fabricated and does not become a negative semantic verdict.
- Full-body, explicit-signature-only veto before AI/custom promotion. Unknown content and human requests before/after signature are preserved; a genuine bare name/phone handoff still follows custom criteria. Narrow surname fallback covers uncommon Russian names.
- Additional exact acknowledgement clause supported, retaining all-segment and appended/inline-human-content checks.
- Existing test cases/matrices extended only; no new test files or added standalone it blocks.
