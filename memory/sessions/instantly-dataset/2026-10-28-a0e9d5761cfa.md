# Telegram, WhatsApp и адрес в гостевой таблице

Пользователь 28 октября попросил переносить мессенджеры и физический адрес из карточки Instantly, кроме существующих телефонов. Подготовлена локальная версия поверх detached 023f2b45a в mailganer-board-fixes; не развёрнута и не отправлена в удалённую ветку.

## Реализация и ограничения

- Новые встроенные колонки telegram, whatsapp, address хранятся в существующем rows.custom; миграция не нужна. Старые c_telegram/c_whatsapp/c_address не перехватываются. Телефон/email и настройки публикации не меняются.
- Автозаполнение только из явно названных полей точного email/campaign Lead, включая payload/custom_variables уже существующего API lookup. Нет новых API/AI запросов. Не переносить личные каналы через originalCompanyContact.
- Не выводить WhatsApp из обычного телефона; не принимать посты/инвайты Telegram, off-host/credentialed/action URLs. Ссылки и адрес можно редактировать и копировать вместе со строкой/таблицей.
- Новые поля намеренно НЕ извлекаются из текста/подписи письма. Независимая проверка пробной версии выявила наши messenger-ссылки в Zendesk/Timepad/flattened history и информационные каналы. Пробная логика полностью убрана, leadReplyContacts не менялся. Чтобы расширять это позже, нужны отдельные доказательства авторства, а не только нынешняя граница подписи.
- Writer заполняет только отсутствующий own-key. Даже пустая строка/null сохраняются как ручной выбор. API при очистке этих трёх ключей сохраняет пустую строку. JSONB PATCH использует optimistic version/CAS и reread/retry, сохраняя другие ключи.
- Старые конфиги дополняются при чтении, без записи/backfill; существующие порядок и hidden сохраняются. CSV/XLSX знает новые колонки. UI optimistic merge не теряет соседние custom values.
- При временно недоступном API нынешний cache не содержит этих полей: пустое значение не доказывает отсутствие контакта в Instantly. Старые записи автоматически не обогащались.

## Проверка

- 32 isolated extraction controls, 49 mocked writer/API/config/import controls, 101 независимая structured-only проверка PASS.
- 2759 сохранённых писем: прежние контактные поля идентичны baseline; новые поля из текста не извлекаются.
- Browser fixture (никакого production): 1440x900 и 390x844, edit, clear+reload, copy, сохранение соседних custom; ошибок JS нет. Сохранён обычный плотный вид таблицы, следуя impeccable.
- TS5 core/pages/API typecheck, worker compile PASS. ESLint: без ошибок, одно прежнее предупреждение setState-in-effect в guest page.
- Одноразовые harness в .tmp: additional-contacts-check.cjs, additional-contacts-board-check.cjs, additional-contacts-independent.cjs, lead-board-ui-check.cjs. Постоянные тесты не добавлены.
