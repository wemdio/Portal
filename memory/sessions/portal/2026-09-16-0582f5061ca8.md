## Запрос и решение пользователя

После экспорта системного промпта пользователь указал, что обработка возражений не нужна ни квалификатору, ни интерфейсу Portal. Бизнес-результат должен быть только «лид / не лид». Подготовка и редактирование ответа при передаче признанного лида остаётся отдельным действующим функционалом.

## Изменения

- Из buildSystemPrompt удалена третья категория, инструкция составлять ответ на возражение и два поля objection_* из требуемого JSON. Бриф остаётся контекстом продукта, не доказательством отправленного оффера. Мягкий отказ сам по себе не лид; отдельный позитивный CTA и правила проекта сохраняют силу.
- Парсер принимает новый сокращённый контракт, игнорирует obsolete поля в старых/provider ответах, но сохраняет строгую валидацию бинарного решения. Внутренние legacy поля и DB-колонки оставлены инертными (false/null) для совместимости, не для работы с возражениями.
- Worker больше не создаёт status=objection; только lead/not_lead после успешной квалификации. Технические ошибки, восстановление и автоматическая повторная смысловая оценка не превращаются в бизнес-отказ.
- GET qualified-leads отображает исторические objection как not_lead и включает их в соответствующие фильтры/счётчики на обоих путях (snapshot и старая схема). Objection drafts не возвращаются. История физически не переписывается, не переоценивается, уведомления не повторяются.
- Удалены вкладка/метка/черновик возражения из UI, текст страницы брифов исправлен. Старая надпись «На проверку» заменена на «Автопроверка». Передача и ответ из карточки доступны только признанному лиду; API forward/forward-email/handoff-draft также проверяют status=lead.

## Проверки и границы

Рабочая копия задачи detached поверх origin/Sergey 78c273d65. Изменения предназначены только для Sergey, не engSPF.

Полный Jest: 213 suites / 2405 tests PASS, 55.763 s. Прицельный набор: 342 tests PASS. Дополнительные разовые проверки вне репозитория: новый JSON, игнорирование старых draft-полей, 8 вариантов промпта, старые записи/счётчики/пагинация/изоляция доступа в 3 режимах схемы, запрет передачи 5 нелидовых состояний по 2 API. Первые ошибки временной проверки были ошибками фикстуры (getRows возвращает копию, отсутствующая дата сортировки, отсутствие профиля второго пользователя); после исправления фикстуры все 3 временных теста PASS. Новых постоянных тестов без ответа на согласование не добавлено.

TypeScript и сборка instantlyLeads worker PASS; ESLint без ошибок, остаются старые предупреждения set-state-in-effect. Проверки используют моки, не живую ИИ-модель или внешнюю отправку. UI не проверялся в живом браузере.

Не менялись production, БД, маршрутизация проектов, модель и лимиты очереди. Миграция для этого изменения не нужна. Для вступления изменений в силу требуется пользовательский релиз и redeploy приложения и обработчика.
