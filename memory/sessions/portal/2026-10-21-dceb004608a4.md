User request 2026-10-21: Sender Statistics needs aggregate selections for all Russian or all English auto-outreach campaigns.

Implemented dropdown choices in StatsTab and source query propagation through stats, bounce-code counts and detail requests. Grouping uses sender_campaigns.source_kind (polza_ru/polza_en), not campaign names, folder display labels or the picker limited to 200 recent campaigns. Manual campaigns are excluded. The scope switch appears only for the global report; group filters always require campaign attribution even if scope=all was retained in state.

Migration 20261021_0020_sender_stats_source_filter.sql adds optional p_source_kind to the four statistics/bounce RPCs. All cohorts, letter counts, daily series, inbox, suppressions, mailbox pools and bounce details apply it. The optional campaign filter intersects the source filter. No-source results preserve previous semantics. Group responses do not append enabled domains belonging to unrelated senders. Existing signatures are dropped to prevent ambiguous default-argument overloads; explicit execute access is restricted to service_role. The MCP guide documents the pending migration.

Validation: TypeScript 7 core/API projects and ESLint passed; 16 existing migration assertions passed. Temporary local PGlite execution applied the migration twice, compared full dashboard/code/detail results for 12 baseline filter combinations and checked RU/EN data isolation, renamed campaigns, manual campaigns with misleading names, cohort vs event dates, foreign replies on a shared mailbox, empty/intersecting filters, mailbox counters and function grants. Temporary API/client harness verified validation and argument/query propagation. A local browser rendered the real StatsTab with synthetic API fixtures and verified all/RU/EN/single campaign selection. Preview screenshot is local output only, with test-data label. No permanent test files added.

Scope: branch dmitriy_kuladmed_new, base c4ca459f0. No push, database migration, production changes or deployment performed; those phases require user approval. The earlier AMO commits remain local too.
