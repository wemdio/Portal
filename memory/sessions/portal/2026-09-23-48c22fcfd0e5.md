Пользователь одобрил исправление малого HH-выхода после read-only аудита [2026-09-23-db3ecf266d50](2026-09-23-db3ecf266d50.md), с условием не сломать действующий аутрич.

- В коде OutreachOS включён полный обход HH-выдачи: отраслевой запрос с `found > 2000` рекурсивно делится на временные интервалы; соседние интервалы перекрывают граничную секунду, кандидаты объединяются по HH employer ID. Ошибки страницы после трёх попыток теперь прерывают прогон, чтобы не считать неполную выборку успешной. Остальные клиенты общего HH-парсера сохраняют прежний режим: полный обход включается только опцией `exhaustive` из OutreachOS.
- Активный seen-журнал теперь загружается до HH-обогащения. HH ID, ещё находящиеся в окне, пропускаются перед дорогим запросом `/employers/{id}`; домен дополнительно проверяется после обогащения. Это компенсирует дополнительные страницы поиска и сохраняет защиту от дублей.
- Статус `appended` остаётся закрытым 45 дней. `skipped` (намеренный LLM-отсев неподходящих компаний) тоже остаётся закрытым 45 дней: сокращать его срок оказалось рискованно. Только `no_email` повторно проверяется через 7 дней. Одинаковая семантика применяется при обратном кросс-дедупе 2GIS по домену.
- На момент read-only снимка production из 12 318 HH-строк `no_email` в прежнем 45-дневном окне лишь 808 имели возраст менее 7 дней. Остальные смогут вернуться только при новой вакансии, а не через автоматический повторный прогон старого списка.
- Проверка: полный набор проекта 252 suite / 2703 тестов прошёл; строгий typecheck, ESLint изменённых файлов и сборка OutreachOS worker прошли. Локальные сценарии проверили разбиение переполненной выдачи и сроки кеша; новые постоянные тестовые файлы не добавлены по правилу проекта. HH API read-only подтвердил работу `date_to` на историческом окне.
- Изменение не требует миграции; production ещё не менялся. Первый запуск после штатного деплоя стоит проверить по времени выполнения, размеру списка и лимиту Instantly.
