После добавления поля `via` в успешный ответ API компонента клиентских ответов CI показал 3 падения в `ExpandedThreadHistoryDeferred.test.tsx`: прежний успешный ответ `{ ok: true }` перестал запускать загрузку истории, поскольку UI сравнивал только `result.via === 'reply'`. Предыдущая версия API действительно возвращала только `{ ok: true }`. Исправление считает отсутствующее `via` обычным ответом (`reply`); явное `via: 'test'` по-прежнему означает отдельное письмо без обновления треда. Поле адресата в уведомлении опционально, чтобы не показать `undefined`.

Проверено на ветке `codex/client-reply-recipient`: до исправления воспроизведены те же 3 падения; после исправления целевой набор 8/8, весь Jest 293/293 набора и 3265 пройденных тестов при 2 пропущенных, TypeScript с `NODE_OPTIONS=--max-old-space-size=8192` завершился без ошибок. Исходный лимит Node 4 ГБ приводил к OOM TypeScript на полном проекте; это ограничение запуска проверки, не ошибка типов.
