## Запрос

Проверить конфликт привязки `connect@polzaagency.online`, который пользователь подтвердил как ящик одного клиента, и предотвратить повторение ошибки.

## Результат

- Live read-only диагностика показала, что ящик одновременно попадал в кампании другого клиента через общий тег пула `неименные почты`; собственный клиентский тег был `Польза Ру`.
- В ручном создании кампании Portal тег раньше сохранялся в `email_tag_list`, поэтому последующие изменения состава общего тега могли незаметно расширить набор отправителей.
- В коммите `fd313e2c4` ручная форма использует тег только как фильтр и сохраняет точный `email_list`; API блокирует tag-only/пустой selector и удаляет `email_tag_list` при наличии точного списка.
- Создание пустой кампании из импорта базы сохранено: запрос без `email_list` и `email_tag_list` проходит без изменения.

## Проверка

- ESLint изменённых файлов — успешно.
- TypeScript strict — успешно с увеличенным лимитом памяти Node.
- Пять локальных проверок нормализации sender scope — успешно.
- Отдельная сборка изменённых API/UI entrypoints через esbuild — успешно.

## Открытый вопрос

Существующие live-кампании другого клиента всё ещё требуют отдельной точечной перенастройки sender scope после определения предназначенных им ящиков и явного разрешения на production-запись.
