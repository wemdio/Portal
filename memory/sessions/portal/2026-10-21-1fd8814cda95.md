Пользователь сообщил health alert Точки в режиме recent: «залито 6, неполная синхронизация ... RuntimeError» дважды. Read-only live logs подтвердили запуск 21.10.2026 12:00 МСК, завершение 12:02:39, для двух счетов «Банк не подготовил выписку за отведённое время». Предыдущие короткие прогоны до 11:50 включительно успешны, Т-Банк и USDT в 12:00 успешны. По старому коду нельзя различить Pending при HTTP 200 и временные не-200 при poll: оба заканчиваются одинаковым текстом. Это не доказательство сбоя авторизации или конкретного HTTP-кода.

Read-only GET balances доступен; он перечисляет 4 доступных счета Точки, тогда как прежний подсчёт по выручке за 90 дней видел только 2 счета с клиентскими поступлениями. Не смешивать полный список счетов и счета с оплатами в выбранном периоде. GET списка выписок /accounts/{account}/statements вернул 501 на всех четырёх счетах; историю состояний получить таким способом не удалось. Новых POST-выписок для диагностики не делали. Не считать этот 501 причиной прежнего сбоя: основной синк использует POST /statements и GET по конкретному statementId.

Локальная правка bank_tochka.py: контролируемый TochkaStatementError сохраняется в итоговом алерте с индексом счёта; неизвестные исключения остаются только именами класса. Poll после исчерпания сообщает последний HTTP-ответ и короткий status/отсутствие выписки. Получение с HTTP 401/403 прерывается сразу. Тело ответа, URL, токен и полные номера счетов не добавляются. Расписание, длительность ожидания, классификация, дедуп и production-код не менялись; улучшение диагностики не является доказанным устранением банковской задержки.

Проверка: 240 existing Python tests passed; временный offline harness проверил Pending/503, auth fail-fast, отказ создания, переход в Ready, изоляцию ошибок, сохранение частичного результата и отсутствие произвольных исключений в итоговом алерте.
