По жалобе на поиск проекта в персонализированных ответах read-only Portal DB подтвердил: project e4077814-d6ad-4724-b4c7-a1e1478689bc имеет статус «На паузе», specialist_user_id заполнен. Корень проблемы: listVisibleProjects в app/src/lib/replyPersonalization/db.ts отбирал только В работе / Тестирование / Подготовка, поэтому клиентский поиск по уже полученному списку не мог найти паузу. Написание названия и права назначенного специалиста не были причиной.

В dmitriy_kuladmed_new добавлена «На паузе» в список доступных статусов только для персонализированных ответов. Фильтр specialist_user_id для неруководителей, роли руководителей и исключение завершённых/отменённых сохранены. Код не меняет статус проекта и не возобновляет кампании. Общий /api/instantly/my-projects не менялся; комментарий о полном совпадении критериев заменён.

Временный offline harness app/.next/cache/check-reply-paused-projects.mjs вызывает реальную listVisibleProjects с локальным query-builder double, воспроизводит отсутствие paused на старом HEAD и присутствие в исправлении, проверяет ownership и admin/director/lead/manager, unknown-role, активные/подготовку/тестирование и поиск по имени. Ни сети, ни записи в БД. Scoped TypeScript для изменённого db.ts прошёл. Общий core typecheck не прошёл из-за существующего в HEAD WarmupSettingsPanel.tsx:67 (не импортирован WarmupParamKey); этот чужой файл не менялся. Постоянные тесты не добавлены.

Исправление локально, без push/deploy/production mutations. Для применения на сайте нужна обычная согласованная выкладка. Push требует отдельного подтверждения.
