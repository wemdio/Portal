## Коррекция пользователя

Теги `неименные …` обозначают общий резерв почтовых ящиков, а не отдельный проект. При временной выдаче ящика проекту на него добавляют второй, проектный тег; кампании проекта должны использовать именно этот второй тег. Это уточняет и исправляет слишком жёсткий вывод сессии `2026-09-21-acf69f9461a0`, где все динамические теги были заменены фиксированным списком ящиков.

## Проверенные факты

- В live Instantly обнаружены два резервных тега: `неименные почты` и `неименные maildoso`.
- Ящик может одновременно сохранять резервный тег и иметь второй тег текущего проекта.
- Динамическая выборка по проектному тегу нужна для ротации временно занятых ящиков; фиксированный `email_list` не является общей заменой этой модели.

## Исправление

Коммит `b9d2d8041` восстанавливает динамический `email_tag_list` для одного проектного тега, скрывает теги `неименные …` в ручной форме и повторно блокирует их по имени в API. Кампания может использовать либо один проектный тег, либо явный список ящиков, но не оба одновременно. Создание пустой кампании для импорта базы сохранено.

## Проверка

ESLint, строгий TypeScript, сборка изменённых API/UI entrypoints и десять локальных проверок sender-scope/pool-tag прошли.

## Остаток

Существующие кампании «Вороной», настроенные на резервный тег, требуют второго проектного тега и отдельной точечной production-коррекции; текущая запись не разрешает такую мутацию.
