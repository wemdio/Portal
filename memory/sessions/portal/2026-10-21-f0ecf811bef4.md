User correction 2026-10-21: remove the Sender Statistics switch between campaign letters and all mailbox traffic. Statistics must always cover Sender campaigns for the selected period, whether running, paused or completed, with single-campaign, RU/EN aggregate and all-campaign selections retained.

Removed the scope UI/state/type and scope query parameters from StatsTab, BounceCodes and the sender client API. Both statistics routes now always send p_only_linked=true, including bounce counts and detail rows; a legacy scope=all query cannot widen the report. Existing SQL has no campaign-status filter, so paused/completed historical campaigns remain counted. The earlier RU/EN migration remains pending; this correction needs no additional migration.

Validation: ESLint and TypeScript 7 core/API projects passed. Temporary API/client checks verified forced linked-only arguments even with scope=all and omission of scope from generated URLs. Local PGlite checks verified exclusion of unattached mailbox bounces from global linked-only statistics and preserved metrics after campaign statuses changed to done/paused. The previous 12-combination baseline and RU/EN filtering scenarios still pass. A local browser render of the real StatsTab with synthetic data confirmed that the switch is absent and period/campaign controls remain.
