# Honest Base Constructor phases and resilient status polling

Request: after validation appeared stuck at 99% for an hour, show the actual stage and progress without changing processing; commit/push to Sergey, no deployment.

Implementation in constructor-retry-resume worktree, based on Sergey `5b3f9e1a3`:
- Optional display-only detail argument on ProgressFn. Validation emits first-pass counts, greylist wait, and retry-pass counts. Worker stores a small step_progress snapshot inside existing result_stats, clears it at every step/attempt, and reports saving separately. No migration. Numeric progress and its <100-until-durable guard remain unchanged for resume/reapers/automations.
- UI labels the current step explicitly instead of presenting overall percentage as a time estimate. Retry/checking counts refer to the current pass (including remaining work after resume). Legacy worker at 99% gets an honest non-specific explanation, not invented counters. No SMTP limits, retries, concurrency, classification, filtering, checkpoint or billing changes.
- Status polling is single-flight, starts immediately, bounds the whole auth+request+JSON operation to 20 seconds, retries after failures, and refreshes on focus/visibility/online. Cleanup and expired requests cannot publish late snapshots. An error and last successful receipt time are visible; manual refresh does not restart processing. Completed preview fetch is separate and guarded on navigation.
