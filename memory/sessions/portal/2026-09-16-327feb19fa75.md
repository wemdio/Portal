Follow-up to sessions/portal/2026-09-16-c8a934b0f4b6.md. User authorized fixing remaining company/website/phone extraction errors. Implemented in the existing task worktree (detached HEAD tracking Sergey), based on 90905880d; unrelated root engSPF changes untouched. No production data updates, replay, migration, deployment or messages.

- Shared website validation now requires a recognised ICANN suffix via pinned tldts 7.0.30 (already present as a dev transitive package, now explicit runtime dependency). Rejects locations parsed as IDNs and glued Cyrillic tails, free/disposable mail domains, chat/shortener/tracking/service URLs; retains genuine IDNs and hosted subdomains. No DNS/network calls added, so syntactic validation is not a guarantee that an otherwise valid domain belongs to the company or resolves.
- Insert spaces around HTML anchors to avoid merging adjacent websites/visible text. Read-only source check confirmed the furniture-company example contains two adjacent anchors, the first showing only https://. Checked the exact layout with synthetic domains. Does not guess how to split an already malformed scalar imported from another source.
- Signature company extraction accepts labels without a colon, ТОО, a shop label, and a quoted legal entity at the end of a job title across up to three lines. Markdown emphasis on label values removed. History boundaries, source campaign/email isolation, uploaded metadata precedence and no-invention behavior retained.
- Shared phone parser keeps explicit extensions (including доп./внутр./ext) and trailing parenthesized extension after a full Russian number; collects multiple signature phones, deduplicates domestic/international Russian notation and prefers extension over bare switchboard duplicates. Whole-number cap prevents clipping a number/extension at 200 chars. Dates, time ranges, tax-ID context, quotes and unrelated sources remain excluded.
