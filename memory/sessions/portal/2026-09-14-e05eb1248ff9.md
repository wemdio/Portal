## Result

User reported another specialist's lead inserted between a lead and its handoff card. Root cause: notification and handoff drafting run independently. Code now starts both preparations concurrently and batches ready Telegram sends by chat + qualification ID in the single Instantly worker.

Configured handoffs wait at most 10 seconds outside the chat send queue. Late generation leaves a status note and subsequently replies to the persisted lead-alert message. No-config leads do not wait. Failed parent sends suppress the child. Durable notification/outbox recovery remains; the process-local pair buffer is not durable or a distributed lock. Before adding worker replicas, distributed dispatch is required. Other humans/bots can still interleave messages.

Verified: 213 suites / 2402 tests; strict types; ESLint; worker build; private transport harness for pairing, concurrency, timeout, late reply, failures and queue recovery. No deployment, migrations, external test emails or historical replay. Existing worker test changed from preparation invocation ordering to qualification-ID pairing; no new permanent tests.
