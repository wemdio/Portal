Запрос: повторная жалоба специалистов — ручные базы невозможно найти после автоматических сборов вертикалей.

Проверенная причина на codex/ve2-preview-recovery-scale, исходный HEAD 3cba6f307: GET /api/tools/base-constructor выбирал последние 20 задач пользователя без фильтра workload_origin; UI не имел поиска и страниц. Исправление ручной квоты не разделяло историю.

Изменение: по умолчанию выдаются manual и legacy NULL; automation доступна отдельной вкладкой. Фильтры владельца, источника и регистронезависимого поиска имени применяются на сервере до пагинации по 20 записей. Добавлены общее число результатов, переход между страницами, состояния загрузки/ошибки и защита от устаревших ответов. Счётчик активных ручных задач остаётся независимым от фильтров. CSV можно скачать из строки истории с названием исходного файла. Задания, результаты, правила обработки и очереди не изменялись; миграций нет.

Проверка: 213 suites / 2405 tests, 28.4 секунды; существующий тест API метаданных усилен проверками прав, ручного/автоматического источника, второй страницы, экранирования подчёркивания/процента и неверных параметров. Число тестов не увеличено. TypeScript прошёл; ESLint изменённых файлов без ошибок. Локальный браузерный стенд с реальным компонентом и синтетической историей: исходные загрузки, вторая страница, поиск старых файлов, отдельная автоматическая вкладка, задержанный ответ и восстановление после ошибки проверены. Native download event в in-app браузере не подтвердился; серверная CSV-выгрузка покрыта существующими тестами. Read-only production metadata подтвердили, что ручные записи сохранены независимо от списка последних 20.

Граница: эта задача разрешает исправление и push в Sergey. Новый merge test/main и deployment пока не выполнялись. Старый выпуск ручной квоты — отдельная завершённая задача.
