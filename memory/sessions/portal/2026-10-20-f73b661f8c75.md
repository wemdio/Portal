Запрос: при заполнении TG-профиля скрывать номер и заменять старую историю фотографий новым фото менеджера.

В codex/tg-profile-privacy-photos (база e70fda0a5) общий applyProfile проверяет приватность телефона и ставит «Никто» без разрешающих исключений. Уже скрытый номер не перезаписывает. Это покрывает одиночное, массовое сохранение и очередь кампании.

При наличии avatar собирается полный снимок старых фото с пагинацией плюс fallbackPhoto; удаление выполняется пакетами только после подтверждения установки нового Api.Photo. ID нового фото дополнительно исключается. Сбой очистки возвращает отдельное предупреждение, чтобы API сохранил новую аватарку и срок отлёжки; оба интерфейса показывают предупреждение. Без avatar фотографии не затрагиваются.

Проверки: TypeScript fast — успешно; ESLint — без ошибок, два существующих предупреждения страницы; одноразовый offline harness — скрытый/открытый номер, разрешающие исключения, очередь, 205 фото и fallback, сбои загрузки и очистки, неполное подтверждение удаления. Постоянные тесты не добавлены. Веточный прогон: 32 набора / 272 теста прошли, 4 набора / 19 проверок упали в незатронутых файлах (CRLF SQL fixture, EPERM удаления временных каталогов, Unix-путь esbuild на Windows); 2 skipped. Все четыре упавших тестовых файла совпадают с HEAD.

Проверки выполнялись без подключения к Telegram/production. Настройки начнут действовать после отдельного релиза и сохранения профиля оператором. Helper памяти в этой Windows-сессии запускался через временный адаптер fcntl.flock -> msvcrt.locking; сам skill не менялся.
