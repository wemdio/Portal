# Cross-mailbox conversation ownership fix

User authorized implementation after the Sep15 wrong-specialist diagnosis. Base is origin/Sergey 86e7c1039 in the task worktree ssh-recovery-sergey-20260909. No deployment, mailbox settings changes, DB writes or notification replay performed.

replyOwnershipResolver now checks a strict cross-mailbox conversation proof before mailbox mappings can override the provider campaign. Requires explicit outbound id/campaign/type, exact full thread id (not the relaxed stable suffix), valid earlier timestamp, consistent outbound from/eaccount, actual outbound To matching reply sender or provider lead identity, and the full normalized outbound body of at least 80 characters contained in the reply. All available context sends are checked, not only the most recent follow-up. Competing proven campaign owners or unknown ownership fail closed. This path does not add Instantly API calls. Generic quote lines or a thread id alone do not enable it.

The worker recognizes conversationVerified separately from mailboxVerified, so a proven cross-mailbox reply is not then rejected by the ordinary receiving-mailbox guard. Existing To/CC and client-party checks remain. Recovery source snapshots now retain the input campaign rather than the derived/corrected campaign; outcome campaign and qualified project remain separate. Reason and matched outbound id are logged.

Limits: this fixes the verified full-quote cross-mailbox scenario, not every possible transport alias. Unproven cases retain existing guarded resolution/recovery.
