Запрос: закончить исправления выгрузки B2B-поиска после инцидента с повторными скачиваниями.

Подтверждено по исходному коду: каждый POST заново искал строки и списывал лимит до генерации файла. Повтор XLSX и CSV могли съедать лимит на один набор. HTTP 200 не доказывает успешное сохранение браузером; точную причину конкретного клиентского сбоя XLSX не установили.

В ветке codex/companies-export-reliability подготовлены сохранённые XLSX/CSV в MAIN S3, повтор по фильтрам/ключу без нового списания, транзакционный commit ledger + seen, история последних 10 файлов, отдельное действие новой выгрузки. Старые записи без storage_prefix не получают файлы задним числом. Нужна миграция 20261016_0001_companies_search_saved_exports.sql. Production не изменён.

Важная ошибка выбора ОКВЭД: сокращённое поиском дерево нельзя использовать как полный узел выбора. Его предки добавляли широкие префиксы. Исправленный клиентский выбор помечает предков навигационными, выбирает только совпавшие ветки, при снятии дочернего кода убирает покрывающий префикс и сохраняет остальные ветки. Старые фильтры не переписываются по предположению об исходном намерении.

Проверки: PGlite с настоящим SQL RPC (повтор, квота, изоляция, откат seen, grants), API с заменами внешних сервисов (одновременные форматы, ошибки поиска/генерации/загрузки, потеря ответа после commit), сравнение всех полей 9952 синтетических строк XLSX/CSV, реальный каталог ОКВЭД, Chromium desktop/mobile, 54 существующих теста, TypeScript API/страниц. ESLint без ошибок; остался прежний warning восстановления фильтров из localStorage в эффекте. Новые файлы тестов в репозиторий не добавлялись.

Следующий этап: штатный выпуск миграции и приложения через Tasks. При неизвестном исходе commit файлы намеренно не удаляются, чтобы не потерять уже оплаченную выгрузку; orphan cleanup и общая межинструментальная блокировка лимитов не входят в изменение.
