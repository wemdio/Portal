# Запрос

Исправить кнопку «Попробовать снова» в конструкторе баз для специалистов: продолжать ту же задачу с сохранённого места; коммит и пуш именно в `Sergey`. Production-деплой этим запросом не разрешён.

# Проверенное изменение

- Раньше кнопка вызывала `resetForm` без API, очищая форму. Добавлен PATCH `{action: "retry", failed_at}`: только сотрудник-владелец ручной failed-задачи (legacy NULL origin допускается как в истории).
- Обновляются только status=pending, error_message, completed_at и новый run_token. data, checkpoint-колонки, step_config, selected_steps, current_step/progress, result_stats и ID сохраняются. Worker claim переводит pending в processing до чтения runner: существующая resume-логика пропускает завершённые шаги.
- CAS по failed/status, владельцу, manual/NULL origin, предыдущему run_token и времени ошибки защищает от двух вкладок и устаревшей карточки. Токен меняется сразу при возврате в очередь, чтобы отложенный результат старого worker не перезаписал восстановленную задачу. Уже pending/processing возвращается без новой записи.
- Проверяются лимит активных ручных баз и наличие корректной точки восстановления; завершённые/отменённые задачи не возобновляются. Автоматические задачи и клиентский тарифный контур намеренно не менялись.
- UI защищён от повторного клика, устаревшего ответа после выбора другой базы, сетевой ошибки и зависшего запроса (20 секунд). Сброс вынесен в отдельную кнопку «Загрузить другую базу»; продолжение ставится в очередь, не исполняется в HTTP-процессе.

# Проверки и границы

- Существующий тест mid-step resume расширен сценариями CAS, доступа, квоты, старой ошибки, сохранения данных/config и старта с нужного шага; новые тестовые файлы/it-блоки не добавлены.
- Весь существующий Jest-набор: 297 suites, 3324 passed, 2 skipped, около 115 секунд. TypeScript 5: core/API/pages/tests без ошибок. Линтер: только шесть ранее существовавших предупреждений в UI, ошибок нет.
- Локальный UI-only браузер с перехваченными API: двойной клик отправил один PATCH; ответ по базе A не переключил экран с B; 503 показал ошибку и разблокировал кнопку; успешный повтор открыл сохранённый прогресс. Реальные задачи не использовались.
- Исходная база ветки: `077bb9302` (origin/Sergey); во время проверки Sergey дополнен несвязанными landing-коммитами, их требуется сохранить при fast-forward push. Эти сведения относятся к коду, не подтверждают production-деплой.
