После инцидента с неправильным адресатом fallback-ответа добавлен второй независимый барьер перед `POST /emails/test`: сравнение явного адресата с адресом автора входящего письма. При невозможности определить автора или расхождении отправка блокируется, событие `client.campaign.replies.reply.recipient_blocked` пишется в `application_logs`. Аудит успешной отправки сохраняет фактический явный `to_email`, `sender_email` и provider `lead` отдельно, чтобы монитор не полагался на одно поле приложения.

Health-бот читает `application_logs` за 24 часа и ежедневно в 21:00 МСК отправляет в существующий health-чат числа успешных ответов, fallback-отправок, отказов, заблокированных адресатов, несовпадений фактического To с From и старых записей без обоих адресов. Для последних выводится «непроверяемо», а не «успешно». Красный/оранжевый отчёт приходит даже при mute обычных уведомлений. На read-only production запросе 28.09 обнаружены 2 сегодняшние старые fallback-записи без адресных полей; новая проверка классифицирует их как непроверяемые, не выдавая ложного подтверждения. Тело писем в отчёт не попадает.

Проверки: SQL обоих запросов выполнен read-only на основной БД; Python `py_compile`; 23 существующих unittest health-check; ручной вызов форматирования с подменёнными соединением и Telegram; строгий TypeScript и ESLint изменённого API. Изменения не активны до релиза. CI собирает образ `portal-health-check:prod` только на `main` при изменении `services/health-check/`; одного пуша в Sergey недостаточно.
