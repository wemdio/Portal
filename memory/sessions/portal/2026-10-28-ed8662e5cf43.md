## Реализация первых двух пунктов

В `Sergey` добавлена цепочка для успешных пустых/JS-shell страниц ENG: HTTP → отдельный Chromium → необязательный TinyFetch. Интеграция затрагивает company-evidence чтение для квалификации и ENG contact-first поиск опубликованной почты. RU и пути без opt-in сохраняют прежнее поведение. При включении нового режима ENG не повторяет 403/429 через прежние прокси; ошибки доступа, чужой домен, неизвестные ответы и опасные адреса терминальны. HTML заменяется только при улучшении, исходные буквальные адреса не теряются. `readMethod` сохраняется в диагностике, evidence, checkpoint и audit.

Браузерный runner не имеет сети (`network_mode:none`) и секретов; отдельный broker передаёт проверенные байты через UDS с DNS-проверяющим dispatcher, ручными redirect и ограничениями ресурсов/времени. Глобально одна сессия без очереди, лишние запросы получают busy. TinyFetch имеет атомарный Postgres budget (800/rolling24h,120/minute), timeout/cap и no-retry. Он требует отдельной конфигурации и подтверждённых условий провайдера; один флаг не доказывает бесплатность или отсутствие обхода защиты. Оба reader выключены по умолчанию, миграция не применялась, production не изменялся.

## Проверки

- Штатный TS7 core typecheck и ESLint: успешно. Веточный выбор тестов:63 suites,589 passed,2 skipped,~23с; постоянные тесты не добавлены.
- Локальные controlled smoke: цепочка TinyFish, сохранение email/evidence provenance, отказы403/429/challenge/private/own IP, wrong-domain redirect до fallback, отмена, сохранение исходного текста, лимиты и кодировки. Бюджетная миграция проверена в PGlite.
- Временная ARM64 Ubuntu VM (Lima/VZ, rootless Docker, без host-home mount/secrets/client data): оба образа собраны; Chromium с sandbox отрисовал публичную JS-страницу quotes.toscrape.com/js/. Runner имеет только loopback, прямой TCP даёт ENETUNREACH. Проверены auth, private/metadata/own IP, реальные403/429, concurrency1+busy и повтор после отмены.
- Обнаружен и исправлен реальный Linux startup blocker: при cap_drop ALL официальный seccomp условно запрещал chroot, нужный Chromium внутри user namespace. Добавлен только syscall chroot к профилю, без capability/privileged/network доступа. Linux runtime после этого успешен.
- Публичный fixture вредоносного redirect в VM сам вернул403; реальный сетевой redirect таким тестом не подтверждён. Его отказ до второго запроса проверен controlled smoke. Полная проверка всех атак/production нагрузки не заявляется; конфигурацию целевого production-хоста проверить перед включением.
