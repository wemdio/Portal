Пользователь попросил после диагностики [[2026-09-24-e4e7227b187f]] добавить углубление поиска только для открывающихся сайтов без найденной почты, до 10 страниц суммарно (не 12).

Ветка codex/constructor-email-deeper-scan от origin/main 81eb21500739184dbc6cb544754dce938e58d5c0. В scrapeEmails добавлена opt-in emptyResultMaxPages: при исчерпании исходного лимита продолжается тот же список кандидатов, только если хотя бы одна страница дала HTML и ни одного пригодного email не найдено. Уже проверенные URL не запрашиваются повторно. Ранний выход после найденной почты, отмена и таймаут сайта сохраняются.

stepFindEmails включает 5→10 только при отсутствии явного maxPages. Явные бюджеты автоматических запусков, включая VE2 max_pages=4, сохраняются. Прочие прямые потребители scrapeEmails (включая «Работу с базами») без новой опции сохраняют прежний обход. Схема БД и production-данные не менялись; ранее завершённые запуски автоматически не перезапускаются.

Проверка: 33 проверки в двух существующих Jest-файлах прошли; ESLint четырёх изменённых TS-файлов, сборка baseConstructor/enrich через esbuild и tsc -p tsconfig.typecheck.core.json прошли. Расширены существующие сценарии (без новых тестовых файлов/it): находка на 6-й/10-й странице, строгий предел 10, отсутствие повторных запросов первых страниц, недоступный сайт без углубления, фильтр мусорных адресов, отсутствие углубления при уже найденном email и отключённом раннем выходе, сохранение явного 4-страничного бюджета. Реальное время массового запуска после изменения не замерялось.
