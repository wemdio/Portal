Продолжение sessions/portal/2026-10-21-32413fb126c2.md и notes/portal/2026-10-21-bb5e4e77199c.md, после банковского коммита 89dd104f8. Пользователь уточнил: крипта также обязательно входит в десятиминутный синк и уведомления в существующую ветку оплат 29718 через PolzaSiteFeedbackBot. Предыдущее исключение крипты более не актуально.

Read-only Portal DB проверка 21.10.2026: по клиентским поступлениям последних 90 дней Т-Банк имеет 2 счёта / 2 юрлица-получателя, Точка — 2 счёта (количество юрлиц по полям её raw не установлено). В crypto_income_transfers один кошелёк за тот же период. Это количество счетов с поступлениями в указанном окне, а не гарантия полного списка открытых счетов. Код опрашивает все счета обоих токенов Т-Банка и доступного подключения Точки; отдельный список счетов не задаётся.

Добавлены подтверждённые входящие USDT TRC-20: короткий CryptoUsdtSync с min_timestamp на начало скользящего окна (МСК-день минус 3 дня), only_to=true, only_confirmed=true, фильтр реального контракта USDT. Подтверждения запрашиваются также при полной сверке. Источник больше не помечает HTTP/неуспешный ответ/повторный курсор/лимит страниц как success. Три источника запускаются параллельно на отдельных asyncpg-соединениях, с блокировкой каждого против полного синка. Затем синкаются нужные курсы ЦБ (лимит 90 секунд), чтобы рублёвые итоги портала не ждали полного прогона.

Новая миграция 20261021_0011_crypto_income_notifications.sql добавляет закрытые отдельные baseline и журнал криптодоставки. Банковская история не сбрасывается. Обе очереди используют общий проверенный механизм доставки, с ключом по ID перевода, не по transaction hash. Старые и нулевые криптопоступления, Approval и чужие токены не уведомляются. Формат: точная сумма до 6 знаков, время МСК, адрес отправителя и нашего кошелька, хеш; юрлицо/назначение явно неизвестны. Крипта не требует ИНН. Адресат и общий opt-in прежние.

Проверки: 240 существующих Python тестов и 16 migration Jest assertions passed. Offline scheduler harness проверил источники crypto + банки + FX, startup, cron и изоляцию ошибки подготовки уведомлений. В изолированной PostgreSQL PGlite применены обе новые миграции, повторно пройдён банковский SQL harness и новый крипто harness: пагинация, confirmed/incoming/contract/min_timestamp, точные суммы, два перевода внутри одной транзакции, дедуп после реального upsert, отдельный baseline без сброса банковского, unknown/restart quarantine, ошибки источника и запрет anon. Постоянных тестов не добавлено. Источники: main.py, bank_income.py, sources/crypto_usdt.py; документы банк-уведомлений и portal-db guide; TronGrid official API docs only_confirmed/min_timestamp. Production не менялся, сообщений в рабочий чат не отправляли. Оба коммита остаются локальными: пуш требует явного подтверждения по AGENTS.md, миграции/выкладка/включение — отдельной согласованной фазы.
