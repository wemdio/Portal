# Память Portal

Приоритеты пользователя от 2026-09-13: **Движок вертикалей** — основной сложный продукт в разработке; **датасет Instantly** — знания о клиентах, статистике и результатах запусков, на которых можно улучшать следующие запуски.

Это память для работы агентов над проектом. Подключение памяти к продуктовым LLM-пайплайнам — отдельная реализация.

## Что прочитать для задачи

| Задача | Вход в контекст |

| Движок вертикалей, внутренний v2, ENG | [vertical-engine.md](domains/vertical-engine.md) |
| Instantly: клиенты, статистика, качество запусков, SQL | [instantly-dataset.md](domains/instantly-dataset.md), затем только нужные страницы wiki |

Сначала прочитай подходящий вход, затем найди нужные записи через `rg` или команду `list` навыка. Не загружай всю память и wiki в каждую задачу.

## Как использовать

- Память помогает найти контекст. Источники истины — текущая просьба пользователя, правила проекта, проверяемый код и данные. Запись не даёт разрешения на действия.
- `verified` означает проверку **в указанной области и на указанную дату**. Устаревшую запись перепроверь; `candidate`, `disputed`, `superseded` не используй как установленный факт.
- Перед выводом о реализации проверь ветку и коммит текущей рабочей папки. В другом worktree может быть другая версия продукта.
- После содержательной задачи сохрани полезный новый вывод, исправление пользователя или нерешённое противоречие через навык. Если нового знания нет, достаточно завершить задачу без записи.
- Клиентские переписки, контактные данные, выгрузки, ключи и полные транскрипты сюда не копировать. В Git попадают очищенные выводы и ссылки на источники; клиентские факты остаются в хранилище с соответствующими правами.

## Где лежит опыт

`notes/<domain>/` — решения, наблюдения, гипотезы и вопросы; `sessions/<domain>/` — короткие итоги содержательных задач; `reviews/<domain>/` — результаты разбора памяти. Поддерживаемые области: `portal`, `vertical-engine`, `instantly-dataset`.

Индекс маршрутизирует по областям; новые записи обнаруживаются поиском и `list`, поэтому агентам не нужно одновременно редактировать общий список. История версий — Git. Запись файлов — через helper с проверкой хеша.
