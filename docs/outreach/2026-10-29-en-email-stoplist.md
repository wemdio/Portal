# Исключение адресов сторонних баз из автоаутрича EN

29.10.2026 пользователь поручил исключить email-адреса из шести таблиц из
собственного английского автоаутрича. Запросов на согласование баз с Глебом
или на запуск этих таблиц в нашей рассылке не было. Исключаем именно адреса,
не домены, и только контур `polza_en`.

## Источники

Все листы проверены по заголовкам, адреса взяты из явных колонок Email,
work_email, personal_email. Колонки с текстами писем, профилями и ссылками
не использовались для поиска адресов. Листы без email-колонок не добавляют
домены в исключения. Отметка «запустил» не ограничивает исключение: владелец
попросил убрать адреса из всех перечисленных баз.

## Постоянный список для будущих запусков — код требует выкладки

Эти же 26 603 адреса сохранены JSON-массивом строк в
`polza_outreach_settings`, ключ `blocked_emails`. Это отдельная настройка EN,
общий `sender_suppressions` не менялся. Для дополнения списка нужно объединять
адреса с существующим массивом, а не затирать предыдущие исключения.

Новый `loadEnEmailStopList` читает настройку один раз на запуск/импорт:

1. EN-раннер исключает закрытые адреса на S5, оставляя другие разрешённые
   адреса той же компании.
2. `sender.importRecipients` повторяет проверку для `source_kind=polza_en`,
   включая базы, собранные до добавления адреса в список. Проверка идёт до
   любых записей или замены базы. Счётчик исключений учитывает только входные адреса.
3. Нет настройки — пустой дополнительный список для совместимости. Сбой
   чтения или повреждённый массив — ошибка, а не разрешение отправить.
4. RU, ручные кампании и VE2 не читают EN-настройку. Их существующие общие,
   клиентские и проектные стоп-листы продолжают применяться.

Старая версия production ещё не читает `blocked_emails`: уже выполненные
исключения защищают текущие 20 кампаний. Для автоматической защиты новых
EN-кампаний необходимо выложить код через `test` → `main` обычным порядком.
Миграций, новых сервисов или дополнительных платных обращений к API нет.

## Проверка кода

Временный локальный harness исполнил реальный загрузчик, `importRecipients`
и S5-цикл раннера: список из 26 603 адресов, нормализация, дубли, повреждённые
данные, ошибки чтения, запрет замены базы до сверки, изоляция RU/manual/VE2,
сохранение общего стоп-листа и корректные счётчики исключений.
37 существующих проверок senderHardening и VE2 senderTransport прошли.
Новых постоянных тестов не добавляли.
