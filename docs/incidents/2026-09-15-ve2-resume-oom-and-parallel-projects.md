## Исправление

- Один процесс VE2 обслуживает до двух разных проектов одновременно;
  `VE_JOB_CONCURRENCY=1` возвращает последовательный режим. Внутри проекта
  одновременно выполняется одна основная задача, включая финализацию и учёт
  расходов. FIFO по времени готовности сохраняется между доступными проектами.
- Сигнал отмены LLM хранится в `AsyncLocalStorage` каждой задачи. Отмена
  проекта не прерывает запрос модели соседнего проекта. Учёт провайдеров уже
  использовал отдельный async-контекст.
- Остановка прекращает новые запуски и ждёт активные задачи с существующими
  правилами checkpoint/grace period. Это один процесс: аварийное завершение
  процесса затрагивает оба проекта, восстановление использует сохранённые
  состояния. Запуск нескольких контейнеров этой правкой **не** поддерживается:
  startup recovery сейчас сбрасывает все `running` задачи.
- Координатор раз в 10 секунд читает лёгкую проекцию состояния базы, а не
  полный `collect_info` с кандидатами и доказательствами. Возобновление базы
  повторно использует уже загруженный snapshot вместо повторной десериализации
  ответа UPDATE.
- До сохранения задачи сохраняется явное намерение пользователя продолжить.
  Если collecting-база обновлена после завершения предыдущей `done`-задачи,
  координатор восстанавливает отсутствующую задачу из сохранённой базы.
  Существующий дедуп не создаёт повторную активную задачу. `failed`/`cancelled`
  автоматически не повторяются; для них требуется явное продолжение.
- Compose: VE2 worker 2 GiB RAM, V8 old space 1536 MiB, CPU 1.0, прежние
  5 минут stop grace. Изменения относятся только к VE2, не к ENG/he_*.
- На присланном пользователем экране верхняя карточка читала ошибку подготовки,
  а строка превью рисовала spinner только по `base.status=collecting` и старому
  флагу `relevance_review_requested`. Теперь обе используют один расчёт статуса
  подготовки. Остановка и очередь не рисуют spinner. Старый snapshot дочерней
  проверки без активной задачи не считается признаком выполняющейся работы.
  Ошибка прерванного продолжения объяснена обычным текстом, кнопка продолжения
  находится в карточке ошибки даже при оставшемся `collecting` у базы.
  Нажатие оставляет пользователя на шаге базы. Готовая часть доступна для
  просмотра и скачивания, подсказка больше не утверждает, что остальная база
  обязательно собирается прямо сейчас. Общий статус применяется также к
  остановленному разбору и к повтору, который уже в очереди, хотя база ещё
  хранит `failed`. В автоаутриче используется одна кнопка продолжения подготовки;
  отдельная кнопка проверки базы остаётся в самостоятельном инструменте.
