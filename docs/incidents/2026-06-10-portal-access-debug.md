# 10.06.2026 — «многие не могут зайти на портал, с VPN и без»

Разбор жалоб + что починено вживую на 139 (без редеплоя). Итог: единой тотальной
поломки не было — сервер, DNS, сертификаты, auth и доступность из RU исправны;
нашли и сняли три класса деградаций, бивших по отдельным пользователям, плюс
осталась внешняя гипотеза (блокировки у части операторов).

## Что проверили и исключили

- nginx/порты/сертификаты (до VIII–IX.2026), диск 9%, RAM ok, conntrack 2k/262k,
  fail2ban/ipset нет, часы 139↔144 синхронны (timesync-cron жив, скачков в
  access.log нет — проверено сканом 400k записей).
- `/login` 200 за ~40мс, цепочка `/` → `/login` ок на обоих доменах; темп логинов
  в `auth.audit_log_entries` обычный; трафик и уникальные IP в норме.
- Доступность из RU: TCP:443 и полный HTTPS-запрос — 200 OK с 4 точек
  (Москва ×2, СПб, Екб, check-host.net). DNS чистый (A верные, AAAA нет,
  Яндекс-резолвер ок). Хостер: HOSTKEY-USA, AS395839.
- Деплой-окна 09:13 и 15:21–15:24 (+0200) дали лишь по ~3–5 минут 502/просадки.

## Не закрыто / для дальнейшей работы

1. **Блокировки у части операторов (ТСПУ)** — главная гипотеза для кейсов
   «совсем не открывается». С датацентровых RU-точек всё ок, но домашние/мобильные
   сети так не проверить. У жалующихся собрать: оператор, город, скрин ошибки
   (таймаут = блокировка, ошибка/спиннер = баг), тест с мобильного интернета
   другого оператора. Если подтвердится — запасной IP из другого блока у HOSTKEY
   или реверс-прокси на RU-доступном VPS.
2. **Хронические 404 на `/rest/v1/project_periods` / `project_contacts_history`**
   (~150/день, минимум с 05.06). Таблицы существуют; anon → 200/401 (permission
   denied на contacts_history — GRANT забыт?), service → 200. 404 видимо
   роль/JWT-зависимые — нужен app-side разбор, клиентская аналитика проектов
   частично не грузится.
3. **PostgREST перечитывает schema cache каждые ~15 секунд** (лог main-rest) —
   event-trigger из `20260525_0001_pgrst_auto_reload_event_trigger.sql` похоже
   срабатывает на каждый DDL вкл. temp-таблицы. Дёшево, но шумно — стоит
   отфильтровать в триггере.
4. **Server Actions после деплоя**: открытые вкладки со старым билдом получают
   `Failed to find Server Action` до жёсткого рефреша. Идея: тост «вышла новая
   версия, обновите страницу» или сохранение старых build-артефактов.
5. `main-storage` и `instantly-postgrest-prod` на 144 — `unhealthy` 5 недель
   (хронически, на портал видимого влияния нет — разобраться при случае).
6. Креды root от 139/144 светились в чате — **сменить пароли / перейти на ключи**.
