# VE2: готовый каталог Яндекс Карт и формат проверки релевантности

## Причины

Две недавние подготовки (лифтовые сервисные компании и стройматериалы B2B)
содержали `yandex_maps_jobs.config.search_urls`, без `catalog_filters`.
VE2 отправлял источник `yandex_maps` в живой парсер, хотя Portal уже использует
готовый `yandex_maps_company_catalog`. Ошибка проверки прокси относилась к
этому неверному пути, а не к доступности готового каталога.

В журнале проверки цитат повторялись ошибки схемы: отсутствующий `abstain`
и лишние ключи. Классификация имела нативную JSON-схему для gpt-4o-mini,
но независимая проверка и исправление цитат на gpt-5-mini использовали только
JSON mode. Маленький повреждённый пакет классификации мог остановить всю базу.

## Исправление

- Новые задачи VE2 читают готовый каталог через существующий read-only RPC
  `yandex_maps_catalog_search`. Живой парсер, proxy и новые дочерние задачи
  Яндекс Карт не используются. Завершённые старые дочерние задачи по-прежнему
  можно прочитать; их данные не удаляются.
- Свободные запросы старого плана сопоставляются с реальными рубриками и
  географией каталога. Точные совпадения не требуют ИИ. Для остальных модель
  получает словарные варианты с явными ID; локальная схема проверяет выбор.
  Пустые рубрики/неизвестное место не превращаются в выборку всего каталога.
- Рубрики сохраняются до чтения строк. Курсор и накопленные строки сохраняются
  вместе после каждой страницы; один тик читает не более четырёх страниц.
  Следующая партия продолжает курсор, исключает уже использованные компании
  и проходит обычные проверки релевантности и email.
- Явное продолжение упавшего превью повторно использует ту же базу и переводит
  неудачный источник Яндекс Карт на каталог, сохраняя ID прежнего парсера.
  Это не возобновляет остановленные старые подготовки и не включает автодобор.
- Проверка релевантности и выбор цитат передают нативную строгую JSON-схему
  для настроенных OpenAI gpt-4o-mini/gpt-5-mini. У других провайдеров сохранён
  JSON mode с той же локальной валидацией.
- Исправление цитат возвращает только `evidence_ids`; пустой массив означает
  отсутствие подтверждения. Допуск всё ещё требует точных цитат и независимого
  смыслового подтверждения. Старые оплаченные попытки и успешные решения
  не сбрасываются массово.
- Повреждённая классификация разбивается на малые пакеты, затем отдельные
  компании. Неисправимый ответ оставляет компанию в резерве; подтверждённые
  соседи продолжают работу. Четыре последовательных повреждённых одиночных
  ответа останавливают дальнейшие запросы, чтобы не оплачивать сбой на всей базе.

## Проверка

Существующие сценарии покрывают остановку между страницами, продолжение
с сохранённого курсора, отсутствие parser jobs, повторное использование ID базы,
точные/синонимичные рубрики и неизвестную географию, изоляцию неправильного
ответа, лимит повторов, недопуск недействительных citation IDs и повтор без оплаты.
Новых тестовых файлов и `it()` не добавлено.

Реальный ограниченный прогон Requesty и read-only RPC:

- «обслуживание лифтов / ремонт эскалаторов» → рубрика «Лифты»;
- строительные запросы → «Фасадные системы», «Кровельные материалы»,
  «Строительные смеси», «Теплоизоляционные материалы», «Стройматериалы оптом»;
- обе выборки: HTTP 200, по три строки (проверочный лимит);
- gpt-5-mini принял нативные схемы смысловой проверки и выбора цитат;
- первый пробный вариант с неявными индексами длинного списка выбрал неверные
  рубрики. До выпуска заменён на явные ID и ранжированный список; повтор прошёл.

Проверка API не изменяла базы/очереди/сервисы production и не запускала рассылку.
Общий кэш результатов компаний другого разработчика не изменён.
Выпуск кода и возобновление production-задач — отдельные действия.
