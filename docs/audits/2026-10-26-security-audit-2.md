# Аудит безопасности Portal №2 (26.10.2026)

Продолжение аудита `docs/audits/2026-10-24-security-and-unused.md`. В тот раз проверяли только код;

## 🔴 Подтверждено на проде — чинится на сервере (нужен доступ к 139)

1. **База Instantly открыта в интернет без пароля** (пункт 1 прошлого аудита, не исправлен).
   `http://139.60.162.24:35401/` отвечает без ключа: 48 таблиц и 29 функций, например
   `client_campaign_leads` — 50 530 строк. Анонимная роль — владелец базы, значит можно и
   менять/удалять (не проверяли). Закрыть — шаг A из `docs/runbooks/2026-10-24-security-urgent.md`:
   ```bash
   iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 35401 --ctdir ORIGINAL ! -s 172.16.0.0/12 -j DROP
   netfilter-persistent save
   ```
   Потом: `curl -m 5 http://139.60.162.24:35401/` снаружи — таймаут; экраны с данными Instantly работают.
   После смены анонимной роли — отозвать у PUBLIC/anon/authenticated функцию «любой SELECT»
   из `supabase/instantly-migrations/20260403_0001_agent_query_readonly.sql`.

2. **Вебхук LinkedIn (Unipile) принимает запросы без секрета.** `POST /api/tools/li-outreach/webhook`
   с битым телом отвечает `400 Invalid JSON` — значит `LI_OUTREACH_WEBHOOK_SECRET` на проде не задан,
   и поддельное «пришло сообщение» / «приняли заявку» обрабатывается от имени наших аккаунтов.
   Починка: сгенерировать секрет (`openssl rand -hex 24`), добавить `LI_OUTREACH_WEBHOOK_SECRET=…` в
   `/home/Portal/prod/.env`, в кабинете Unipile дописать к адресу вебхука `?secret=<он же>`, пересоздать
   портал (`docker compose -p portal -f docker-compose.prod.yml up -d --force-recreate --no-deps portal`).

3. **Порты, открытые в интернет:** 35401 (выше), 35432 и 35434 (Postgres, пароль есть, но перебор
   и открытый текст), 35480 (Kong основной базы по http, без TLS), 8081 (telegram-bot-api), 8090
   (atmos-bot). Закрыть тем же приёмом `DOCKER-USER`, оставив доступ из Docker и нужных хостов.

## 🟢 Проверено и в порядке

- Основная база с публичным ключом: `profiles`, `projects`, `tasks`, финансы, TG-аутрич, AMO — 401.
  Открыты намеренно: `companies_directory` (справочник), опубликованный регламент.
- RLS включён на всех 452 таблицах; все «открытые» правила для `authenticated` перекрыты
  ограничением `is_internal_staff()` (блокировка 15.10 держится); функции с повышенными правами
  проверяют вызывающего.
- Бакет `deploy-backups` (бэкапы `.env`) не публичный. Регистрация напрямую через Supabase выключена.
- Внутренние API закрыты от анонимов и клиентов (staff-гейт middleware); клиентский кабинет
  (128 маршрутов) проверяет владельца по каждому id; роль из браузера не поднять.
- SQL параметризован, фильтры PostgREST с клиентским вводом экранируются, XSS-вставок нет,
  открытых редиректов нет. HTTP → HTTPS работает, порт 3000 закрыт.
