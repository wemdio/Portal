# Аудит Portal: дыры в безопасности и неиспользуемый функционал

Дата: 24.10.2026. Проверка по коду репозитория (только чтение): 757 API-роутов, 142 страницы,
689 миграций, compose/CI/сервисы. На серверы и в базы не заходили — пункты с пометкой
**«проверить на проде»** зависят от настроек сервера, их видно только там.
Самые серьёзные находки перепроверены вручную по коду.

Главный фон для оценки: **регистрация в портале открыта** (RU без лимитов и подтверждения почты),
поэтому «любой вошедший» = фактически любой человек из интернета.

## Блок 1. Безопасность

### 🔴 Сейчас (срочно)

1. **База Instantly доступна без пароля из интернета (если порт открыт).**
   PostgREST базы Instantly опубликован на `0.0.0.0:35401`, а «анонимная» роль у него — владелец
   базы (`deploy/instantly-db/docker-compose.yml:61,73`). Без ключа можно читать, менять и удалять
   кампании, лиды, квалификации. Docker-порты обходят файрвол.
   → Закрыть порт (`127.0.0.1:35401`) или сменить анонимную роль. **Проверить на проде:**
   `curl http://139.60.162.24:35401/` снаружи.

2. **Ключ полного доступа к старому проекту Supabase лежит в git.**
   `app/scripts/migrate-instantly-to-new-db.mjs:27`, `app/scripts/export-prod-transcripts.mjs:7` —
   service_role ключ проекта `whhkkmfcmstawodnghzw` (действует до 2035). Локальный `.env` до сих пор
   смотрит в этот проект — скорее всего, он жив и хранит старую копию данных.
   → Удалить проект или сменить его JWT-секрет; убрать ключ из скриптов.

3. **Telegram-агент: можно выдать себя за админа и выполнять SQL по всей базе.**
   Вебхук агента проверяет подпись Telegram только при `TELEGRAM_WEBHOOK_SECRET_ENFORCED=1`
   (`app/src/lib/telegram/webhookSecret.ts:43`), а пользователя определяет по `from.id` из тела
   запроса. Зная Telegram-ID админа (не секрет), можно отправить поддельный запрос — агент выполнит
   SQL с правами сервиса и ответит злоумышленнику. Сам «read-only» SQL обходится (нет режима только
   чтения, фильтр по словам).
   → Включить флаг на проде (сначала перерегистрировать вебхук), позже — сделать проверку обязательной.

4. **Сброс пароля меняет пароль сразу, без подтверждения.**
   `app/src/app/api/auth/forgot-password/route.ts:181`: зная почту сотрудника или админа, можно раз
   в минуту сбрасывать ему пароль — человек не сможет войти. Новый пароль уходит письмом открытым текстом.
   → Перейти на ссылку подтверждения сброса (пароль меняется только после клика).

5. **Новая таблица отчётов TG-аутрича открыта любому вошедшему.**
   `supabase/migrations/20261022_0040_tg_outreach_reports.sql:25-33` — `using (true)` для
   `authenticated`: контакты, диалоги и передачи лидов по всем кампаниям. С открытой регистрацией —
   читает кто угодно. Регрессия после закрытия доступа 15.10.
   → Новая миграция: убрать политики для `authenticated` (портал читает через service role).

6. **Контейнер портала имеет доступ к Docker хоста (= root на сервере).**
   `docker-compose.prod.yml:19,26-27` + `entrypoint.sh` — `docker.sock` смонтирован, пользователь в
   группе docker. Любая дыра в Next.js превращается в полный захват сервера. Код, которому это было
   нужно (`lib/adminBots/docker.ts`), нигде не используется.
   → Убрать монтирование `docker.sock` и `group_add` у портала (`--force-recreate`).

### 🟠 Нужно сделать (ближайшие недели)

7. **Postgres обеих баз открыт в интернет и без шифрования** (`0.0.0.0:35434`, `0.0.0.0:35432`;
   в репо 10 мест с `sslmode=disable`). Пароли идут открытым текстом, порт открыт для перебора.
   → Пускать только по IP-allowlist / через SSH-туннель, включить TLS.
8. **CI деплоит по паролю сервера и без проверки ключа хоста**
   (`.semaphore/scheduled-deploy.yml` — `sshpass` + `StrictHostKeyChecking=no`), а прод-секреты
   (`portal_secrets`) подключены к тестам **любой ветки** (`.semaphore/semaphore.yml:79-80`) —
   вредоносная зависимость в `npm install` может вынести пароль от прода.
   → Деплой по SSH-ключу с проверкой хоста; секреты — только в деплой-пайплайн main.
9. **Прод-`.env` при каждом деплое заливается в бакет `deploy-backups`.** Если бакет публичный —
   это критично. **Проверить на проде** флаг `public` и политики бакета.
10. **SSRF через разбор сайтов:** демо-разбор (`api/client/demo/personalize`) и автозаполнение
    брифа (`api/client/brief/autofill`) скачивают любой URL, в том числе внутренние адреса сервера
    (через редирект или напрямую). Ответ пересказывает ИИ — так можно читать внутренние сервисы.
    → Проверять каждый адрес после редиректа, запрещать приватные сети.
11. **Регистрация RU без лимитов, капчи и подтверждения почты** (`api/signup/route.ts`): массовое
    создание аккаунтов, каждая регистрация шлёт уведомление в Telegram и создаёт сделку в AMO.
    → Лимит по IP, подтверждение почты, капча; если самостоятельная регистрация не нужна — закрыть.
12. **Траты на ИИ без ограничений:** `api/parsers/search/generate` доступен из демо-сессии без лимита,
    плюс `portal/translate`, перегенерация гипотез брифа — можно исчерпать месячный лимит Requesty
    (как 30.09). → Лимиты и запрет для демо/неоплаченных.
13. **Вебхуки без обязательной подписи:** LinkedIn/Unipile (`tools/li-outreach/webhook`, открыт,
    если не задан `LI_OUTREACH_WEBHOOK_SECRET`), расшифровка видео (`tools/tg-transcribe/webhook`),
    ИИ-звонилка (`ai-caller/telegram/webhook`), atmos-bot (`:8090`, проверяет `user_id` из тела).
    Поддельные запросы шлют сообщения от наших аккаунтов, останавливают кампании, ставят задачи.
    → Обязательная проверка секрета. **Проверить на проде**, заданы ли секреты.
14. **Секреты в базе открытым текстом:** TG-сессии аккаунтов, пароли прокси TG-пула, ключи Unipile/
    OpenAI, ключи клиентских эндпоинтов. Любой сотрудник читает их через REST.
    → Шифровать как пароли почтовых ящиков (`sealMailboxSecret`).
15. **Порт портала 3000 опубликован наружу** в обход nginx/TLS — можно подделать IP и обойти
    лимиты. → `127.0.0.1:3000`.

## Блок 2. Неиспользуемый функционал

### 🔴 Сейчас: похоже, что функции не работают, хотя должны

1. **Напоминания о дедлайнах, эскалация лидов, напоминания технички и синхронизация «Баз» клиента,
   скорее всего, не работают.** Они живут только в `app/worker/index.ts`, который в проде не

   а напоминания не уходят. → Перенести эти циклы в работающий воркер.
2. **`api/instantly/events` недостижим** (middleware режет запрос без входа) — рабочий приёмник
   `instantly/webhook/[account]`. Удалить.
3. **`vercel.json`** — мёртвый конфиг (портал в Docker); вместе с ним не идёт чистка архива регламента
