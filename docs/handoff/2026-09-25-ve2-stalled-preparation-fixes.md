## Изменения

- Возобновляемый источник удерживает страницу только ради пригодной строки
  либо ещё допустимого поиска сайта. Результат «сайт не найден» не блокирует
  следующую страницу. Старые исходные строки и квитанции поиска сохраняются;
  курсор, лимиты расходов и проверки пригодности контактов остаются действующими.
- Координатор перечитывает базу при терминальной задаче, а шаблон — при
  терминальной генерации. Завершение анализа между чтением и enqueue также
  обрабатывается без ложной ошибки и без повторного анализа.
- Ошибка template учитывается только для текущего поколения анализа. Неудача
  новой генерации по-прежнему требует явного повтора, бесконечного платного
  цикла нет. Ошибка чтения координатора сохраняет запрос для следующего опроса.
- Большие резервы сохраняют одинаковые длинные описания один раз в
  `relevance_reserve.descriptions`; строка содержит `_ve_description_ref`.
  `readVeRelevanceReserve` восстанавливает исходные строки. Адреса, компании,
  статусы и вердикты не удаляются; SQL-проверки доступности review по-прежнему
  читают свои поля напрямую. Все записи checkpoint и восстановление failed
  preview применяют уплотнение. Некорректная ссылка вызывает явную ошибку.
- Изменений схемы БД нет. Для старого worker, не знающего словарь описаний,
  перед откатом понадобится обратное разворачивание нового представления;
  повторное использование старого reader после уплотнения не поддерживается.

  гонка завершения анализа не создаёт повторный job; ошибка чтения сохраняет

- Новые тестовые файлы/проверки в Jest не добавлялись: отдельное разрешение
  было запрошено, но до завершения работы ответа не было.

## После деплоя — отдельное разрешение на production

Сначала подтвердить версию web/VE2 worker, затем снять свежие состояния этих
пяти баз. Одного деплоя недостаточно для уже терминальных подготовок.
Артефакт/ProfiAds продолжать с их же каталогов; StaffLine — с сохранённых
проверок и дочерних задач. У двух баз Когнитуса сначала восстановить именно
подготовку писем по уже готовому анализу: не перезапускать сбор автоматически
ради снятия старой ошибки, не повышать пределы расходов.

Не обещать 500 контактов: исправления устраняют технические блокировки,
а остановки по исчерпанию/рентабельности сохраняются. Другие частичные базы
Когнитуса, остановленные по лимитам, сами по себе не доказательство ошибки.
