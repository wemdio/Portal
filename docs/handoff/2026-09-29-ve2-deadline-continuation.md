# VE2: продолжение после дедлайна и аналитика первой отправки

Дата: 2026-09-29. Изменения подготовлены для Sergey на базе test `75e5867c2`. Production не изменяли; нужна штатная выкладка с миграцией `20260929_0060_ve_continue_after_deadline.sql`.

## Решение пользователя

Если специалист явно подготовил запуск, прошедший дедлайн не должен прекращать поиск и пополнение. Цель остаётся прежней. До дедлайна дневной план учитывает оставшиеся рабочие дни; после — использует текущую автоматическую ёмкость отправителей или ручной лимит до достижения цели. Start остаётся только в Instantly. Тесты дополняются в существующих файлах с явного согласия пользователя.

## Реализация

1. При отсутствующей аналитике в catalog inventory проверяет campaign ID через GET в неизменяемом workspace запуска, затем читает overview строго этой кампании. Принимает только явные целые неотрицательные счётчики; new_leads_contacted_count не может превышать emails_sent_count. Нет workspace, неверная identity, пустой/неверный ответ и сетевой сбой остаются ошибкой. Отсутствующая строка больше не подменяется нулём. Это только GET, без записи в catalog.
2. Убран запрет по прошедшей дате из проверки карточки, preview и создания кампании. План сохраняет исходную дату; после неё прогноз ограничен 366 рабочими днями и использует выбранную дневную ёмкость.
3. Миграция заменяет только проверки/расчёт срока в девяти VE2-функциях. Она читает установленные определения, проверяет каждую ожидаемую подстроку и прерывается при несовпадении. Повторное применение ничего не меняет. Сохраняются grants/owner, блокировки, идемпотентность и проверки текущего согласования.
4. Сохранены остановки по цели, Pause в Instantly, пауза поиска, закрытие периода/нерабочий статус проекта, смена привязки и появление периода у запуска без периода. Старые released-запуски автоматически не возрождаются. Накопленный ручной факт карточки не становится фактом этого запуска.
5. Двухдневный буфер supply и ограничения источников не менялись. Готовые новые контакты после проверки и аудита идут в резерв тех же кампаний. Дополнительная загрузка использует тот же дневной ledger: accepted/uncertain не отправляются повторно.
6. Интерфейс объясняет продолжение после даты до цели; поле для проекта без периода называется «Цель новых контактов».
