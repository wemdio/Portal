# VE2: индивидуальный запуск готовых баз

## Поведение

Раньше запуск требовал готовности и одобрения всех гипотез, выбранных для подготовки.
Теперь на шаге «Базы и объём» видны готовность и число проверенных контактов каждой базы.
Одобренную базу можно передать в настройки запуска кнопкой «Запустить отдельно» либо
отметить несколько баз для одного запуска. Остальные гипотезы, подготовка и одобрения
не меняются. Сбор незавершённых баз не перезапускается.

Обзор запуска явно перечисляет только выбранные базы; окончательное разрешение на
создание кампаний и отправку остаётся отдельным подтверждением. Изменение состава
сбрасывает обзор и подтверждение. Если выбранная база утратила одобрение, она не
исключается молча: запуск блокируется до нового выбора/одобрения. Уже переданная в
запуск база показывает результаты вместо повторного одобрения/запуска.

## Сервер и выпуск

`readSetup` проверяет непустое подмножество сохранённого выбора вместо равенства
всему набору. Для каждой базы сохранены проверки проекта, готовности, версии одобрения,
писем и аудита. Миграция `20260928_0001_ve_launch_selected_bases.sql` меняет ту же
проверку в `ve_start_outreach` под существующими блокировками.

Для появления возможности требуется обычный выпуск UI/worker и этой миграции
основной БД Portal. Миграцию production в задаче не применяли. Один незавершённый запрос
создания/активации на проект (`queued/running/waiting`) по-прежнему сохраняется;
после его завершения можно настроить следующий запуск без снятия других гипотез.
Идемпотентность, защита от повторного создания кампаний и правила ежедневной поставки
не менялись.

## Повторная проверка

При отдельном ревью после `516ffaf23` воспроизведены и исправлены два UI-недочёта:

- Список запуска использовал `row_count`, хотя сохранённые строки могут ещё не пройти
  все проверки. Теперь он получает `checked_ready` из той же загрузки аудитории, что
  подробная карточка: без дополнительного запроса, без подмены лимитом цели или числом
  строк. Если загрузка аудитории не удалась, число скрывается.
- Поля проекта и цели оставались доступны во время сохранения запуска. Теперь они,
  выбор клиента и форма создания клиента заблокированы до ответа; после ошибки
  снова доступны. Обычная форма отдельного шаблона сохраняет прежнее поведение.

Локальная проверка реальной миграции расширена до 15 групп: две базы из трёх,
следующий индивидуальный запуск после первого без повторного выбора и одобрения,
отказ всего группового запроса при невалидной базе без частичной записи. Runtime:
18 групп. Offline-браузер дополнительно проверяет правильный счётчик, блокировку
полей при медленном ответе, повтор с тем же ключом после потери ответа, изменение
настроек и отзыв одобрения, сохранность ввода при polling, запрет запуска с
несохранённым лимитом. Проверены прежние индивидуальный/групповой сценарии и мобильная
вёрстка. Артефакты: `/Users/cybermart/.codex/handoffs/ve2-individual-launch-review-20260928/`.

После исправлений: полный Jest 293 suites / 3265 passed / 2 skipped (106.712 s),
