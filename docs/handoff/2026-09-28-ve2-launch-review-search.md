## Найденный дополнительный сбой восстановления

После сохранения accepted tranche и перезапуска до активации loadPreflight мог
упасть на ещё отсутствующей аналитике. Из-за этого код не доходил до уже
существующего activateDeliveredContactCampaigns.

Ошибке неизвестного first-contacted присвоен отдельный класс. Только для неё
scheduler пробует существующую процедуру восстановления активации. Новые
контакты по-прежнему не резервируются при неизвестной статистике. Процедура
сохраняет все прежние проверки live campaign/senders, одобрения, срока/дней,
accepted watermark, неопределённых попыток и ручной паузы. Прочие ошибки
preflight не включают этот путь, shutdown не начинает дополнительную работу.
Ошибку аналитики продолжаем логировать: восстановление активации не означает,
что дозаливка разрешена без статистики.

## Поиск

- Общий первый экран VE2: название/сайт, число совпадений, сброс, отдельное
  пустое состояние; фильтр сохраняется при возврате из проекта.
- Клиент/профиль отправки в OutreachLaunchPanel и в отдельном Step5Template:
  список с вводом части названия.
- «Проект клиента» в общем DeliveryPlanBlock: такой же поиск.

Использован один VE2-компонент SearchableSelect. ID выбора сохраняется отдельно
от поискового текста: печать/Tab/Escape не выбирают другую запись. Выбор мышью
либо Enter, навигация стрелками, закрытие при уходе фокуса. Учитываются регистр,
ё/е и пробелы (StaffLine находит Staff Line). Закреплённые настройки и блокировки
во время отправки формы сохранены. Production API и правила одобрения не менялись.
