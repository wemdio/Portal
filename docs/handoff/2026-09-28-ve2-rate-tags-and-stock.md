Production в этой работе только читался; миграций нет.

## Причины и исправления

- Расчёт темпа отвергал любую другую активную кампанию с `email_tag_list`, даже
  если её почты не пересекались с текущим профилем. Теперь объединение тегов
  разрешается через `/accounts?tag_ids=...` с полной пагинацией и ограниченными
  пачками тегов. Реальное пересечение исключается из мощности, посторонние почты
  её не блокируют. Ошибка/повтор курсора/повтор почты в одной выборке не считаются
  отсутствием занятых почт. Таймаут чтения включает тело ответа.
- После первой загрузки каталог может ещё содержать `new_leads_contacted_count:
  null`. Прогноз доставки по-прежнему не считает неизвестное нулём; отдельный
  `DELIVERY_ANALYTICS_PENDING` объясняет ожидание синхронизации. Подтверждённые
  факты готового запаса, загрузок за день/всего и неопределённых результатов
  показываются независимо от прогноза, по ledger и блоклисту, в часовом поясе
  закреплённого запуска. Загрузка при неполной аналитике остаётся заблокирована.
- Кнопка «Подготовить следующий запуск» переименована в «Выбрать другую базу для
  запуска». Действие прежнее: переход к выбору баз, без создания кампании или
  повторной отправки. Для ежедневной дозаливки текущей базы она не нужна.

Документация фильтра `tag_ids` (OR):
[Instantly List account](https://developer.instantly.ai/api-reference/account/list-account).
