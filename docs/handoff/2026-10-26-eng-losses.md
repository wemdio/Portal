# ENG: потери на нашей стороне — замер и правки (26.10.2026)

Решение владельца: «сначала чини потери на нашей стороне: чтение закрытых
сайтов и проверку адресов на Microsoft и Mimecast», затем «разрешаю:
опубликованные на сайте самой компании адреса, которые нельзя проверить, брать
в базу с пометкой и отправлять малыми порциями с контролем отказов; и сделай
правки чтения сайтов».

Граница: сайты, которые закрываются от роботов, и запрет Microsoft/Mimecast на
проверку ящиков мы не обходим.

## Замер по HST (6 191 решение по компаниям, 2 466 потеряны на чтении сайта)

| Почему не прочитали | Компаний |
|---|---|
| Домен не существует (компании нет или её купили) | 487 |
| Ведёт на сайт другой компании | 503 |
| Сайт закрыт от роботов (403/429/проверка) | 267 |
| Сервер не отвечает или ошибка | ~450 |
| Открывается, но моделям мало текста | 369 |
| Сертификат с ошибкой (наш читатель отбрасывал) | 7 |
| Собирается скриптами, браузер показывает текст | 54 из 249 «пустых» |
| Сейчас открывается, тогда был сбой | 123 |

Большинство «ошибок TLS» (46) — сервер не принимает защищённое соединение для
этого имени; открывает только http, который политика рынка запрещает.

## Сделано

- `b6a2d9249` — прямое чтение сайтов английского рынка терпит негодный
  сертификат и заголовки до 64 КиБ, как поиск почт конструктора. Защита адреса
  та же. Все 7 сайтов HST с ошибкой сертификата теперь читаются.
- `8dcf32f8d` — этап 1: адрес с сайта компании со статусом «unknown» (строка не
  из реестра, домен компании) остаётся в базе после проверенных с пометкой
  `_email_unverified: 'site'`. Запуск его не отправляет («Отложено адресов без
  проверки»), кабинет клиента считает его в `unverified`, не в `failed`.
  Проверено офлайн-стендом (20 проверок), TypeScript, Jest 299, build:workers.

## Не сделано

- Чтение страниц на скриптах браузером: +54 компании из 2 466 (~2%), нужен
  браузер в воркере с проверкой адреса на каждом запросе и запасом памяти —
  отложено.
- Повтор позже для «не ответил»: проверка уже делает три попытки в разных
  кругах; у этих сайтов они не прошли, выигрыш не доказан — не делалось.
- Уже собранные базы помеченных адресов не содержат: «unknown» тогда
  отбрасывались при сборе. Их дадут новые сборы (или повторный импорт из
  выгрузок конструктора — запись на прод, по «да»).

## Этап 2 — отправка (`71d81dd36`, 26.10)

Решение владельца: «клиенту не показывать, видна только нам; делай отправку
отдельной кампанией до 10 новых контактов в день».

- Запуск (launchTemplate.ts, шаг 6b) после кампаний клиента создаёт кампанию
  «… · unverified»: те же письма, пул ящиков и окно, `daily_max_leads` = 10.
  Только компании без единого проверенного адреса в базе, после «Do not
  contact», без адресов основной кампании, до 2000. Отказ — в журнал, запуск
  клиента не страдает. Force-перезапуск ставит прошлую такую кампанию на паузу.
- Запись — `launch_info.unverified_campaign`; клиенту не видна нигде (нет в
  `campaigns`, в heEngLaunchCampaigns, в проекции кабинета). Фраза этапа 1
  «Отложено адресов без проверки» из ответа клиенту убрана.
- Старт и пауза — проход engUnverifiedCampaign.ts в воркере движка гипотез
  (раз в 5 минут): отправляет, только когда клиент хочет отправку, аккаунту
  можно и каждая основная кампания с адресами отправляет или закончила; иначе
  пауза. Остановку рассыльщика (защита от bounce) не снимает — алерт команде.
- Ответы — клиенту под именем основной кампании; «Do not contact» и лента
  партнёров её учитывают.

## Деплой

- Приложение и воркеры (запуск идёт в приложении, проход — в воркере
  hypothesis-engine вне полосы ENG-сборов). Миграций нет.
- Переменные (необязательные): `HE_ENG_UNVERIFIED_SEND=0` — выключить (запуск
  не создаёт такие кампании, проход ставит на паузу идущие);
  `HE_ENG_UNVERIFIED_TICK_MS` — период прохода (по умолчанию 5 минут).

## Ограничения

- Пауза клиента доходит до скрытой кампании в течение прохода (до ~5 минут),
  не мгновенно; основные кампании встают сразу, как раньше.
- Смена окна отправки клиентом скрытой кампании не касается (окно — с момента
  запуска).
- Ночной долив непроверенные адреса не добавляет: в скрытую кампанию они
  попадают только при запуске.
