# VE2: автоматический темп и ручной верхний предел

28.09.2026. Ветка задачи `codex/ve2-preview-recovery-scale`, доставка коммита в `Sergey` по поручению пользователя. Production в этой работе не менялся.

## Поведение

- В автоаутриче перед запуском выбранных баз есть «Темп новых контактов»: автоматически или ручной верхний предел. Перед новым запуском настройка явно сохраняется; её версия входит в согласованный запрос. Несохранённое изменение выключает подтверждение запуска.
- В «Результатах» того же проекта настройку можно изменить для действующего запуска. Это общий предел проекта, не отдельный лимит каждой гипотезы.
- Существующие проекты без записи `ve_contact_delivery_rates` сохраняют прежний лимит. Для StaffLine после деплоя нужно открыть «Результаты», выбрать режим и нажать «Применить темп». Существующий запуск повторять не нужно.
- Темп рассчитывается по выбранным почтам профиля, их фактическим лимитам и состоянию, окну отправки и интервалам. Бюджет делится на максимальную длину цепочки, чтобы оставить место продолжениям. Ручное число ограничивает этот результат сверху.
- Текущий план по цели/оставшимся рабочим дням и предупреждения о дефиците остаются в обзоре запуска. Рассчитанная мощность — верхняя граница, а не гарантия первых отправленных писем к дедлайну.
- После уточнения пользователя общие почты других активных кампаний не исключаются из мощности: Instantly применяет дневной лимит каждой почты суммарно ко всем её кампаниям. Пересечение показывается как информация; реальный темп может быть ниже расчётной верхней границы. При включённом slow ramp API не сообщает текущую ступень; считаем по 2 письма/день и явно показываем это в интерфейсе. Не выводим ступень из возраста почты. При неполных данных расчёт не считается успешным.
- Лимиты самих почт не повышаются. Перед очередной доставкой воркер пересчитывает мощность, обновляет только `daily_limit` и `daily_max_leads` собственных кампаний и перечитывает результат. Лимиты распределяются между ними так, чтобы сумма не превышала общий бюджет. Если положительного лимита не хватает на каждую кампанию, применение отклоняется с объяснением.

## Сохранность и сбои

Настройки версионированы (CAS), изменения записываются в журнал. Короткая возобновляемая аренда исключает двух одновременно применяющих воркеров и изменение политики посреди PATCH. Сбой API/неподтверждённый PATCH блокирует новую загрузку до проверки в следующем проходе. Уже существующие кампании не создаются и не активируются этим кодом.

Смена лимита не меняет строки загрузки, принятые/пропущенные/неопределённые адреса и истории попыток. Уже зарезервированная порция за текущий день остаётся прежней; следующая новая порция использует новый лимит. Лимит объёма контактов тарифа Instantly и восстановление неопределённых результатов работают прежним способом.

## Выпуск

**Миграция `20260928_0004_ve_contact_delivery_rate.sql` обязательна до запуска новой версии приложения и воркера.** Она создаёт настройки/журнал и RPC, разрешает подтверждённое изменение только мощности в ранее неизменяемой привязке, добавляет барьер свежести перед резервированием. Применение миграции здесь не выполнялось.

ENG, `he_*`, общие почтовые профили и аккаунты не меняются. Старые отдельные ручные формы запуска сохраняют свой прежний путь; новая настройка размещена в основном интерфейсе автоаутрича.

Уточнение потока после сообщения пользователя о ручной паузе StaffLine: основной
автоаутрич сначала готовит кампании без отправки. Отдельное подтверждение
специалиста в «Очереди запусков» разрешает активацию. До подтверждения контакты
остаются в резерве Portal; первая порция загружается после него. Воркер больше
не подставляет `confirm_campaign_review: true` за специалиста. Ручная пауза уже
запускавшейся кампании не снимается автоматически.
