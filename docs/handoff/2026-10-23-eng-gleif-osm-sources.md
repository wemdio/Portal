# ENG: бесплатные источники GLEIF и OpenStreetMap

23 октября 2026. Ветка назначения `Sergey`. Пользователь: «подключай первыми
GLEIF и OpenStreetMap как бесплатные источники ENG; только ENG, RU и VE2 не
трогай, деплой сделаю сам». Оба нашлись в каталоге Firecrawl Alexandria, как
и вчерашние реестры; берём данные напрямую у первоисточника, без Firecrawl и
без ключей. Миграций нет, переменных окружения нет.

## Что подключено

Оба источника работают внутри существующего механизма реестров ENG
(`eng_registry`: план срезов, страница по 25 записей, проверка сайта,
подтверждение страны, лимит $5 базы).

**GLEIF** (`api.gleif.org`) — мировой реестр юрлиц с кодом LEI. Отрасли в нём
нет, поэтому срез ищет слова в названиях на языках стран клиента плюс
английский (`engGlobalRegistryCatalog.ts`: «versicherung», «lebensversicherung»,
«verzekering», «forsikring»… — фильтр GLEIF ищет только целые слова, поэтому
немецкие составные слова перечислены отдельно). Берутся только активные
юрлица категории GENERAL, без фондов, фондов-благотворителей, ассоциаций и
холдингов; страна — по юридическому адресу (фильтр API) и по адресу
штаб-квартиры (проверка записи). Сайта в GLEIF нет: его находит тот же путь,
что у Companies House (каталог PDL по названию, затем один платный поиск,
~$0,001). На сайте компании проверяется LEI или номер в местном реестре
(`registeredAs`: «HRB 7876», KvK, CVR, org.nr, CRO, RCS…) вместе с
названием — номера местных реестров повторяются между судами и странами.
Отрасли: ПО, банки, фонды и кастодианы, управляющие активами, страхование,
страховые брокеры, больницы, лаборатории, грузоперевозки, стройка, отели,
машиностроение, юрфирмы, бухгалтерия и аудит.

**OpenStreetMap** — помещения бизнесов на карте, через SPARQL-сервис QLever
Фрайбургского университета (`qlever.dev/api/osm-planet`). Публичный Overpass
не подошёл: страница по Германии шла ~100 с, и сервер просит не нагружать его
автоматически. Берутся только объекты с названием и сайтом (ещё почта и адрес,
если есть) внутри границы страны клиента; страница из 25 — 4–15 с. Сайт из
карты принимается как собственный сайт компании, поэтому платного поиска нет.
Отрасли — по тегам карты: стоматологии, клиники, больницы, лаборатории,
ветклиники, аптеки, юрфирмы, бухгалтеры, нотариусы, агентства недвижимости,
архитекторы, инженерные бюро, кадровые и маркетинговые агентства, турагентства,
автосалоны, фитнес, салоны красоты, рестораны и кафе, языковые и автошколы,
коворкинги, IT-компании, банки, страховые агентства, логистика, стройка, отели.
Для поиска компаний от 50 сотрудников OpenStreetMap не используется: на карте
в основном малый бизнес и нет численности.

## Как устроено

- `engPublicRegistryTypes.ts`: провайдеры `gleif`, `osm`; у глобального среза
  `country: 'global'` и список `countries`; у кандидата GLEIF —
  `localRegistryId`.
- `engPublicRegistryPlan.ts`: один срез на отрасль сразу на все страны клиента
  (до 40 стран в срезе). Срез «на страну × отрасль» дал бы десятки срезов,
  которые по очереди отодвинули бы PDL на много кругов. Новые отрасли малого
  бизнеса — только для глобальных источников. Сохранённые планы и id срезов не
  меняются.
- `engPublicRegistries.ts`: запросы и разбор ответов GLEIF и QLever.
- `engRegistryIdentity.ts`: LEI с проверкой контрольной суммы ISO 17442,
  элемент OSM `node/…`, `way/…`; адреса записей фиксированы.
- `engRegistryCompanyEvidence.ts`: сверка номера GLEIF на сайте, больше форм
  юрлиц («GmbH & Co. KG», «B.V.», «S.p.A.», «A/S», «UG (haftungsbeschränkt)»,
  «Aktiengesellschaft»); варианты названий для каталога по новым странам.
- `engCompanySearch.ts`: запрос поиска сайта v3 убирает и эти формы; v3
  совпадает с v2 для названий без них, оплаченные запросы v1/v2 узнаются.

План реестров создаётся при старте сбора: новые источники получат только новые
сборы, идущие базы не меняются.

## Проверки

- TypeScript core, ESLint изменённых файлов, полный Jest (298 наборов, 3384
  теста), `npm run build:workers`. Новых `*.test.ts` нет.
- Живой бесплатный прогон через настоящий план, чтение страниц и проверку
  кандидатов (каталог — с прода только на чтение, платный поиск не запускался):
  - OSM, стоматологии DE/NL/DK без ограничения размера: страница 14,5 с, 25
    кандидатов с сайтами, 8 из 8 проверенных подтверждены;
  - OSM, юрфирмы UK/IE 10–200: страница 3,7 с, 5 из 6 подтверждены, размер из
    каталога по сайту (11–50, 51–200), один — размер не подтверждён;
  - GLEIF, страница ~0,8 с: страховщики 10 стран, юрфирмы UK/IE, разработчики ПО
    DE/AT/CH; без платного поиска сайт нашёлся только через каталог (1 из 24),
    как и ожидалось — для GLEIF нужен поиск сайта, как для Companies House;
  - для отраслей малого бизнеса GLEIF отдавал личные холдинги врачей — такие
    отрасли оставлены только OpenStreetMap, холдинги отсекаются.
- 7 офлайн-случаев сверки номеров GLEIF (HRB с названием и без, тот же HRB у
  другой компании, Impressum, LEI, KvK с подписью и тот же номер как телефон) и
  12 прежних случаев проверки сайтов — все верно.
- Планы для 7 разных клиентов: страховщики 200+, стоматологии, юрфирмы 10–200,
  ПО 50+, салоны красоты, маркетинговые агентства, фонды — срезы как задумано.

## Что не проверено и риски

- Сквозной сбор с новыми источниками на проде — после деплоя, с отдельным «да».
- QLever и GLEIF — бесплатные внешние сервисы без гарантий доступности. Сбой
  чтения обрабатывается как у других реестров: повтор с паузой, после трёх
  неудач срез помечается недоступным, сбор идёт дальше.
- Охват OpenStreetMap неравномерный: юрфирм с сайтом в Германии 3 649, в
  Великобритании 1 258, в США 5 236, а в Дании 48, в Швеции 39.
