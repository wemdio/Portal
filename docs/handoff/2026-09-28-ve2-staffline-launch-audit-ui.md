# StaffLine: противоречие аудита и счётчика кампаний

## Подтверждено 28 сентября 2026

На экране индивидуального запуска «Энергетические компании» одновременно были
«Аудит сегментации ещё не завершён полностью», «Готово к запуску» и 0 кампаний / 774 контакта.

Read-only SQL в production подтвердил:

- проект `523affe8-01fe-4b1e-a584-b4f6415c33f3`, база `1a69cda6-7acf-4bc1-9494-3341d78da62f`;
- аудит `a68e3415-cf4c-4625-884d-bf3f493764c2`: ready, launch_status=idle, error=null;
- summary.status=not_required, segments=[], default.count=774, исключения и незавершённые пакеты — 0;
- задача аудита `b84e6525-e721-41db-95fd-ecf1d747957c` done, обновлена 07:05:40 UTC;
- на момент проверки outreach runs у проекта отсутствовали.

`not_required` означает, что все получатели используют общую цепочку писем;
774 контакта дают одну кампанию. Повторять сбор или аудит для этого не нужно.

## Причины и исправление

1. `OutreachLaunchPanel` читал `summary.defaultGroup`, хотя prepare-launch возвращает
   сохранённый `VeSegmentationAuditSummary` с полем `default`. Теперь используется
   канонический тип, учитываются непустые сегменты и общая группа. Надпись:
   «Будет создано кампаний»; при отсутствии summary выводится «—».
2. Панель передавала ID ещё работающего аудита в `useTemplateLaunch`. Общий хук
   запускал второй delivery-preview и сохранял ошибку incomplete. После завершения
   аудита ID не менялся: prepare-launch уже говорил ready, а отдельная ошибка могла
   оставаться до следующего запроса. Панель теперь использует только preview из
   prepare-launch, связанный с текущим requestKey. Второй preview-запрос отключён
   отсутствием audit ID у общего хука. `DeliveryPlanBlock` принимает готовый preview
   и проверяет соответствие проекта, периода и цели. Обычный Step5Template продолжает
   использовать собственную проверку; его поведение не менялось.

Серверные проверки запуска не ослаблялись. Смена параметров убирает старый расчёт
и требует нового согласия; поздний ответ для прежних параметров не открывает запуск.
