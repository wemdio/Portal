# StaffLine: первая загрузка блокировалась несинхронизированной статистикой

## Проверенная цепочка событий

Продолжение `2026-09-28-ve2-staffline-launch-audit-ui.md`.
Проект `523affe8-01fe-4b1e-a584-b4f6415c33f3`, гипотеза «Энергетические компании».

- Создан outreach run `0d9d32f6-baff-4ef6-a3bc-a89772ca8a6c` и кампания
  `ba5b0ce7-e336-4c15-b458-474a49d108ef` с 774 контактами в готовом резерве.
- Сначала run ждал сезонного решения: snapshot unknown, not_before=null,
  RU mode=enforced. Это не ожидание времени: без ручного решения unknown не исчезает.
- Пользователь сохранил activate_next в интерфейсе 28 сентября в 08:11:42 UTC.
  Очередь `ebb9235a-302a-4423-b247-8c1ae0ef6e2c` и run стали active в 08:12:28 UTC;
  outreach_start job `955c4194-8551-4536-ba10-26ff754cab31` done.
- **active означает допуск к загрузке, а не подтверждённую отправку.**
  В 08:16:39 UTC: 774 ready, 0 загружено, remote_status=0 (Draft), activated_at=null,
  записей суточной доставки/попыток активации ещё нет.
- Рабочий процесс healthy, интервал доставки 300000 ms. Логи двух проходов:
  `delivery catalog requires an exact non-negative first-contacted count`.
- Read-only запрос к instantly-postgres-prod подтвердил: строка каталога уже есть
  (synced_at=08:08:41 UTC), но new_leads_contacted_count, analytics_synced_at,
  leads_count и emails_sent_count ещё null. Каталог и аналитика синхронизируются отдельно.

## Исправление

`contactDeliveryInventory` допускает начальный null как 0 подтверждённых первых
контактов только когда **оба** new_leads_contacted_count/analytics_synced_at равны
null и журнал Portal подтверждает leads_count=0, activated_at=null, наблюдённый
Draft/Paused с корректной датой наблюдения. Существующие числовые факты сохраняются.
Отсутствие метаданных, прежняя загрузка/активация, повреждённое значение или null
после синхронизации аналитики по-прежнему блокируют работу. Новых API-вызовов нет.

В очереди «Активная отправка» заменена на «Запуск разрешён», группа — «Запуски в
работе». Результаты проекта также показывают разрешение загрузки/отправки, а не
утверждают, что отправка уже включена.

## Проверки и граница

- 8 существующих Jest suites: 106 passed, 1 existing skipped. Исправлена fixture
  новой кампании в contactDeliveryRunner.test.ts; новых it()/test-файлов нет.
- TypeScript core + tests, ESLint, bundle worker-vertical-engine-v2 — PASS.
- Изолированный harness воспроизводит production-сбой на исходном HEAD, проходит
  на исправлении: начальный null; числа; отсутствие каталога; прежняя загрузка/
  активация; неправильный статус; отсутствие наблюдения; повреждённые и недоступные
  данные. 450 расчётных комбинаций проверяют учёт известных загрузок.
- Артефакты: `~/.codex/handoffs/ve2-first-delivery-20260928/`.

Production только читали. Нужен обычный деплой приложения и VE2 worker; миграций и
ручного пересоздания кампании нет. После деплоя существующий active запуск входит
в очередной автоматический проход доставки (каждые 5 минут). Фактические загрузку
и включение Instantly следует отдельно подтвердить по журналу, а не по run.active.

Открыто: StaffLine закреплён лимит 50 новых контактов/день, цель 4000 до 30.09.2026.
Исправление статистики не решает несоответствие цели и дневного темпа. Production-
настройки этой задачей не менялись.
