# ENG: поиск актуального сайта для мёртвых и припаркованных доменов

23 октября 2026. Ветка `Sergey`, коммит `766fda5aa`. Не задеплоено. Миграций и
переменных окружения нет. Только английские сборы.

Решение владельца: «строй поиск актуального сайта в ограниченном виде: только
мёртвые домены и припаркованные, только тот же бренд».

## Зачем

В проверочном сборе страховщиков HST (`0777749b`) из 2 154 решений по
компаниям 715 — «сайт не открывается» и 283 — «редирект не подтверждён». По
разбору 23.10 из потерянных сайтов около 38% — домен не существует, около 6% —
припаркован; остальное — блокировка роботов, плохой сертификат, молчащий сервер,
редирект к купившей компании. Поиск помогает только первым двум группам и только
когда компания переехала на домен со своим брендом.

## Что сделано

- `engCompanyQualification.ts`, чтение сайта (`companyPages`): итог `dead`:
  - `dns` — имя не существует у главной и у `www.` (только ответ резолвера
    «такого имени нет»; сбой нашего резолвера сюда не попадает);
  - `parked` — главная уходит на сервис парковки или маркетплейс доменов
    (sedoparking, dan, afternic, hugedomains, bodis и др.), на страницу GoDaddy
    `/lander`, или короткая страница говорит, что домен продаётся
    (`heEngParkedPage`). Текст такой страницы до моделей не доходит.
- Только при `dead` и окончательном отказе чтения — одна платная страница Serper
  (`createHeEngCatalogWebsiteSearchPlan`: название без юридической формы +
  страна, запрос того же вида, что у поиска сайта реестровой компании, ≤ 300
  символов). Деньги — из бюджета базы ($5). Поиск хранится в
  `economy.siteSearches` состояния проверки до и после вызова и второй раз не
  покупается; перезапуск посреди запроса — `unknown_cost`, как у реестров.
- Из выдачи читается первый сайт того же бренда (`companySiteAlias` от сайта
  каталога); сайт другого бренда не читается вовсе. Страницы с другого домена,
  поэтому принадлежность подтверждают обе модели; мягкое правило совпадения
  отрасли (`77b7b8d84`) здесь не действует.
- Вердикт принятой компании получает `currentWebsite`. `website` строки остаётся
  сайтом каталога: на нём держатся ключ вердикта, просмотренные компании,
  исключения и доказательство страны. Проверка перед письмами
  (`heEngCompanyQualified`) отказывает, если `currentWebsite` — не тот же бренд
  или тот же мёртвый домен.
- Конструктор (`buildConstructGrid` в `stages/baseCollect.ts`): найденный сайт
  уходит в колонку `Company Website`, которую поиск почт и фильтр адресов берут
  раньше `Site` (`PRIMARY_SITE_HEADERS`), а импорт не читает (её нет в
  `CONSTRUCT_HEADER_MAP`). Сетка без таких строк прежняя байт-в-байт. Шаг
  описаний по-прежнему берёт `Site`; у английских сборов описание приходит из
  страниц, прочитанных поиском почт.

## Проверки

Офлайн-стенд: настоящая `runHeEngCompanyQualification`, бюджет базы в памяти,
подменённые Serper, модели и чтение страниц (`ctx.fetchText`). Мёртвый домен →
найден сайт того же бренда → принято с `currentWebsite`; парковка → то же, текст
парковки до моделей не дошёл; мёртвый домен → только чужой бренд → не читается,
не принято; блокировка 403 → поиска нет; живой сайт → поиска нет; ровно три
поиска, каждый списан по 1 кредиту; повтор по сохранённому состоянию ничего не
покупает; перезапуск с поиском в полёте → `unknown_cost`; подмена
`currentWebsite` на чужой бренд → отказ перед письмами. Стенд мягкого правила —
21 из 21. TypeScript core и tests, ESLint, полный Jest (301 набор),
`npm run build:workers`. Новых `*.test.ts` нет.

## Ожидаемый эффект

Поиск получат около 44% потерянных сайтов (мёртвые и припаркованные): на сборе
размера `0777749b` (2 509 кандидатов) это около 430 поисков, около $0,4. Если
у четверти из них найдётся сайт того же бренда и половина пройдёт проверку
моделей, это около +10–15% контактов. Точную цифру даст первый сбор после
деплоя: смотреть долю `site_unavailable_exhausted`, число `currentWebsite` в
вердиктах и строки `Company Website` в джобах конструктора.
