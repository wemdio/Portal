# ENG: неотвеченный запрос поиска больше не останавливает базу

22 октября 2026. Ветка назначения `Sergey`. Пользователь: «почини остановку
сбора из-за медленного ответа поиска: такой запрос списывать по резерву и
продолжать сбор. Только ENG, RU и VE2 не трогай, деплой сделаю сам».
Миграций нет, записей в прод нет.

## Что было

Проверочный сбор HST Insurance carriers (база `c21cb843`) встал в 16:34 UTC с
`stop_reason=error` на 24 контактах и $0,13 из $5. Один запрос в Serper не
ответил за 8 секунд. Код записал его в бюджет базы с неизвестной ценой
(`he_eng_base_spend_requests.status='unknown'`), бюджет получил
`hold_reason='unknown_cost'`, и все следующие платные действия этой базы
отказывали — сбор закончился. Так же кончалась база при обрыве соединения, при
ответе 502 с HTML вместо JSON и при ответе без поля `credits`. В ENG это был
первый такой случай (65 запросов прошли, 66-й нет).

## Что сделано

`lib/hypothesisEngine/engCompanySearch.ts`, `runHeEngCompanySearchPage`:

- Отправленный запрос без квитанции о цене (таймаут, обрыв, ответ без
  `credits`) списывается по полному резерву — 2 кредита, $0,002 по тарифу
  $1 за 1 000. Serper берёт 1 кредит за страницу, так что бюджет базы не
  занижается. Блокировки базы нет.
- Такая страница считается потраченной: её результаты потеряны, курсор
  переходит к следующему запросу, та же страница сразу не покупается заново.
- Три неотвеченных запроса подряд — поиск помечается временно недоступным
  (`search_transient`) для этой контрольной точки: у веб-поиска базы это
  значит, что сбор идёт дальше по другим источникам, у компании из реестра —
  причина «поиск недоступен». Отвеченная страница обнуляет счётчик.
- Ждём ответа 15 секунд вместо 8: запрос оплачен в любом случае, лучше
  дождаться результатов.
- Отмена задачи посреди запроса: запрос списывается по резерву, контрольная
  точка сохраняется без метки «запрос в полёте», стадия останавливается;
  следующий запуск продолжает обычно. Отказ до отправки по-прежнему стоит 0.

`lib/hypothesisEngine/engRegistryCompanyEvidence.ts`: если единственный поиск
сайта компании из реестра не ответил, причина — `website_search_unavailable`, а
не «сайт не найден».

RU, VE2, общий бюджетный журнал, миграции и правила для LLM не менялись.

## Что по-прежнему останавливает базу

- Жёсткое убийство процесса ровно во время запроса: код не успевает записать
  цену, метка «в полёте» остаётся. Обычный деплой останавливает воркер мягко,
  отмена проходит по пути выше.
- То же правило «неизвестная цена — стоп» для запросов к моделям (Requesty,
  `engBaseBudget.ts`, `settleHeEngRequestyCall`). В этой задаче не трогали.
- Сбой базы данных в момент записи цены.

Остановленная база `c21cb843` сама не продолжится: снять с неё блокировку —
запись в прод. Проще после деплоя запустить новый проверочный сбор (нужно
отдельное «да», до $5).

## Проверки

- TypeScript core, ESLint изменённых файлов, полный Jest (298 наборов, 3384
  теста), `npm run build:workers` — успешно. Новых `*.test.ts` нет.
- 15 офлайн-случаев на настоящем `runHeEngCompanySearchPage` и
  `resolveHeEngRegistryCandidate`: бюджетные вызовы — копия правил
  `supabase/migrations/20261020_0003_he_eng_base_budget.sql` в памяти, Serper —
  поддельный. Медленный ответ (ждали 15 с), обрыв, ответ без цены после двух
  неудач (настоящая цена, счётчик обнулён), три 502 подряд (поиск недоступен,
  больше ничего не отправляется), ответ без `credits` с результатами
  (результаты сохранены), отмена посреди запроса и до отправки, компания из
  реестра без ответа поиска. Во всех случаях блокировки нет, неоплаченных
  записей нет.

Миграций и переменных окружения нет. Выкатывается вместе с остальными
коммитами ENG из `Sergey`.
