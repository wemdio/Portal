# Сохранённые выгрузки B2B-поиска

Изменение ветки `codex/companies-export-reliability`, 2026-10-16. Это описание реализации, не подтверждение её установки в production.

## Причина

Раньше каждый POST скачивания снова выполнял поиск и добавлял `row_count` в учёт лимита до формирования файла. Поэтому повтор XLSX и последующий CSV могли списать один набор несколько раз и вернуть только остаток лимита. Состав экспортов и фильтры не сохранялись. Наблюдавшийся HTTP 200 на XLSX сам по себе не подтверждает сохранение файла браузером; точная причина сбоя на компьютере клиента не установлена.

В дереве ОКВЭД отфильтрованный поиск передавал в обработчик сокращённые ветки вместе с кодами предков. Выбор предка добавлял, например, `01` вместо показанных `01.41` и `01.46`, а сервер закономерно расширял выборку по этому префиксу.

## Поведение

- Обычное скачивание переиспользует последнюю сохранённую выгрузку пользователя с теми же нормализованными фильтрами. Формат не является частью ключа. Смена порядка кодов не создаёт новую выгрузку.
- Для свежих данных есть отдельное действие «Создать новую выгрузку XLSX». Оно сохраняет UUID попытки в браузере до успешного ответа; повтор после ошибки использует тот же UUID. CSV этой выгрузки доступен из истории без дополнительного списания.
- XLSX и CSV формируются из одного массива и записываются в MAIN S3 **до списания**. CSV содержит BOM UTF-8; XLSX сжат. Новая страница скачивает по короткоживущей ссылке с Content-Disposition, без Blob URL. Уже открытая старая страница получает бинарный ответ, как раньше.
- Учёт строк и seen-журнал записываются одной транзакцией. Повтор/одновременный запрос с тем же ключом возвращает победившую запись. При конкурентных новых выгрузках RPC учитывает списания, появившиеся после снимка ledger. Общая квота других инструментов по-прежнему проверяется через `countClientRows`; глобальная межинструментальная блокировка не вводится.
- При неопределённом исходе RPC файлы сохраняются: ответ мог потеряться после успешного commit. Следующий запрос восстанавливает результат. Лишние файлы после таких ошибок могут остаться без ссылки; автоматическое удаление здесь не добавлено.
- История показывает последние 10 новых сохранённых выгрузок. Старые записи учёта не приобретают файлы задним числом. Обычный POST находит подходящий сохранённый экспорт и за пределами этих 10 записей.
- Все чтения ограничены `user_id` из авторизации. Оплатный гейт сохранён. Повтор доступен при нулевом остатке строк; подписка должна давать доступ к инструменту.
- Выбор через поиск ОКВЭД добавляет только показанные совпадающие ветки. Снятие дочернего кода убирает покрывающих его предков, сохраняя остальные ветки. Старые сохранённые фильтры с широкими кодами не переписываются: их первоначальное намерение восстановить нельзя.

## Хранение и выпуск

Нужна миграция основной Portal DB `20261016_0001_companies_search_saved_exports.sql`, затем код приложения. Миграция добавляет nullable-поля к существующему ledger и RPC только для `service_role`; старый код продолжает работать с прежними столбцами. Новый код требует миграцию и уже используемый приложением MAIN S3. Никаких новых секретов или сервисов не добавляется.

`storage_prefix` указывает на `companies-search/<userId>/<attemptUUID>`, расширения `.xlsx` и `.csv`. У этих объектов нет автоматического срока удаления в данной реализации. Подписанная ссылка действует 10 минут, свежая ссылка выдаётся кнопкой формата. Удалять объекты под этим префиксом без согласованной политики нельзя: они обеспечивают повторное скачивание уже оплаченных строк.

## Проверка

Локально, без production-записей:

- 9 952 синтетические строки: XLSX повторно открыт, CSV разобран, все 16 полей каждой строки совпали, ИНН с ведущими нулями и кириллица сохранены.
- Реальное дерево ОКВЭД: поиск по каждому числовому коду, выбор `01.41` + `01.46` через родительский checkbox, снятие ветки внутри целого раздела, удаление чипа.
- PGlite: применение миграции и повторное применение, идемпотентность, квота при пересечении запросов, сохранность прежних записей seen-журнала, откат всего списания при ошибке журнала, права RPC.
- API с локальными заменами авторизации/S3/поиска и настоящим SQL RPC в PGlite: одновременные форматы, повтор при исчерпанном лимите, сбой поиска/формирования XLSX/загрузки, потеря ответа после commit, разделение пользователей, совместимость бинарного ответа старой страницы.
- Существующие тесты тарифа и миграций, TypeScript API/страниц, ESLint изменённых файлов.
- Chromium: выбор двух веток ОКВЭД, оба скачивания, история после перезагрузки, скрытие устаревшего результата при смене фильтров, сохранение ключа неудачной новой попытки, desktop/mobile.
