# «Рассылка»: ящики Google Workspace без паролей

Инструкция на один раз. После неё портал сам видит все ящики Workspace и
отправляет с них письма — пароли приложений не нужны, заходить в аккаунты не
нужно, новые ящики домена подхватываются кнопкой.

## Зачем

Пароль приложения Google создаёт только владелец ящика, зайдя в свой аккаунт и
включив двухэтапную аутентификацию. На двух сотнях аутрич-ящиков это двести
заходов руками, и при каждой новой партии — заново.

Альтернатива — служебный аккаунт с делегированием на домен: админ Workspace
один раз разрешает нашему служебному аккаунту работать от имени пользователей,
после чего портал перед каждым входом в ящик берёт у Google ключ на час именно
на этот адрес. Пароля у такого ящика нет вовсе, хранить нечего.

Третий вариант — SMTP-релей по IP — сознательно не используем: он умеет только
отправлять, ответы читать нечем, а без ответов холодный аутрич бессмыслен.

## Что сделать в Google (нужен супер-админ Workspace)

1. **Google Cloud Console** → проект (любой, можно новый) → «APIs & Services» →
   включить два API:
   - **Admin SDK API** — чтобы читать список ящиков;
   - **Gmail API** — чтобы работать с почтой.
2. Там же → «IAM & Admin» → **Service Accounts** → создать служебный аккаунт →
   вкладка «Keys» → «Add key» → **JSON**. Скачается файл с `client_email` и
   `private_key` — это то, что нужно порталу.
3. В карточке служебного аккаунта скопировать **Unique ID** (он же Client ID,
   длинное число).
4. **admin.google.com** → Безопасность → Доступ к данным → **Управление
   делегированием на уровне домена** → «Добавить» → вставить Client ID и ровно
   два разрешения через запятую:

   ```
   https://www.googleapis.com/auth/admin.directory.user.readonly
   https://mail.google.com/
   ```

   Урезанный `gmail.send` для SMTP не подходит: Google его не принимает.

## Что прописать на серверах

Ключ из JSON кладётся одной строкой: реальные переносы заменяются на `\n`.

**Портал** (139.60.162.24, `.env` стека портала) — нужен для кнопки «Загрузить
из Google Workspace»:

```
SENDER_GOOGLE_SA_EMAIL=portal-sender@<проект>.iam.gserviceaccount.com
SENDER_GOOGLE_SA_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n
SENDER_GOOGLE_ADMIN_EMAIL=admin@<ваш-домен>
```

**Sender-хост** (144.31.54.166, `/opt/portal-sender/.env`) — нужен воркеру,
чтобы входить в ящики:

```
SENDER_GOOGLE_SA_EMAIL=...
SENDER_GOOGLE_SA_PRIVATE_KEY=...
```

Адрес админа воркеру не нужен: каталог он не читает.

После правки `.env` обязательно пересоздать контейнер, иначе переменные не
подхватятся:

```bash
docker compose -p portal-sender --env-file .env up -d --force-recreate worker-sender
```

## Как пользоваться

Вкладка «Ящики» → кнопка **«Загрузить из Google Workspace»** (появляется только
когда переменные заданы). Портал читает каталог, пропускает заблокированные и
архивные ящики, остальные добавляет со статусом «Проверяется» — воркер входит в
каждый по SMTP и IMAP и переводит в «Готов».

Кнопку можно жать сколько угодно раз: уже подключённые ящики не задваиваются, а
обновляются и уходят на перепроверку. Новая партия доменов подключается тем же
нажатием.

Ящики с паролями (Maildoso, ZapMail, ручная загрузка файлом) продолжают работать
рядом — способ входа хранится у каждого ящика свой.

## Если не работает

- **«Google не отдал список ящиков: unauthorized_client»** — в админке не выдано
  делегирование или выдано с другими разрешениями. Проверьте шаг 4: Client ID
  должен совпадать с Unique ID служебного аккаунта, а разрешения — с точностью
  до символа.
- **Ящик встал в «Ошибка» с «Google не выдал доступ»** — чаще всего в списке
  разрешений нет `https://mail.google.com/` (только `gmail.send`), либо ящик
  заблокирован в Workspace.
- **Кнопки нет на экране** — не заданы переменные на портале; воркеру они не
  помогут, кнопка смотрит на окружение самого приложения.
- **Письма уходят, ответы не читаются** — у ящика выключен IMAP (в Gmail:
  Настройки → Пересылка и POP/IMAP) либо админ выключил IMAP на весь домен.
