# Общий каталог компаний Яндекс.Карт

Каталог хранится отдельно от результатов конкретного запуска парсера. Ключ записи —
стабильный ID организации из выгрузки Яндекс.Карт, поэтому повторное появление компании
в региональной и рубричной разбивке не создаёт новую карточку. Непустые поля объединяются,
а источники и число появлений сохраняются для контроля качества импорта.

## Что лежит в базе

Первичный импорт выполнен 07.08.2026 из `G:\Полная база Яндекс карт для сайта`.

Строк из файлов вдвое больше, чем организаций, потому что источник содержит две полные
нарезки одних и тех же данных: `Разбивка по регионам` и `Разбивка по рубрикам`. Компания
с несколькими рубриками лежит в каждой из них.

Заполненность: страна — 100%, ссылка на карточку — 100%, без города и региона осталось
4 456 записей (0,045%).

## Откуда берутся страна, город и ссылка

В 13 269 xlsx-файлах **нет колонки «Страна»** — она есть только в 4 корневых CSV
(Абхазия, Армения, Молдова, Таджикистан). Импортёр достаёт страну из пути файла:

```
Разбивка по регионам\<Страна>\<Регион>\<Город>.xlsx
Разбивка по регионам\<Страна>\<Город>.xlsx
Разбивка по рубрикам\<Страна>\<Рубрика>\<Подрубрика>.xlsx
```

Колонка из файла всегда приоритетнее пути — путь только закрывает пробелы. Файл, названный
так же, как его папка (`Алтайский край\Алтайский край.xlsx`), — это сводка региона:
город из него не выводится, иначе «Алтайский край» попал бы в список городов.

Ссылки на карточку в xlsx тоже нет — она собирается из ID: `https://yandex.ru/maps/org/<id>`.
Яндекс открывает организацию по одному идентификатору, слаг не нужен.

## Поиск из интерфейса

Выбор страны, города и рубрики обслуживается каталогом и **не обращается к Яндексу**.

Полей «URL поиска» и «организаций на 1 запрос» в форме больше нет: запуск — это один
запрос к своей базе, а не тысячи заходов в выдачу, поэтому урезать его незачем. Оператор
забирает всё, что нашлось, до серверного потолка `CATALOG_MAX_RESULTS` (50 000 строк за
запуск); в кабинете объём остаётся полем, потому что списывается с тарифа клиента.

Живой парсинг по URL никуда не делся на стороне воркера — им пользуются
reputation-finder и гипотезы, — просто в этой форме его больше не завести.

Списки в форме строятся из справочников `yandex_maps_catalog_places` (4 777 записей) и
`yandex_maps_catalog_rubrics` (2 628), которые пересчитываются из самого каталога
функцией `yandex_maps_catalog_refresh_dictionaries()`. Благодаря этому на экране не может
появиться город или рубрика, за которыми в базе ничего нет.

Поиск сверяет выбранное место **и с городом, и с регионом**: в выгрузках Яндекса города
федерального значения (Баку, Москва) часть организаций держат на уровне региона с пустым
городом, и фильтр только по городу терял бы их десятками тысяч.

### Как устроен выбор мест и сфер

Списки занимают весь верх формы двумя высокими колонками, потому что выбирать
приходится из тысяч пунктов: 4,8 тыс. мест и 2,6 тыс. рубрик. На широком экране пункты
раскладываются в две-три колонки, длинный хвост догружается кнопкой, а не прячется
за жёстким лимитом отрисовки.

| Что | Зачем |
|---|---|
| «Весь регион» в заголовке группы | Кладёт в запрос **один** регион вместо сотен городов. Поиск сверяет и с `city`, и с `region`, поэтому так забираются и организации региона без города |
| Чипы выбранного | Выбор виден и снимается по одному; раньше о нём говорил только счётчик |
| «Только с контактами» | Прячет рубрики, где телефона и сайта нет ни у кого: скамейки (554 тыс.), детские и мусорные площадки, велопарковки. Порог — 15% организаций с контактом |
| Процент у рубрики | Доля организаций с телефоном, сайтом или почтой — из `with_contacts` справочника |
| Быстрый выбор сферы | 14 крупнейших рубрик, у которых есть с кем говорить, кнопками над списком |
| Сортировка и «показать выбор» | По охвату, по алфавиту, по доле контактов; отдельный режим — показать только выбранное |

Массовый выбор рубрик ограничен 50 пунктами: каждая рубрика добавляет в условие
`like '%…%'` по двум колонкам, и «выбрать все 2 600» превратилось бы в запрос, который
база не досчитает. Города сверяются равенством по индексу — там потолка нет.

### Почему функции поиска собирают запрос текстом

`yandex_maps_catalog_search` и `yandex_maps_catalog_count` формируют условия через
`format('%L')` и выполняют `execute`. Это не небрежность, а замер: вариант с постоянным
набором условий вида «параметр пуст ИЛИ совпадает» шёл 11 секунд, тот же запрос
с подставленными значениями — 1 секунду. Такая дизъюнкция неиндексируема, база обязана
проверить каждую из 9,9 млн строк. Значения экранируются, подстановка кода невозможна.

## Фоновое пополнение новыми организациями

Механизм ищет **новое**, а не освежает старое.

1. Из очереди `yandex_maps_catalog_discovery_queue` берётся пара «место × рубрика».
2. Делается обычный поиск по Яндекс.Картам, собираются ссылки выдачи.
3. ID организации виден прямо в ссылке — известные отсеиваются запросом к своей базе,
   без обращений к Яндексу.
4. Карточки открываются **только у новых**, результат пишется в каталог.
5. Пара возвращается в очередь: нашлось новое — через 14 дней, пусто — через 60.

Очередь заполняется `yandex_maps_catalog_seed_discovery_queue(мест, рубрик)`;
по умолчанию 200 крупнейших мест × 100 рубрик = 20 000 заданий.

**Приоритет — размер места × размер рубрики с поправкой на долю организаций с контактами.**
Поправка обязательна: «Скамейки» — вторая по величине рубрика каталога (554 тыс.), но
телефон есть у 20 записей из них, то есть у 0%. Мусорные площадки — 0%, велопарковки — 0%,
детские площадки — 1%. Против 86% у «Бизнеса» и 83% у «Красоты». Без поправки обход начал
бы с объектов карты, бесполезных для аутрича.

Пропавшие организации помечаются попутно и бесплатно: если выдача оказалась исчерпывающей
(Яндекс вернул меньше, чем запрошено, — значит показал всё), то наши организации этого
города и рубрики, которых в списке нет, получают `missing_streak + 1`. `closed_suspected_at`
ставится после двух промахов подряд — один ничего не доказывает.

Ожидаемый объём — **сотни новых организаций в сутки, не тысячи**: база залита свежая, и
почти всё, что Яндекс показывает, в ней уже есть. Дневной потолок обращений — 15 000,
но упирается механизм не в него, а в то, сколько реально открылось нового.

### Переменные окружения

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `YANDEXMAPS_CATALOG_DISCOVERY_DAILY_LIMIT` | 15000 | Дневной потолок обращений |
| `YANDEXMAPS_CATALOG_DISCOVERY_MAX_LINKS` | 250 | Ссылок за один поиск |
| `YANDEXMAPS_CATALOG_DISCOVERY_CHUNK_SIZE` | 5 | URL на запрос к сервису парсинга |
| `YANDEXMAPS_CATALOG_DISCOVERY_STALE_MINUTES` | 120 | Через сколько зависшее задание вернуть в очередь |

## Повторный импорт снапшота

```powershell
cd G:\PycharmProjects\Portal\app
npm run build:yandex-maps-catalog
```

Запуск через обёртку, которая сама перезапускает импорт с контрольной точки при падении.
Строка подключения передаётся параметром и в файлы не пишется:

```powershell
.\scripts\yandex-maps-catalog\run-full-import.ps1 -DatabaseUrl "<URL основной БД>"
```

Импорт пишет контрольную точку по файлам, поэтому после падения продолжает с нужного
места, а не перечитывает миллионы строк. Продолжение вручную — флагом `-Resume`.

Заливка идёт около 4 часов и упирается в скорость чтения xlsx. Строку подключения лучше
брать на ту же машину, где база: заливка в облачный Postgres через домашний канал шла
в 15 раз медленнее.

После импорта обязательно пересчитать справочники, иначе форма покажет старые списки:

```sql
select * from public.yandex_maps_catalog_refresh_dictionaries(20);
select public.yandex_maps_catalog_seed_discovery_queue(200, 100);
```
