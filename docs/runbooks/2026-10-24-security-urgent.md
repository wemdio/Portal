## Шаг A. Закрыть PostgREST Instantly от интернета (пункт 1)

Портал и воркеры ходят к нему из Docker-контейнеров на этом же сервере, поэтому закрываем
порт для всех, **кроме внутренних адресов Docker** (`172.16.0.0/12`). Код не меняется.

```bash
iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 35401 --ctdir ORIGINAL ! -s 172.16.0.0/12 -j DROP
```

Если в шаге 0 среди подключений были внешние адреса, которые должны работать (например, хосты
«Рассылки» 144/77), разрешите каждый **после** команды выше (`-I` ставит правило над DROP):

```bash
iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 35401 --ctdir ORIGINAL -s <адрес> -j RETURN
```

Проверка:
1. С внешнего компьютера `curl -m 5 http://139.60.162.24:35401/` — теперь таймаут.
2. В портале открыть экран, который читает Instantly (например «Автоотчёты» → список кампаний,
   кабинет клиента → «Кампании») — данные грузятся.

Откат: та же команда с `-D` вместо `-I`.
Чтобы правило пережило перезагрузку: `netfilter-persistent save` (пакет `iptables-persistent`).

Позже (не срочно) правильнее перевести PostgREST на роль без прав и ключ — тогда открытый
порт перестанет быть опасным сам по себе.

## Шаг B. Включить проверку подписи у Telegram-ботов портала (пункт 3)

Порядок важен: сначала перерегистрировать вебхуки (они получат секрет), потом включить проверку.
Если сделать наоборот — боты перестанут отвечать.

1. Войти в портал сотрудником, открыть консоль браузера (F12) и выполнить:
   ```js
   const k = Object.keys(localStorage).find((x) => x.endsWith('-auth-token'));
   const t = JSON.parse(localStorage[k]).access_token;
   for (const p of ['/api/telegram/agent/register', '/api/telegram/client-replies/register']) {
     console.log(p, await (await fetch(p, { method: 'POST', headers: { Authorization: 'Bearer ' + t } })).json());
   }
   ```
   В обоих ответах должно быть `telegram_response.ok: true`.
2. На 139 добавить в `/home/Portal/prod/.env` строку `TELEGRAM_WEBHOOK_SECRET_ENFORCED=1` и пересоздать портал:
   ```bash
   cd /home/Portal/prod && docker compose -p portal -f docker-compose.prod.yml up -d --force-recreate --no-deps portal
   ```
3. Проверка: написать Telegram-агенту и боту ответов клиентам — оба отвечают.

Откат: убрать строку из `.env` и снова пересоздать портал.
