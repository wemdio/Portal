# Vertical Engine v2 — план cutover (v1 → v2)

Дата: 2026-08-26. Владелец: Sergey. Статус: план (реализация после звонка).

## Цель

Переключить внутренних специалистов с v1 на v2:
- **v2** — видимый и основной для новых прогонов.
- **v1** — read-only архив существующих прогонов + баннер «перейдите в v2».
- **ENG** (`/client/eng`) — НЕ трогаем: backend v1 (`he_*`) остаётся live.

## Согласованные решения

1. **Матчинг «сайт уже прогоняли в v1»** — по **нормализованному домену** `website_url`.
2. **Блокировка в v2** — **явное предупреждение** (не глухой запрет): «этот сайт уже прогоняли в v1», требует осознанного подтверждения, случайно не прокликается.
3. **ENG не трогаем** — `/client/eng` продолжает работать через `he_*`.
4. **v1 read-only** — границы гибкие, главное не сломать ENG.

## Решение разграничения «внутренний vs ENG» (найдено)

- Признак — **роль создателя**: `he_projects.created_by → profiles.role`.
  - `role = 'client'` → ENG-прогон (создан через `/client/eng`, `requireClientAuth`).
  - `role ∈ INTERNAL_ROLES` (technician/manager/director/admin/sales/marketer/lead) → внутренний прогон.
- Надёжнее `market`/`autopilot`: ENG всегда `market='us'`, но и внутренний специалист может гнать US-рынок (`market='us'`) — поэтому `market` не различает контур, а роль — различает.
- Готовые хелперы: `isInternalRole()` / `isClient()` в `app/src/lib/roles.ts`.
- SQL-маппинг: `join profiles p on p.id = hp.created_by where p.role <> 'client'` → множество внутренних прогонов, по которым сверяем домен для блокировки дублей.
- Нюанс: `he_projects.created_by` nullable — строки с `created_by IS NULL` (старое легаси) считать внутренними (консервативно) либо пометить «неизвестно» и не блокировать.

## Двухфазный порядок

**Phase A — без запретов (сначала):**
1. Деплой миграций (#6 base-per-hypothesis, #12 fix collecting unique).
2. Сквозной прогон VBI в v2 (проверка фиксов Ани #1–#9).
3. Сделать v2 видимым (навигация/меню; сейчас — direct URL only).

**Phase B — переключение:**
4. v1: баннер «перейдите в v2» + блок новых прогонов (только внутренний контур `/tools/hypothesis-engine`).
5. v2: проверка по нормализованному домену + явное предупреждение при дубле с v1 (внутренние прогоны).
6. v1 read-only для существующих: просмотр + экспорт базы/цепочки; выключить всё, что создаёт новые данные.

## Не сломать ENG

- `/client/eng` и его backend (`hypothesisEngine`, `he_*`, `HE_MODEL_*`) остаются нетронутыми.
- Любое ограничение в v1 касается **только внутреннего** `/tools/hypothesis-engine`.
