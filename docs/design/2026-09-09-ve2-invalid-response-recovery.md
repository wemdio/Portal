# VE2: восстановление VBI после invalid_response

## Инцидент и воспроизведение

После production-сбора VBI база `2ae93e75-2241-4d22-aea4-43f6418dda28` завершилась ошибкой первичной проверки релевантности: 2000 компаний, 40 технически проверены, 0 готовых контактов. Отчёт расходов за этот сбор: Requesty **$0.03831755**, Serper **0 credits**, финансовый журнал полный. Цена готового контакта не определена при нулевом результате.

Из сохранённого резерва и фактов источников восстановлен пакет из 20 компаний. Его batch hash `d9d312c24d8f8da964405c74afc94ccc9ef0852573e3e73e462b55a6105595a6` и context hash точно совпали с checkpoint production. Получены только read-only снимки; сбор, очередь и production-данные не менялись.

Исторический ошибочный ответ модели не сохранялся, поэтому его конкретную ошибку нельзя доказать. При новых вызовах на том же пакете воспроизведены неполный список (3 вместо 20), пустые цитаты и лишнее решение (6 вместо 5). Повторный ответ с 20 решениями и пустыми цитатами воспроизводимо отклоняется прежним кодом. Простое повторение запроса также иногда проходит, поэтому один успешный вызов не подтверждает устойчивость.

## Поведение после исправления

- Для проверенного GPT-4o mini, включая короткое имя и датированные варианты, передаётся строгая JSON-схема Requesty: размер пакета, диапазон индексов, поля и типы. Это opt-in только первичной/сайтовой классификации VE2; другие роли и пользовательские модели сохраняют прежний режим. Формат соответствует [документации Requesty](https://docs.requesty.ai/features/structured-outputs). Локальная проверка полноты, уникальности индексов и доказательств остаётся обязательной.
- Пустая цитата отбрасывается существующей проверкой доказательств. Она не подтверждает решение и не допускает компанию: неподтверждённый статус идёт в автоматическую проверку сайта. Объяснения принимаются до 2000 символов и сокращаются до 400, как уже делала смысловая проверка.
- Повтор получает целый предыдущий ответ до 32 000 символов; более длинный ответ полностью опускается. Инструкция требует весь результат по исходным строкам.
- После двух невалидных ответов большой пакет разбивается на группы по пять, с одной schema-попыткой на группу. Максимум для исходных 20 — два больших и четыре малых ответа классификатора; обычные сетевые повторы и отдельные смысловые проверки учитываются дополнительно. Первая ошибка малого пакета останавливает дальнейшие вызовы. Успешные группы сохраняют checkpoint и не оплачиваются заново при продолжении.
- Ошибки оплаты, конфигурации, отмены и записи checkpoint не запускают восстановление формата. Диагностика пишет только тип ошибки, причину завершения и ограниченные коды/пути схемы, без текста компаний, цитат и ответов модели.

Версия контекста сохранена: правила допуска не менялись, поэтому корректные оплаченные решения повторно проверять не требуется. Изменения находятся только в VE2; backend ENG не менялся.

## Проверка

Сохранённый ошибочный ответ: старый код — `invalid_response`; новый — 20 технически проверенных компаний, все `needs_review`, без допуска по пустым или выдуманным цитатам. Внешний офлайн-набор проверяет также восстановление, продолжение с checkpoint, остановку расходов, отмену, строгую схему и сохранение JSON mode для пользовательской модели. Постоянный CI-набор не расширен.

Живой вызов окончательного кода на полном пакете: **20/20**, без ошибки, **20 needs_review**, Requesty **$0.00126765**. Сайтовые запросы в этом изолированном тесте отключены, поэтому результат не является 20 готовыми контактами и не подтверждает завершение всей production-базы.

Живой тест восстановления: два сохранённых неполных ответа воспроизведены локально без оплаты, затем выполнены четыре настоящих вызова GPT-4o mini на группах по пять и два вызова GPT-5 mini для независимой смысловой проверки. Итог **20/20**, без ошибок, **5 relevant / 15 needs_review**; подтверждены исходные категории «Косметология»/«Пластическая хирургия». Стоимость этого теста **$0.00403855**. Различие с полным пакетом отражает вариативность классификатора; это не метрика всей базы. Статус relevant также не заменяет пригодность почты и остальные условия готового контакта.

Все диагностические модельные вызовы этого исправления, включая неудачные промежуточные прогоны: **14 HTTP / $0.01206985** по `usage.cost`, неизвестных сумм нет. Serper не вызывался. Это отдельные расходы разработки; они не входят в приведённые выше $0.03831755 production-сбора. Один промежуточный прогон был остановлен локальным ограничением на модель смысловой проверки; следующий прогон завершён с явно ограниченным доступом к обеим моделям.

Валидация окончательного изменения: 56 существующих Jest-тестов, 19 внешних сценариев gate, 11 внешних сценариев LLM, строгая проверка TypeScript, ESLint и сборка VE2 worker. Внешние проверки работают без сети, не расширяют постоянный набор тестов и сохраняют доказательство старого сбоя на замороженном ответе.

Артефакты с запросами, ответами, расходами, fixture и внешними проверками сохранены локально в `~/.codex/handoffs/ve2-vbi-invalid-response-20260909/` с ограниченными правами. В git не включены исходные строки и конфигурация провайдера.

## Применение

Обычный redeploy приложения/VE2 worker после интеграции коммита выполняет пользователь. Затем нужна повторная автоматическая проверка сохранённой базы VBI; повторный первичный сбор для проверки этого исправления не нужен. До этого production остаётся на прежнем коде, а исправление подтверждено локальными и изолированными модельными тестами.
