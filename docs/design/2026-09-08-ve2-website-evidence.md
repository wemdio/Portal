# VE2: поиск и чтение сайта для проверки релевантности

Изменение относится только к внутреннему Vertical Engine v2. ENG и `he_*` не меняются.

Ранее проверка использовала только первый домен из ячейки и начало главной страницы плюс `/uslugi` или `/services`. Доступное направление могло находиться на другом домене той же компании или глубже на странице.

Теперь reader:

- рассматривает до трёх допустимых доменов из исходной ячейки;
- при известном ИНН использует только сайты с подтверждением этого ИНН как оператора в футере, реквизитах или юридическом разделе; посторонние/несколько ИНН требуют уточнения;
- объединяет проверенные исходные домены одного ИНН, не смешивая факты неподтверждённых сайтов;
- при отсутствии пригодного подтверждённого сайта делает один запрос Serper по точному ИНН и проверяет найденные страницы тем же reader;
- исключает известные каталоги и платформы; сниппеты поиска служат только для нахождения ссылок и не становятся доказательствами;
- выбирает тематические выдержки из полного текста и до двух страниц услуг по реальным ссылкам своего origin;
- сохраняет уже подтверждённые данные, если дополнительное чтение не успело завершиться.

Без ИНН сохраняется прежнее допущение о первом сайте из входных данных: переход на другие домены и поиск не выполняются. Поэтому «связь сайта с юрлицом подтверждена» нельзя утверждать для такого случая. Пустой результат проверки не означает нерелевантность компании.

## Ограничения и конфигурация

Используется существующий `SERPER_API_KEY` и общий `search/serperClient`; отсутствие ключа, сбой поиска или исчерпание кредитов сохраняют компанию на уточнение. Оплата поиска отдельно от Requesty. Текущий общий адаптер возвращает пустой список при ошибках, поэтому состояние баланса следует проверять в Serper, а не выводить из нулевой выдачи.

На компанию: до 10 логических чтений страниц, до трёх перенаправлений на страницу, один поисковый запрос, общий таймаут 25 секунд, таймаут страницы 5 секунд, ответ до 1 MiB, итоговый текст до 6000 символов. Gate по-прежнему ограничивает website-review 30 компаниями за вызов. Все сетевые переходы сохраняют проверку публичного адреса, закрепление IPv4, ограничения origin/домена и TLS; HTTP downgrade запрещён.

Каталоги, неоднозначные группы юрлиц, сайты только на JavaScript, реквизиты только в PDF, TLS-ошибки и сведения за пределами лимита могут остаться на уточнение. Совпадение ИНН в карточке каталога само по себе не подтверждает оператора сайта.

## Повторное выполнение

`website_evidence.reader_version = 1` отличает новые проверенные извлечения. Старые результаты, основанные на website evidence без этой версии, переводятся на уточнение и перечитываются; оплаченный первоначальный просмотр не повторяется. Старые непроверенные pending-выдержки не используются. При продолжении нового checkpoint готовый результат и завершённый поиск не повторяются автоматически.

Наличие кода не запускает перепроверку сохранённых баз или production-деплой. Дальнейший запуск и выпуск выполняются отдельно согласно AGENTS.md.

## Проверка 8 сентября 2026

Четыре существующих набора Jest (40 проверок), ESLint, строгая типизация затронутых модулей и проверка diff прошли. Временные проверки без сети покрыли поиск фрагментов в конце длинной страницы, несколько ИНН, реквизиты оператора, отказ каталогам, несколько доменов, лимиты, отмену, сохранение частичных данных и обновление старого checkpoint. Новые постоянные тесты не добавлялись.

Новая выборка зафиксирована до разметки: 24 компании без пересечений с прежними 40, по 8 вероятных косметологий, стоматологий и сложных случаев. Независимый обзор ИИ по источникам: 9 relevant, 9 irrelevant, 6 unknown. Это не человеческая экспертная разметка и не случайная репрезентативная выборка всей базы.

Живой Serper ответил `400 Not enough credits` на все 22 запроса. Поэтому восстановление отсутствующих сайтов не прошло приёмку. Чтение дало пригодные данные только для 2 компаний. Финальный GPT-4o-mini: 0 relevant, 1 irrelevant, 23 needs_review, 0 технических ошибок; все 9 подходящих остались недопущенными. В одном случае модель собрала цитаты из разных фрагментов, и строгая проверка evidence сохранила неопределённость. Нулевые ложные допуски при нуле допусков не доказывают точность фильтра.

В локальной среде используется синтетический DNS. Для реальных страниц применён отдельный публичный HTTP-recorder через trusted `fetchPage` DI; parser, выбор страниц и gate — производственные функции. Это не приёмка production DNS, закреплённого IPv4, сетевого транспорта или развёрнутого worker. Для завершения проверки нужны рабочий баланс Serper и новый прогон; текущий результат не основание для массового запуска.
