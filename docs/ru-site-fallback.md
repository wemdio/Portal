# Резервное чтение сайтов русских вертикалей

Внутренний Vertical Engine v2 передаёт русским заданиям конструктора явную
настройку чтения сайтов. Язык задания остаётся `ru`; обход ENG contact-first и
таблицы `he_*` для этого не используются. Обычные вызовы других инструментов
без настройки сохраняют прежний путь.

Порядок: обычный HTTP → изолированный Chromium → необязательный TinyFish Fetch.
Браузер дочитывает только успешную пустую страницу/JavaScript-оболочку.
Наличие пригодного адреса на исходной странице исключает лишний вызов.
Ошибки доступа, CAPTCHA, вход по паролю, частные адреса, неизвестный исход и
переход на чужой сайт не разрешают внешний резерв. Исходный HTTP-результат и
буквально найденные в нём адреса сохраняются при отказе резерва.

## Когда разрешён TinyFish

Обычная русская партия использует только собственный браузер. TinyFish получает
разрешение от родительского движка после завершения обычной партии, когда:

- число готовых контактов после проверки почты, релевантности и названий ниже
  цели базы;
- нет незавершённых партий, проверок или ошибки сервиса;
- обычные источники действительно исчерпаны либо штатная оценка источника
  подтвердила низкий выход двух окон минимум по 50 компаний.

Операции с зафиксированным составом источников (исправление географии,
обновление ресторанного источника, продолжение known-websites) новый резерв
не открывают. Неопределённая релевантность результата TinyFish остаётся в
резерве и не останавливает обычный продолжаемый сбор; сохранённая остановка
по низкому выходу остаётся действующей, пока цель не достигнута.

Резерв повторно читает сайты уже известных компаний без почты и, если отдельно
включён Search, ищет дополнительные сайты по запросам исходной гипотезы.
Search возвращает страницы, не готовые организации: название подтверждается
на собственном сайте (Organization/LocalBusiness или подтверждённый site name),
а не берётся из заголовка поисковой выдачи. Адреса не генерируются.
На базу допускается одна сохранённая попытка, не более 100 компаний в сумме;
перезапуск воркера продолжает ту же дочернюю задачу. Ранее использованный резерв
той же гипотезы учитывается и при переходе от превью к следующей базе.
Состояние хранится в `collect_info.ru_website_rescue`. Уникальное разрешение
`ve_ru_website_rescue_claims` на пару «проект + гипотеза» не даёт двум базам
открыть резерв одновременно; повтор той же базы возвращает прежний ID.
Удаление базы не открывает попытку заново. Для этого требуется миграция
`20261031_0002_ve_ru_website_rescue_claim.sql`; отсутствие таблицы/ошибка
резервирования пропускают дополнительный резерв.
Пригодные результаты
проходят обычные проверки почты, релевантности и очистки названий. Резерв не
увеличивает бюджет источников или число разрешённых обычных раундов.
Ручной конструктор не может купить TinyFish одним `tinyfish: true`: worker
сверяет дочернюю задачу, исходные строки и сохранённое разрешение с родителем.

## Отдельный бесплатный аккаунт

Все переменные выключены по умолчанию. На всех потребителях нужны одинаковые:

```text
RU_BROWSER_ENABLED=1
RU_TINYFISH_ENABLED=1
RU_TINYFISH_SEARCH_ENABLED=1
RU_TINYFISH_ACCOUNT_ID=<stable-real-quota-account-id>
RU_TINYFISH_API_KEY=<secret-ru-key>
```

Chromium использует существующие `ENG_BROWSER_URL` и `ENG_BROWSER_TOKEN`.
Брокер и runner должны поддерживать закреплённую локаль `ru`: русский клиент
не принимает ответы старого сервиса без подтверждения языка. URL-защита,
изолированная сеть runner, sandbox и лимиты ресурсов не ослабляются.
RU и ENG делят одну браузерную сессию; занятость немедленно возвращает отказ.

RU не использует ключи или пул ENG. Постоянный account ID обозначает реальный
аккаунт квоты; он не меняется при замене ключа. Разные ключи одного аккаунта не
добавляют квоту. Перед Fetch обязательны свежая нулевая цена USD/URL и usage
текущего UTC-дня меньше 1000. Общий RPC v2, введённый миграцией
`20261030_0002_eng_tinyfish_pool_budget.sql`, резервирует до 1000 URL за
скользящие 24 часа на аккаунт и до 120 в минуту суммарно по RU/ENG и всем
воркерам. Неизвестная/ненулевая цена, отсутствие миграции, ключа или квоты
пропускают TinyFish. После попытки Fetch другой ключ не пробуется; бронирование
не возвращается при таймауте. Live rate не является гарантией неизменности
тарифа провайдера между проверкой и запросом.

Search использует тот же отдельный RU-аккаунт, но собственную метрику:
`ru_tinyfish_search_budget` и RPC `ru_tinyfish_reserve_search`, миграция
`20261031_0001_ru_tinyfish_search_budget.sql`. Общие атомарные ограничения —
30 запросов за скользящую минуту, 500 за час и 12000 за 24 часа. Перед каждым
Search проверяются свежий нулевой USD/query тариф и usage текущего UTC-дня
меньше 12000. В справочнике Search описан дневной allowance и возможное
платное продолжение, тогда как pricing обещает отсутствие списаний: поэтому
одного маркетингового обещания недостаточно, оба программных ограничения
остаются обязательными. При неизвестном исходе запрос не повторяется,
Serper/другой платный провайдер вместо него не вызывается. В одном резерве
не более пяти запросов; встроенный параметр Search+Fetch не используется.
Платные Agent и TinyFish Browser API не вызываются.
Отметка бесплатного поиска сохраняется на компаниях резерва, в том числе
после конструктора и при дальнейшей проверке сохранённых результатов.
Для этих компаний relevance-gate может читать уже имеющийся поисковый кэш,
но не покупает Serper при недоступном или неподтверждённом сайте. Настройки
платного поиска остальных обычных компаний сохраняются.
Источники условий: [pricing](https://www.tinyfish.ai/pricing),
[Search reference](https://docs.tinyfish.ai/search-api/reference.md).

Чтение компании ограничено 30 секундами, один резерв страницы — 20 секундами,
весь вызов TinyFish — 15 секундами. Неверный ответ или отказ не останавливает
обычную обработку базы. Пропущенные страницы не повторяются автоматически.

## Названия, колонки и проверка

Fetch возвращает HTML, а не новую таблицу. Названия компаний, сайты, ИНН и
происхождение остаются полями исходного источника. Конструктор дополняет только
почту и, по обычной настройке, пустое описание. `siteName` из браузера/Fetch не
заменяет компанию. Сетка RU сохраняет канонические «Компания», «Сайт», «Email»,
«ИНН», «Источник»; обратный импорт сопоставляет заголовки по имени. Очистка
названий и привязка проверки к конкретному адресу выполняются прежними шагами.
Rendered HTML не записывается в строковый кэш как прямой HTTP-ответ. Неудачная
очистка названий оставляет новые строки в непроверенном резерве, сохраняя
прежние готовые контакты и завершённость обычного раунда.
Адреса, буквально опубликованные в успешном прямом HTTP-ответе, сохраняются
и при встроенной CAPTCHA контактной формы. При признаках проверки доступа
renderer/Fetch не включаются, а HTML такой проверки не становится описанием
компании.

Локальные проверки должны включать RU/ENG ветви, отдельные ключи/квоты,
перезапуск сохранённого резерва, кириллицу, ИНН с ведущим нулём, переставленные
колонки, сохранение компании при отсутствующем HTML title, статусы отдельных
адресов, CAPTCHA/403, истечение бюджета и смену фактического URL для
относительных контактных ссылок, а также отбраковку Search-страницы без
подтверждённой компании и повторного домена. Моки транспорта не подтверждают sandbox Linux;
при выпуске нужен штатный acceptance из `deploy/eng-browser/README.md`.

Выпуск, миграция и активация серверных секретов — отдельный разрешённый этап.
Сначала выпускаются совместимые broker/runner и consumers с RU-флагами 0;
после проверок включается браузер, затем отдельный бесплатный резерв. До этого
локальная реализация не означает, что RU-резерв работает на production.
