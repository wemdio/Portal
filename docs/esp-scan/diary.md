## 2026-08-16 — запуск и первый раунд баз

### Контекст и решение

- Заказчик (мы, агентство) имели автоматизацию аутрича через Mailganer и их API
  (`domain-spf-score`), возвращающий score + SPF. Для выхода на англоязычные
  рынки решили делать детект сами — API Mailganer для этой задачи не используем.
- Механика Mailganer реверс-инжинирена ещё до старта: скрипт
  `app/scripts/verify-spf-self-parse.mjs` подтвердил на выборке из их экспорта,
  что score = взвешенная сумма маркеров ESP в v=spf1 TXT-записи домена.
  Воспроизводится локально через `node:dns` — сторонний API не нужен.
- Скоуз: юниверс = `pdl_companies` (19.57M компаний по миру, PDL Free Company
  Dataset, CC BY 4.0); на выходе — CSV-базы, БЕЗ автоаутрича и без записи в прод.
- Всё выполняется локально с ПК; прод-сервер участвует только как read-only
  источник `pdl_companies` (REST GET, 1 запрос / 1000 строк). Никаких вызовов
  «от лица» прода/доменов наружу нет: DNS идёт на публичные резолверы.

### Что построено (коммиты в `engSPF`)

- `cd970ca62` — feat(esp-scan): либа `app/src/lib/espScan/` (словарь ~70 ESP,
  резолвер, скоринг), CLI `app/scripts/espScan.ts`, 18 юнит-тестов,
  `npm run build:esp-scan`.
- `4f418ce8f` — fix: list-filters (rpc возвращает jsonb-объект, не массив) +
  терпеливые ретраи для ночных прогонов.

Скоринг: score дают только marketing-ESP (платформа = 50, automation = 40);
грейды A ≥ 90 / B ≥ 45 / C > 0. SendGrid/Mailgun/SES и корпоративная почта —
информационно, без скоринга (транзакционные письма ≠ рассылки по своей базе).

### Потенциал и остаток

- Осталось в шести странах: 8 009 218; нетронуто (другие страны): 10 194 832.
- Темп ~5 400 компаний/мин → докрутка шести стран ≈ 25 ч, весь мир ≈ 56 ч.
- Прогноз хитов на весь мир: ~600–700k компаний сверх собранных 48.7k.
- Приоритет следующего раунда: добить UK/CA/AU/NL → Германия+Скандинавия+ОАЭ → US.

### Нюансы и уроки

- **Klaviyo почти невидим** (243 хита): шлёт через SendGrid, а SendGrid у нас в
  transactional (без скоринга). Для прицельного e-commerce-сегмента нужно правило
  «SendGrid + retail/e-commerce = сигнал» или отдельный маркер.
- **Сеть до polza-portal.ru флапает** с ПК (connect timeout 10s undici): лечится
  терпеливыми ретраями (уже в коде). Хост дальний, ~800мс RTT.
- **Env-ловушка**: в корневом `.env` `NEXT_PUBLIC_SUPABASE_URL` указывает на
  облачный проект с другим ключом (401); рабочий — `SUPABASE_URL`
  (polza-portal.ru). Скрипт берёт `SUPABASE_URL` первым.
- Transient DNS-ошибки ~1.2–1.5% — домены выпадают из прогона; повторный проход
  тем же фильтром их не подберёт (курсор ушёл). Восстановление: `--reset`.
- Темп режут хвостовые DNS-таймауты: `--concurrency=100` вместо 50 ускорил в ~5 раз
  (с ~500 до ~7 000 строк/мин) без роста ошибок.
- Чекпоинты `.esp-scan/state-*.json` — прогоны прерываемы/продолжаемы per-country.
- SPF-строка лежит в CSV → перескоринг/новую сегментацию можно считать
  пост-фактум по готовым файлам, без повторного DNS-скана.

### Как запускать

```bash
cd app && npm run build:esp-scan
node app/dist/scripts/espScan.cjs --list-filters                     # что есть в базе
node app/dist/scripts/espScan.cjs --country="united kingdom" --limit=300000 \
  --out=esp-base-united-kingdom.csv --concurrency=100                 # скан
# продолжение той же командой подхватит чекпоинт; --reset — начать заново
```
