# Редизайн вкладок «Запуск» и «Библиотеки» в «Нашем автоаутриче»

Дата: 2026-09-24
Инструмент: `/tools` → «Наш автоаутрич» (`polza-ru-outreach`)
Затрагивает: только фронтенд (`app/src/components/polzaRuOutreach/`)

## Зачем

Обе вкладки выросли органически и стали неудобными. Разобранные с заказчиком проблемы:

**Запуск**

1. Форма запуска всегда раскрыта целиком — 12 полей, включая редко используемые
   (мин. сумма госконтракта, выручка от/до, сотрудников от).
2. Нельзя повторить прошлый запуск: параметры вводятся заново, пресетов нет.
3. Непонятно состояние запуска: прогресс — одна строка текста, полосы нет,
   в списке все запуски подписаны одинаково («Запуск на 100»).
4. Форма, список запусков, воронка, фильтры и таблица идут одной простынёй
   сверху вниз — между запуском и разбором результата приходится скроллить.

**Библиотеки**

5. 44 кейса без поиска, фильтров и сортировки.
6. Строка кейса нечитаема: статус, ID, название, лиды и текст письма слиты в одну строку.
   Непроходные кейсы (< 8 лидов) неотличимы от рабочих.
7. Четыре библиотеки идут стопкой без навигации — до «Подписей» надо прокрутить все кейсы.
8. Форма редактирования раскрывается внутри списка и выталкивает его вниз;
   15 полей в два столбца без группировки.

## Ограничение, определяющее палитру

Тёмная тема портала реализована **не** через `dark:`-варианты Tailwind, а через
«мост» в `app/src/app/globals.css`: явный список утилит, переопределяемых под
`html[data-portal-theme='dark'] .portal-shell` (см. блок с 2562 строки). Утилита,
которой в этом списке нет, останется светлой и даст белое пятно на тёмном фоне.

**Правило:** новые цветовые утилиты не вводим. Используем только те, что уже
встречаются в компонентах `polzaRuOutreach`: `bg-white`, `bg-gray-50/100/200`,
`bg-violet-600/50`, `bg-emerald-50`, `bg-amber-100`, `bg-red-50`,
`text-gray-500…900`, `text-violet-700`, `text-amber-800`, `border-gray-200/300`.
Качество достигается компоновкой, типографикой и ритмом, а не новой палитрой.
Утилиты раскладки (`grid`, `flex`, `sticky`, `gap-*`) темы не касаются и свободны.

## Устройство

### Общий каркас

Два новых компонента в `components/polzaRuOutreach/`, используются обеими вкладками.

**`WorkArea.tsx`** — двухколоночная раскладка.
Слева колонка фиксированной ширины 280 px с `position: sticky` (прилипает при
прокрутке), справа рабочая область на остаток. На ширине меньше `lg` (1024 px)
колонки схлопываются в одну: левая превращается в горизонтальную ленту с
прокруткой, правая идёт под ней.

Интерфейс: `{ aside: ReactNode; children: ReactNode }`.
Зависимостей, кроме Tailwind, нет.

**`SidePanel.tsx`** — выезжающая справа панель поверх затемнения.
Закрывается по `Esc`, по клику вне панели и по кнопке-крестику. Фокус при
открытии уходит внутрь панели и не выходит за её пределы, при закрытии
возвращается на элемент, который панель открыл. Прокрутка страницы под
панелью блокируется.

Интерфейс: `{ open: boolean; title: string; onClose: () => void; children: ReactNode; footer?: ReactNode }`.

### Вкладка «Запуск»

`PolzaRuOutreachView.tsx` сегодня — 352 строки, держит и состояние, и всю
разметку. Разбирается на четыре файла; состояние (список запусков, активный
запуск, фильтры, результаты, опрос каждые 5 с) остаётся в `PolzaRuOutreachView`
и передаётся вниз пропсами — это сохраняет существующую логику нетронутой.

**`JobList.tsx`** — левая колонка.
Кнопка «Новый запуск» сверху. Ниже карточки запусков: дата и время, «на N компаний»,
полоса прогресса, бейдж статуса, «готово X из N». Активная карточка подсвечена
`bg-violet-50`. Кнопка удаления и кнопка «Повторить» появляются при наведении.
«Повторить» открывает `LaunchPanel`, заполненную из `job.config`.

Полоса прогресса: трек `bg-gray-200`, заливка `bg-violet-600`, ширина —
`progress_percent`. Для завершённых показываем полную заливку `bg-gray-300`.

**`JobDetail.tsx`** — правая колонка.
Шапка: статус, процент, размер пула, причина остановки, текст ошибки; справа
кнопки «Остановить», «Excel: готовые», «Excel: журнал». Ниже — существующие
`Funnel` и `ResultsTable` без изменений, фильтры по статусу и причине,
пагинация результатов.

**`LaunchPanel.tsx`** — форма запуска внутри `SidePanel`.
Собирается из нынешнего `LaunchForm.tsx`; поля и отправляемый конфиг не меняются.
Разделена на две секции:

- «Основное» (всегда видно): источники компаний, сколько готовых компаний,
  свежесть повода, подпись.
- «Тонкая настройка» (свёрнуто по умолчанию): порог скоринга, мин. сумма
  госконтракта, «брать компании, которые уже выгружались». Блок «размер компаний»
  (выручка от/до, сотрудников от) остаётся условным — показывается только при
  выбранном источнике «общая база», как и сейчас.

Принимает `initial?: Partial<RuOutreachConfig>` — так работает «Повторить».

**Пустое состояние.** Когда запусков ещё не было, вместо двух колонок
показывается одна карточка: что делает инструмент и кнопка «Новый запуск».

### Вкладка «Библиотеки»

**`LibrariesTab.tsx`** (переработанный `Libraries.tsx`).
Слева меню четырёх разделов со счётчиками: «Кейсы · 44», «Утверждения оффера · 6»,
«Подписи · 3», «Файлы сигналов · 12». Справа — только выбранный раздел.
Загрузка данных остаётся как есть (`/libraries` + `/uploads` параллельно).

**Панель над списком.** Поиск (по названию, ID и тексту), фильтр по статусу,
фильтр по отраслевой группе (только для кейсов), сортировка (лиды ↓/↑, название,
дата изменения). Всё считается на клиенте из уже загруженных строк — новых
запросов к API не появляется. Состояние панели живёт в компоненте раздела и
сбрасывается при переключении раздела.

**Строка записи** — две строки вместо одной:

- Первая: название, ID моноширинным, бейдж статуса, бейдж «N лидов».
- Вторая: текст для письма, обрезанный одной строкой (`truncate`).
- Справа: «Изменить» и удаление.

**Непроходной кейс.** Если статус «утверждено», но `leads_count` пуст или меньше 8,
строка получает янтарную полосу слева (`border-l-4 border-amber-100`) и бейдж
«в письма не идёт». Порог 8 — константа `MIN_CASE_LEADS = 8` рядом с фильтрами,
чтобы правило жило в одном месте.

**Пагинация** по 20 записей — уже реализована, переносится как есть.

**Редактирование** переезжает из списка в `SidePanel`. 15 полей группируются:

- «Тексты для писем»: текст для письма, английский текст, английский сегмент, ссылка.
- «Подбор»: отраслевые группы, цепочки, сколько лидов.
- «Служебное»: ID, название, статус, разрешение клиента, кто проверил,
  источник цифр, действует до, заметки.

Группы для «Утверждений» и «Подписей» задаются тем же способом — в описании
полей появляется `group`, а форма просто раскладывает поля по группам.

## Что не меняется

Бэкенд, роуты `/api/tools/polza-ru-outreach/*`, типы в `lib/polzaRuOutreach/`,
`Results.tsx` (`Funnel`, `ResultsTable`), формат конфига запуска и схема БД.
Ни одного нового запроса.

## Проверка

- Фильтрация, сортировка и пагинация выносятся в `libraryFilters.ts` — чистые
  функции без React, покрываются jest-тестами: поиск по трём полям, фильтр по
  статусу и отрасли, сортировка по лидам с пустыми значениями, признак
  «непроходной кейс» на границе 8, пагинация с клампом страницы.
- `npm run typecheck:strict`, `npm run lint`, `npm test` по затронутым файлам.
- Живой просмотр в браузере при поднятом `npm run dev` — с оговоркой: dev-сервер
  тянет `ensureDatabase` и `.env`, локально может не подняться. Если не поднимется,
  об этом говорится прямо, без заявлений о визуальной проверке.

## Сознательно отложено

Таблица кейсов с колонками, галочками и массовой сменой статуса (вариант «В»
при обсуждении). Требует нового метода на бэкенде; выносится в отдельную задачу
после того, как приживётся эта раскладка.
