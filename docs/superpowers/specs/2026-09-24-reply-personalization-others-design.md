# Папка Others в «Персонализированных ответах»

**Дата:** 24.09.2026
**Статус:** согласовано с пользователем в чате 24.09.2026
**Повод:** специалисты разбирают ответы в Instantly Unibox, в том числе в папке
Others. Инструмент показывает только часть писем оттуда, поэтому целиком
заменить Unibox он пока не может.

## 1. Что есть сейчас

- Кампании основного аккаунта Instantly. Список строится из таблицы
  квалификатора `instantly_lead_qualifications`. Обычный сбор ответов читает
  обе папки (`mode: 'emode_all'`), но берёт только письма, которые Instantly
  привязал к кампании. Настоящие ответы в Others почти всегда не привязаны:
  человек ответил с другого адреса или его контакт уже удалили из кампании.
  Такие письма попадают в список только через сторож Others
  (`othersWatchdog.ts`), а он пропускает лишь то, что цитирует наш домен и
  совпадает по теме с письмами кампании.
- Кампании других аккаунтов Instantly. Инструмент читает их напрямую
  (`liveReplyList.ts`) и только из основной папки, потому что без `mode`
  Instantly отдаёт `emode_focused`. Others по этим проектам не видно вообще.
- Ответить на непривязанное письмо через `POST /emails/reply` нельзя: Instantly
  отвечает 400 «not part of an Instantly campaign». Инструмент этот случай не
  обрабатывает, поэтому отправка по «сиротам» из основного списка падает с
  ошибкой.

## 2. Решение (согласовано)

Отдельная вкладка **Others** рядом со списком «Ответы». В ней вся папка Others
по ящикам кампаний проекта во всех аккаунтах Instantly, из которой убраны
только роботы.

Что видит специалист:

- Над списком писем переключатель «Ответы | Others». Вкладка «Ответы» не
  меняется.
- В Others письма, пришедшие в эту папку на ящики кампаний проекта. Сначала
  свежие, по сотне с догрузкой при прокрутке.
- Роботов убираем: отчёты DMARC, уведомления о недоставке и служебные адреса
  (mailer-daemon, postmaster, no-reply и т. п.), а также письма, которые наши
  ящики пишут друг другу. Прогрев от чужих ящиков и спам остаются: их нельзя
  надёжно отличить от живого ответа.
- Письмо открывается в той же правой панели, где есть переписка, черновик ИИ,
  отправка и «Пропустить». Пометки «отправлено» и «пропущено» работают так же.
- Если сторож уже перенёс письмо в основной список, в Others оно видно с тем же
  статусом и тем же черновиком: это одно и то же письмо.
- Поиск. По части адреса, темы или текста поиск идёт по уже загруженным письмам.
  Полный адрес дополнительно ищется в самом Instantly. Кнопок кампаний во
  вкладке нет, потому что письма в Others к кампаниям не привязаны.
- В строке и в шапке письма показываем ящик, на который оно пришло, а не
  кампанию.

Ограничения, о которых пользователь предупреждён:

- Глубина около 30 дней: дольше Instantly не хранит письма в Others.
- Счётчика писем нет, потому что Instantly не отдаёт общее число.
- Ящик, общий для кампаний двух проектов, показывает свои письма в обоих.
- Если человек ответил с другого адреса, наших писем в переписке может не быть.

## 3. Что сознательно не делаем

- Не копируем Others в свою базу фоновым процессом: это круглые сутки
  расходует общий лимит LIST /emails ради того, что открывают изредка.
- Не трогаем квалификатор, сторож и передачу лидов (`leadQualifier.ts`,
  `leadQualificationWorker.ts`, `othersWatchdog.ts`, `handoffSender.ts`,
  `replyIntake.ts`). Правило изоляции из спецификации инструмента от 12.09
  остаётся в силе, поэтому фильтр роботов пишем в модуле инструмента, а не
  импортируем из сторожа.
- Не прогоняем письма Others через ИИ-квалификацию и не шлём по ним алерты.
- Не распознаём чужой прогрев эвристиками: уверенного признака нет, а цена
  ошибки — спрятанный живой ответ.

## 4. Как устроено

### 4.1 Ящики проекта

Кампании проекта берём как сейчас (`getProjectCampaignIds`), аккаунт каждой
кампании — из каталога (`getCampaignCatalog`). Для каждой кампании
`GET /campaigns/:id` отдаёт `email_list` и `email_tag_list`. Большинство
кампаний задают ящики тегами (см. `app/scripts/instantly-dataset/005_*.sql`),
поэтому каждый тег раскрываем через `GET /accounts?tag_ids=<тег>`, как это
уже делает `launchClientProvisioning.ts`.

Результат — для каждого аккаунта таблица «ящик → кампания проекта». Кампания
нужна, чтобы подложить ИИ цепочку писем, которую слал этот ящик. Если ящик
работает в нескольких кампаниях проекта, берём первую по порядку кампаний
проекта. Кэш в памяти — 30 минут на кампанию и на тег. Если по кампании не
удалось получить ящики, остальные показываем и выводим предупреждение.

### 4.2 Чтение папки

Для каждого аккаунта:
`GET /emails?mode=emode_others&email_type=received&eaccount=<ящики через запятую>&sort_order=desc&limit=100`,
`requestPriority: 'interactive'`, `consumer: 'personalization_others'`.
Ящики режем пачками по 50, чтобы строка запроса не стала слишком длинной.
Каждая пачка — отдельная «дорожка» со своим курсором `starting_after`.
Курсоры всех дорожек отдаём клиенту одной непрозрачной строкой, по которой
грузится следующая страница. Клиент склеивает страницы, убирает повторы по id
и сортирует по дате.

`eaccount` принимает список через запятую — так сказано в документации
`GET /api/v2/emails`. Живьём фильтр до этой задачи в коде не использовался:
первое открытие вкладки после выкладки нужно проверить глазами (раздел 6).

Короткий кэш страницы в памяти — 60 секунд, ключ: проект, запрос и курсор.
Кнопка «Обновить» идёт мимо кэша. После отправки или пропуска вкладка не
перечитывает Instantly, а меняет статус письма на месте.

### 4.3 Фильтр роботов

Чистая функция в модуле инструмента. Письмо отбрасывается, если:

1. нет id или адреса отправителя, либо `ue_type` не 2 (не входящее);
2. домен отправителя — наш рассыльный: домены всех ящиков основного аккаунта из
   датасета (`raw_accounts`, кэш 12 часов) плюс домены ящиков проекта. Если
   датасет недоступен, берём только домены ящиков проекта: лучше показать
   лишнее, чем спрятать ответ;
3. локальная часть адреса служебная (та же регулярка, что в стороже Others);
4. тема — DMARC-отчёт (`Report Domain:`).

### 4.4 Номер письма и статусы

Строка Others получает id по правилу: если у письма есть строка квалификатора
(`instantly_lead_qualifications.instantly_email_id`), берём её id, иначе — id
письма Instantly. Так у одного письма в обеих вкладках общий черновик и статус.
Статусы берём как в основном списке (`getLatestDraftStatuses`).

### 4.5 Открытие, переписка, генерация, отправка

`resolveProjectReply` находит письмо по id и после этой задачи понимает ещё
один случай. Если id не из таблицы квалификатора, пробуем письмо во всех
аккаунтах проекта, включая основной. Принимаем его, если кампания письма из
проекта (как сейчас) **или** письмо пришло на ящик проекта. Во втором случае
кампания берётся по ящику, а письмо помечается как «вне кампании».

- **Переписка** письма вне кампании: `GET /emails` с `search=<адрес>`,
  `eaccount=<ящик>`, `mode=emode_all`, без фильтра по кампании и треду. Это всё,
  чем ящик обменивался с этим адресом. Если ничего нет, показываем то, что
  сохранено в самой строке.
- **Генерация** без изменений: бриф, база знаний, цепочка кампании ящика и
  переписка.
- **Отправка** письма вне кампании (Others и «сироты» основного списка с
  `reply_out_of_campaign = true`) сразу идёт новым письмом с того же ящика через
  `sendTestEmail`: тема «Re: …» и цитата письма адресата. Так уже работают
  кабинет клиента и передача лида. Для остальных писем обычный `replyToEmail`,
  а при ошибке «not part of an Instantly campaign» — тот же обход.
  В окне подтверждения для писем вне кампании есть пометка, что ответ уйдёт
  отдельным письмом и в Instantly его видно не будет.

## 5. Ошибки

- Нет брифа — вкладка показывает ту же подсказку, что и «Ответы».
- Instantly не ответил по одному аккаунту или дорожке — показываем остальное и
  пишем, по какому аккаунту письма не загрузились.
- Бюджет LIST /emails исчерпан (`Instantly email read deferred`) — сообщение
  «Instantly сейчас занят, обновите через минуту» без повторов по кругу.
- У проекта не нашлось ни одного ящика — пустая вкладка с объяснением.

## 6. Проверка

- По правилам проекта новых тестовых файлов не заводим. Проверки: `tsc`,
  `eslint` по изменённым файлам и существующие тесты инструмента, если они
  затронуты.
- После выкладки открыть Others у проекта основного аккаунта и у проекта
  другого аккаунта. Сверить с Unibox, что это те же письма тех же ящиков, и
  отправить один тестовый ответ по письму вне кампании.
