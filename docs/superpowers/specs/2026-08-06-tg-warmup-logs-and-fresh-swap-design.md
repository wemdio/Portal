# TG Outreach: детальные логи прогрева + автосвап при полном отвале

Дата: 2026-08-06. Утверждено заказчиком (выбраны варианты «полный объём логов» и
«менять прокси при полном отвале даже свежим»).

## Контекст и повод

Прогон прогрева 04–06.08.2026 (16 аккаунтов, кампания TG_VBI) показал две
проблемы.

**Логи нечитаемы за пределами сегодняшнего дня.** Вкладка показывает только
время (ЧЧ:ММ) без даты и последние 300 строк. Успешные отправки не логируются
вовсе (сообщения видны только в карточке переписки после её завершения), сбой
`account_not_connected` не пишет в журнал ни строчки, а сообщения оборванной
на середине переписки теряются (persist только при успешном финише).

**Плашки `account_not_connected` вводят в заблуждение.** Сорванная переписка
помечает обоих участников: из 2 реально сорванных переписок дня 2 в UI
получилось «4 акка не подрубаются», из которых один (Valdes Fadeevs) был просто
собеседником, и все четверо на день 3 нормально подключены. `last_error` висит
без даты и не отличает виновника от жертвы.

**Автосвап не спасает свежую партию.** Мёртвые порты мобильного пула
(10007/10018/10004 на 103.152.136.70) корректно довели прокси до cooldown, но
свап был пропущен: `account_too_fresh_1.4d`. Гейт `ACCOUNT_FRESH_DAYS = 7`
считает возраст от загрузки аккаунта в портал, поэтому вся свежезалитая партия
первую неделю живёт без автосвапа — ровно тогда, когда прогрев и идёт.

## Решения

### A. Детальные логи прогрева

1. **Запись каждой отправки.** `runWarmupConversation` получает optional
   callback `onMessage(msg, index, total)`. Цикл прогрева на каждую отправку
   пишет info-строку в `tg_outreach_warmup_logs` с `account_id` отправителя:
   `«Иван → Пётр (3/8): „текст…“»` (текст обрезается до ~120 символов).
2. **Не терять отправленное.** Через тот же callback цикл инкрементально
   обновляет `messages` строки переписки в БД после каждой отправки. Упавшая
   на 5-м сообщении переписка сохраняет первые 4; заодно карточка «идёт»
   показывает сообщения живьём, а не после финиша.
3. **Внятные причины сбоев.**
   - `account_not_connected` получает виновника: `error_reason =
     "account_not_connected: <session_name>"` (или оба имени, если не
     подключились оба) плюс warning-строка в журнал с именами пары.
   - Ошибка отправки логируется с именем отправителя, на котором оборвалось.
4. **Журнал за все дни.** API логов получает курсор `before_id` (подгрузка
   старых страниц); UI рисует разделители по календарным датам («5 августа»)
   и кнопку «Показать ещё». Формат времени в строке остаётся ЧЧ:ММ — дата
   видна из разделителя.
5. **Честные плашки аккаунтов.** Статусный роут отдаёт `last_error_at`
   (finished_at сорванной переписки) и атрибутирует
   `account_not_connected: <имя>` только виновнику, а не обоим участникам.
   UI показывает «когда»: `вчера 21:53 · не был подключён`. Прочие причины
   (resolve_failed и т.п.) — поведение как раньше, обоим. Счётчик `failed`
   не меняем: переписка сорвалась у обоих.

Новых таблиц и миграций нет: всё ложится в существующие
`tg_outreach_warmup_logs` (колонки уже есть) и `messages` переписки. Объём
логов при пике: ~64 переписки × ~10 сообщений = ~640 строк/день на кампанию —
для Postgres несущественно.

### B. Автосвап при полном отвале подключения

`handleProxyError` различает стадии по `reason`:

- `connect_timeout`, `tcp_dead` — аккаунт вообще не смог подключиться к
  Telegram (эти reason приходят только из `buildClients`). Это «полный отвал»:
  freshness-гейт (`account_too_fresh`) пропускается. Сидеть на мёртвом порту
  хуже смены IP: аккаунт не греется вовсе.
- `getDialogs_hung`, `reconnect_failed` — аккаунт подключён, но связь
  деградировала. Поведение прежнее: свежим не свапаем.

Остальные гейты (`account_degraded`, дневной лимит 2 свапа) действуют всегда.
`canAutoSwap` получает флаг `fullOutage` и в лог при пропуске/свапе пишется,
по какой ветке прошли.

## Тесты

- `warmupConversation.test.ts`: onMessage вызывается на каждую отправку;
  ошибка отправки доносит частичный прогресс (первые N сообщений) до caller.
- Новые кейсы `canAutoSwap`: свежий + fullOutage → ok; свежий без fullOutage →
  отказ как раньше; degraded + fullOutage → отказ.
- Логи/статусный роут: юнит на атрибуцию виновника в last_error (если для
  роутов есть тестовая обвязка; иначе логика выносится в чистую функцию).

## Вне объёма

- Причина брака портов пула (известный блокер mobpool) — не здесь.
- Перезапуски воркера от сторожевого таймера (пачки «подключён») — отдельная
  известная тема.
