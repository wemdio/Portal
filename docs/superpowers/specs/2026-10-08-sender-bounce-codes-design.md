# «Рассылка» → «Статистика»: блок «Коды отказов»

Дата: 2026-10-08. Решения пользователя: «просто список кодов», блок в «Статистике».

## Зачем

Видеть, какими кодами отвечают почтовые серверы получателей. Коды при самой
отправке почти всегда «250, принято» — их даёт наш же сервис (smtp.gmail.com,
Maildoso), а не получатель. Настоящие статусы приходят позже письмами-отбойниками
(DSN) с полем `Status: X.Y.Z`; за 30 дней их ~190, код находится в 186.

## Что на экране

Блок под «Доставляемостью», берёт период и кампанию из фильтров вкладки.
Таблица в две группы: «Окончательные (5.x)» и «Временные (4.x)»; строка —
код, пояснение одной строкой, число писем, доля от всех отказов.
Отказы без кода — отдельной строкой «Код не найден».
Клик по строке раскрывает до 100 последних писем с этим кодом: дата, кому,
наш ящик, кампания (если письмо из живой кампании), первая строка ответа
сервера; полный текст — по клику.

## Источники и фильтры

Те же, что у `bounce_events` в `sender_stats_dashboard`: отбойники во входящих
(`sender_replies.kind = 'bounce'`) и отказы при отправке
(`sender_messages.status = 'failed'`). Фильтр кампании — так же через
получателя; отбойники без привязки (171 из 193 — адреса удалённых кампаний)
видны только без фильтра кампании.

## Устройство

- Миграция: `sender_bounce_code(text)` — код из текста (Status: → любой
  расширенный → базовый 4xx/5xx), `sender_bounce_codes(since, campaign)` —
  счётчики, `sender_bounce_code_events(code, since, campaign, limit)` — письма.
- API: `GET /api/tools/sender/stats/codes?period&campaign[&code]`.
- Пояснения кодов — `lib/sender/bounceCodes.ts` (точные коды, затем по классу).
- UI: `components/sender/BounceCodes.tsx`, подключён в `StatsTab`.

Тестов не добавляем (правило проекта). Разрезов по ящикам/сервисам и алертов нет.
