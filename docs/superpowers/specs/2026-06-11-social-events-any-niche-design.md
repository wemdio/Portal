# «Соцсети» + «События» — рабочие на любой нише

Дата: 2026-06-11
Статус: дизайн согласован, переходим к плану
Источник: фидбэк по выгрузке `сигналы-11-06-2026.xlsx` (66 строк, ниша — маркетинг/B2B-агентства).

## Контекст и проблема

Из всех сигналов в выгрузке реально сломаны **два**: «Соцсети» и блок «События»
(Открытие/Ребрендинг/Ремонт/География). Остальные (Стек, Клиенты, Кейсы, Цены, Найм,
Интеграции, Последний пост) заполняются на 60–90% и от ниши не зависят — их не трогаем.

Подтверждённые причины (разбор xlsx + код + живое скачивание сайтов):

1. **«Соцсети» пустые у 23/66.** Разбивка:
   - ~8 строк — это вообще не компании (в «Site» лежат `rbc.ru`, `vc.ru`, `rutube.ru`,
     `twitter.com`, `vk.com`, `ru.linkedin.com` — главные страницы площадок; «Company» =
     заголовок статьи). Качество входного списка, не парсера.
   - ~13 строк — реальные компании, сайт открылся (Стек/Профиль заполнены), но соцсетей в
     HTML нет. Скачал как парсер (lidorium.ru, syntonic.ru, easycalls.ru, komus-contact.ru,
     saburov.team, calltell.ru): ноль ссылок на соцсети даже на `/contacts`. Иконки в подвале
     **инъектируются JS** в браузере. `extractSocialMedia` читает статический HTML; Playwright
     включается только когда HTTP вернул пусто — а тут HTTP вернул страницу, значит браузер не
     запускается → JS-иконки не видим.
   - 2 строки — сайт не открылся (arendarop.ru, onlanta.ru).

2. **«Соцсети» шумные там, где заполнены (43/66).** `extractSocialMedia` обходит **все** `<a>`
   страницы без фильтра «компания/личное/бот/чужое»:
   - боты: `t.me/adratings_bot`, `…/ColdySupport_bot`, `…/chatgptgold_bot`, `…/Integ_Solutios_bot`;
   - личные профили: LinkedIn `/in/astepchenkov`, `/in/darina-shyro`; личные телеграмы
     менеджеров `t.me/vm_sales`, `…/Egor_leadtorg`, `…/MaxPilyavsky`;
   - чужие соцсети из встроенных статей/виджетов: строка `mdis_granulex` подтянула **весь Хабр**
     (`t.me/habr_com`, `vk.com/habr`, `dzen.ru/habr`, `youtube.com/@Habr_com`); один и тот же
     YouTube-канал попал в две разные компании (общий встроенный виджет);
   - дубли (`vk.com/selecty` + `vk.com/selecty1`), нет потолка по количеству.

3. **«События» пусты у 66/66 — везде «–» (а не «Нет»).** Значит `detectEventSignals` вернул `{}`
   для каждой строки. Причины (ключ/модель/endpoint исключены — та же модель
   `anthropic/claude-sonnet-4-5-20250514` через requesty работает в `llmExtractor` и заполняет
   «Год основания»/«Размер команды»/«Отрасли»):
   - **нет входных данных:** `extractSocialPosts` читает посты только с публичных каналов
     (`t.me/s/<ch>`, `m.vk.com`, `m.ok.ru`, `dzen.ru`). А в «Соцсети» — личные телеграмы, боты,
     WhatsApp, с них постов не достать → `socialPosts` пуст;
   - **промпт заточен под HoReCa** ([eventDetector.ts](../../../app/src/lib/enrich/extractors/eventDetector.ts) `SYSTEM_PROMPT`:
     «аналитик сигналов … в HoReCa (рестораны, кафе, бары…)»). Даже при наличии постов для
     не-HoReCa компании это вернуло бы «Нет».

Проблемы #2 и #3 связаны: чистые публичные каналы компании — вход для событий.

## Цель

«Соцсети» находятся (в т.ч. JS-инъекция и off-site) и чисты (без ботов/личных/чужих).
«События» заполняются для **любой ниши**, а не только HoReCa. Состав колонок не меняется.

## Зафиксированные решения

1. **Колонки и типы не меняем.** «Соцсети» (`string[]`), 4 события (`event_*` + `*_summary`) —
   те же. Никаких новых колонок БД, заголовки экспорта прежние.
2. **Точность соцсетей (фильтр):** выкидываем Telegram-ботов (`/bot$/i`), личные LinkedIn `/in/`,
   соцсети из контентных блоков (`<article>/<main>` и встроенные виджеты) — берём из
   header/footer/nav/контактных зон; потолок ≤2 на сеть и ≤8 всего; dedup как сейчас.
3. **Полнота соцсетей (recall), слоями:** статический HTML → если пусто, **рендер Playwright**
   главной → если пусто, **поиск официального канала через Serper** по имени компании + домену.
   Все источники проходят тот же фильтр.
4. **Имя компании для Serper** берём со страницы (`og:site_name` → `<title>` → корень домена) —
   `processSignalsForUrl` имени компании не получает.
5. **Единая точка `discoverSocialMedia`** используется и колонкой «Соцсети», и fallback'ом
   событий — чтобы события получали уже очищенный обогащённый список.
6. **События — ниша-независимы:** переписать `SYSTEM_PROMPT` в `eventDetector.ts`, убрать
   привязку к HoReCa, расширить определения (см. ниже). Схема ответа, tri-state, рендер — те же.
7. **Всё best-effort:** Playwright/Serper/LLM падают → молча `[]`/`{}`, строку/джобу не роняем.
8. **Быстрый режим:** env-флаг `SIGNALS_SOCIAL_DEEP` (дефолт включён); `=0` отключает
   Playwright+Serper-добор для быстрых прогонов.

## Компоненты

### 1. `socialMediaExtractor.ts` — фильтрация
- **Боты:** в telegram-классификации отклонять handle по `/bot$/i`.
- **LinkedIn `/in/`:** убрать `in` из company-паттерна (оставить `company|school|showcase`) —
  личные профили больше не считаются соцсетью компании.
- **Контентные блоки:** в `extractSocialMedia` сначала собирать `<a>` из «фирменных» зон
  (`footer`, `header`, `nav`, элементы с class/id ~ `social|soc|contact|footer|подвал`); если там
  нашли — берём только их. Только если пусто — общий обход всей страницы (как сейчас). Это
  отсекает кейс Хабра (встроен в тело статьи), сохраняя обычные сайты.
- **Потолки:** ≤2 URL на семейство, ≤8 всего, детерминированный порядок (как сейчас, по
  `SOCIAL_PATTERNS`).
- Сигнатура `extractSocialMedia(html): string[]` сохраняется; фильтры — внутри.

### 2. `serperClient.ts` (новый, общий) + `socialCompanyFinder.ts` (новый)
- `serperClient.ts`: вынести `serperSearch(query): Promise<SerperItem[]>` (ключ `SERPER_API_KEY`,
  `gl/hl=ru`) — сейчас приватная копия в
  [socialProfileSerperEnrichment.ts](../../../app/src/lib/cisLeads/socialProfileSerperEnrichment.ts).
  Новый модуль использует её; рефактор cisLeads на общую — вне scope.
- `socialCompanyFinder.ts`: `findCompanySocials(companyName, domain): Promise<string[]>`.
  - Запросы: `site:t.me <company>`, `site:vk.com <company>`, `<company> telegram канал`,
    `<company> vk группа` (1–4 запроса, не больше).
  - Матчинг: домен результата ∈ поддерживаемых сетях; имя компании/домен встречаются в
    title/snippet/handle; отклоняем явные личные (`/in/`, `…_bot`). Берём ≤1 на сеть.
  - Верификация достижимости (HEAD / для telegram — что `t.me/s/<h>` отдаёт превью).
  - Нет ключа / 429 / timeout → `[]`. Прогоняем через фильтр из п.1.

### 3. `deriveCompanyName.ts` (новый, маленький)
`deriveCompanyName(html, url): string` — `og:site_name` → очищенный `<title>` (отрезать
« — …»/«| …») → корень домена. Для Serper-запроса.

### 4. `websiteSignalProcessor.ts` — recall-цепочка
- Вынести текущий social-блок (main+about merge) в `discoverSocialMedia(mainHtml, aboutHtml)` →
  очищенный `string[]`.
- Новая оркестрация (когда нужны `social_media` ИЛИ события, и `SIGNALS_SOCIAL_DEEP`):
  1. `urls = discoverSocialMedia(main.html, about)`;
  2. если `urls` пуст и `main.method==='http'` → `pw = fetchHtmlWithPlaywright(normalized,…)`;
     `urls = discoverSocialMedia(pw, about)`;
  3. если всё ещё пусто → `urls = await findCompanySocials(deriveCompanyName(main.html, normalized),
     hostOf(normalized))`.
- `out.social_media = urls` (если колонка запрошена). Блок событий (строки 598–604) использует
  тот же `urls` вместо локального пересчёта `extractSocialMedia(...)`.
- Playwright-рендер для соцсетей кешируется и переиспользуется (один рендер на строку).

### 5. `eventDetector.ts` — ниша-независимый промпт
- Переписать `SYSTEM_PROMPT`: «аналитик сигналов для B2B-аутрича **в любой нише**». Расширить:
  - **event_opening** — открытие/запуск нового офиса, филиала, точки, направления, продукта,
    выход на новый рынок/в новый город (не только заведение HoReCa);
  - **event_redesign** — ребрендинг, новый логотип, редизайн сайта, смена названия/позиционирования;
  - **event_renovation** — ремонт, переезд, новое помещение/офис (где применимо);
  - **event_geo** — города, где у компании есть присутствие/офисы/филиалы.
- Правила вывода (не выдумывать; true только при явном упоминании; false когда прочитал и нет;
  summary конкретная), схема JSON, tri-state, очистка — **без изменений**.
- (Опц.) модель из env `OPENROUTER_EVENTS_MODEL` (дефолт текущий) — для единообразия с другими
  экстракторами. Endpoint/ключ те же.

## Поток данных

URL → main(+about) HTML → `discoverSocialMedia` (static, фильтр). Пусто → Playwright-рендер →
`discoverSocialMedia`. Пусто → Serper `findCompanySocials`. → `out.social_media` (колонка) и тот же
список → `extractSocialPosts` → `detectEventSignals` (ниша-независимый) → `event_*` →
`result_text` → `formatExtraValue` → ячейки (или DASH).

## Обработка ошибок

Playwright fail → пропускаем шаг. Serper нет ключа/429/timeout → `[]`. LLM-события best-effort →
`{}` → DASH. Любой сбой добора оставляет то, что было, и не роняет строку/джобу.

## Производительность и стоимость

Добор (Playwright ~10–18 с + Serper ~1–3 с) идёт **только** на строках, где статический HTML дал
0 соцсетей (~20–35%). Serper — копейки за запрос, 1–4 запроса на такую строку. Для пакетной
выгрузки приемлемо; `SIGNALS_SOCIAL_DEEP=0` отключает добор (быстрый режим).

## Тестирование

- `socialMediaExtractor`: бот `…_bot` отброшен; LinkedIn `/in/` отброшен, `/company/` оставлен;
  соцсети из `<article>` (виджет Хабра) НЕ попадают, из `<footer>` попадают; потолки ≤2/сеть, ≤8;
  существующие кейсы зелёные.
- `socialCompanyFinder` (мок serper): матч по имени/домену → канал; нет ключа → `[]`; чужой/личный
  результат отклонён; недостижимый отклонён.
- `deriveCompanyName`: og:site_name > title > домен; обрезка хвостов title.
- `websiteSignalProcessor` (моки): static пусто → Playwright-путь даёт соцсети; и Playwright пусто
  → Serper-путь; события получают очищенный список; `SIGNALS_SOCIAL_DEEP=0` пропускает добор.
- `eventDetector`: схема/tri-state-тесты зелёные; не-HoReCa «открытие нового офиса» → opening=true.

## Вне scope (YAGNI)

- Не чиним качество входного списка (junk-лиды rbc.ru/vc.ru/заголовки) — только пометить в
  отчёте отдельной задачей; не блокирует.
- Не трогаем остальные сигналы (Стек/Цены/Найм/Интеграции/…) — они работают.
- Не рефакторим cisLeads на общий `serperClient` (только выносим функцию для переиспользования).
- Не добавляем подстраницу `/contacts` как отдельный SubpageKind — глобальный подвал ловится
  рендером главной.
- Без новых колонок БД и без смены заголовков экспорта.
