# Стеклянные дашборды — дизайн

Дата: 2026-08-07
Ветка: `dmitriy_kuladmed`

## Задача

Добавить порталу «стеклянность» в духе свежих мобильных оболочек (HyperOS): полупрозрачные
поверхности с размытием фона. Начинаем с дашбордов.

## Решения, принятые на брейншторме

| Вопрос | Решение |
| --- | --- |
| Степень эффекта | Вариант «подложка + стекло»: под карточками появляется собственный фон, иначе размывать нечего |
| Палитра подложки | Почти монохром — оттенки серо-синего. Цвет остаётся у цифр и линий графиков |
| Охват | `/analytics/first-sales`, `/analytics/renewals`, `/analytics/projects`. Загрузка ящиков (`/analytics/mailbox-load`) — вне охвата |
| Таблицы | Стеклянная только рамка таблицы и её шапка; строки лежат на плотной подложке |
| Анимация подложки | Нет. Постоянная перерисовка и расход батареи не окупаются |
| Способ внедрения | Отдельный набор именованных материалов в `globals.css` + точечная замена оформления в трёх экранах |
| Темы | Светлая и тёмная, обе обязательны |

## Ключевое ограничение: тёмная тема

Тёмная тема портала реализована как слой принудительных переопределений в `globals.css`
(секция `html[data-portal-theme='dark'] .portal-shell …`, начиная примерно со строки 2540).
Он ловит утилитарные классы Tailwind и перекрашивает их с `!important`:

```css
html[data-portal-theme='dark'] .portal-shell .bg-white,
html[data-portal-theme='dark'] .portal-shell .bg-white\/80 { … !important }
```

Полупрозрачная карточка, собранная на `bg-white/60`, в тёмной теме будет принудительно
залита непрозрачным `--pd-surface`, и стекло исчезнет.

Отсюда требование: стеклянные поверхности вводятся под собственными именами классов,
которых этот слой не знает. Совместимость обеспечивается по построению, а не отладкой.

По той же причине запрещено реализовывать эффект способом «переопределить `bg-white`
внутри дашбордов» — это добавка в тот же перегруженный каскад.

## Архитектура

### Сцена

Класс `.glass-stage` надевается на корневой `div` каждого из трёх экранов.

- Даёт фон: базовый серо-синий плюс два-три бледных радиальных пятна.
- Позиции и радиусы пятен задаются в процентах от размеров элемента, а не в пикселях.
  Это обязательное требование: на странице с таблицей на несколько сотен строк
  пиксельные пятна остались бы вверху, и низ страницы стал бы плоско-серым — стекло
  там перестало бы читаться.
- Фон рисуется на самом элементе (`background-image` из нескольких `radial-gradient`),
  без дополнительных DOM-узлов и без псевдоэлемента с `position: fixed`.
- Анимации нет.

### Материалы

Три именованных материала. Каждый объявлен один раз, со значениями для светлой и
тёмной темы.

**`.glass-tile`** — плитки KPI и карточки графиков.
Полупрозрачная заливка (светлая тема — белый ~55%), размытие фона, тонкая светлая
рамка, мягкая тень. Скругление совпадает с текущим `rounded-xl`, чтобы геометрия
экранов не поехала.

**`.glass-panel`** — строка фильтров, заголовок экрана, вспомогательные плашки.
Та же формула, но заливка прозрачнее и скругление меньше: служебный слой не должен
конкурировать с плитками.

**`.glass-frame`** — внешняя коробка таблицы и её шапка (`thead`).
Стеклянные только они. Строкам данных задаётся плотная подложка, чтобы текст в
таблице читался без просвечивания соседних строк.

**`.glass-tint-{blue,emerald,amber,red}`** — модификатор к `.glass-tile`.
Нужен для дашборда проектов: там четыре верхние карточки уже несут цветовую
семантику (`bg-blue-50/50`, `bg-emerald-50/50`, `bg-amber-50/50`, `bg-red-50/50`,
`app/analytics/projects/page.tsx:344-358`). Модификатор подмешивает тот же оттенок
в стеклянную заливку, сохраняя смысл цвета.

### Тёмная тема

В тёмной теме стекло описывается не как «белый с прозрачностью», а как светлый слой
поверх тёмного: белая заливка около 7%, рамка белым около 14%. Прямое переиспользование
светлых значений даёт мутный серый блок.

Правила для тёмной темы живут рядом с определением материалов, в новой секции
`globals.css`, а не внутри существующего слоя переопределений.

## Графики (ECharts)

`resolveSurface()` в `app/src/components/charts/theme.ts:77` определяет фон, поднимаясь
по дереву до первого непрозрачного предка. Значение используется как фон всплывающей
подсказки (`theme.surface`, применяется в `theme.ts:204`) и для зазоров между
сегментами.

Проверка «непрозрачности» отсеивает только `transparent` и `rgba(0, 0, 0, 0…)`.
Полупрозрачный белый вроде `rgba(255, 255, 255, 0.55)` она пропустит как валидный
фон — подсказка станет просвечивать насквозь.

Правка: материалы объявляют CSS-переменную с плотным цветом поверхности
(`--chart-surface`), а `resolveSurface()` сначала читает её и только при отсутствии
идёт вверх по дереву. Одно изменение в общем файле покрывает все дашборды.

Дополнительно: холстам графиков задаётся прозрачный фон, чтобы подложка читалась
под линиями.

## Производительность и доступность

- **Без вложенного стекла.** Размытие внутри размытия — то, что реально ломает
  прокрутку. Правило: `.glass-frame` не содержит `.glass-tile`, и наоборот.
- **`prefers-reduced-transparency`** (системная настройка Windows и macOS): под
  медиа-запросом материалы отдают непрозрачные варианты. Экран остаётся полностью
  рабочим, теряется только эффект. Firefox медиа-запрос не поддерживает — там
  останется стеклянный вариант, это приемлемо.
- **Контраст.** Цвета текста не меняются. Проверяется, что основные цифры KPI и текст
  таблиц проходят по контрасту на самом светлом участке подложки в светлой теме и на
  самом тёмном — в тёмной.

## Затрагиваемые файлы

- `app/src/app/globals.css` — новая секция: сцена, три материала, тонированные
  модификаторы, правила тёмной темы, ветка `prefers-reduced-transparency`.
- `app/src/components/charts/theme.ts` — приоритет `--chart-surface` в `resolveSurface()`.
- `app/src/components/first-sales/` — `FirstSalesView`, `KpiRow`, `FiltersBar`,
  `SourceTable`, `FunnelChart`, `TimeSeriesChart`.
- `app/src/components/renewals/` — `RenewalsView`, `KpiRow`, `FiltersBar`,
  `RenewalsTable`, `RenewalsRowsTable`, `RenewalsUndatedSection`, `RenewalsChart`,
  `RenewalsFunnel`.
- `app/src/app/analytics/projects/page.tsx` — сцена, четыре тонированные плитки,
  четыре табличных блока.

## Вне охвата

- `/analytics/mailbox-load`
- Боковое меню, шапка портала, остальные страницы админского контура
- Клиентский контур `/client` (собственная палитра `.client-portal`)
- Любая логика, запросы и данные — изменения только в оформлении

## Критерии приёмки

1. Три дашборда показывают подложку и стеклянные поверхности в светлой и тёмной теме.
2. Переключение темы не оставляет непрозрачных или мутно-серых карточек.
3. Всплывающие подсказки графиков непрозрачны на обеих темах.
4. При включённой системной настройке «уменьшить прозрачность» экраны читаемы и
   не содержат размытия.
5. На странице проектов сохранена цветовая семантика четырёх верхних карточек.
6. Загрузка ящиков, боковое меню и остальные страницы визуально не изменились.
