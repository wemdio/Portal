# Письма английского автоаутрича: боль вместо «что вы делаете» — дизайн

Дата: 29.09.2026. Ветка: `dmitriy_kuladmed_new`. Только EN (`lib/polzaOutreach/`); русские
письма не меняются.

## Зачем

Отзыв Ника (продажи, 29.09.2026) на письма EN: строка «You provide tele-audiology solutions…»
(`{{about}}`) — «кринжик». Вместо описания того, что компания делает, надо угадать боль с учётом
повода и ударить в неё: какую задачу компания решает и какие проблемы бывают с тем, как она
решает её сейчас. Письма — короче, по его структуре из четырёх писем.

## Решения пользователя

- Боль угадывает **дешёвая модель разбора сайта на каждую компанию** в том же вызове
  (`siteProfile.ts`). Цепочку по-прежнему пишет Gemini — одну на оффер.
- Письмо 1 на общий ящик заканчивается предложением «прислать список тому, кто отвечает за
  продажи?»; на личный — «прислать список?».
- Обращение остаётся «Hi there,» — имени получателя нет.

## Боль под компанию — `{{pain}}`

Разбор сайта (`SYSTEM` в `siteProfile.ts`) получает вместо `about_line` поле `pain_line`:
1–2 предложения по схеме «когда [ситуация повода], узкое место обычно не [очевидное], а
[настоящее]» — про продажи/пайплайн этой компании с учётом того, что и кому она продаёт.
- В вызов передаётся повод компании, известный до разбора: найм (короткое название вакансии),
  YC (батч), иначе «нет повода» — тогда боль строится от того, что и кому продают.
  Ключ кэша разбора включает отпечаток повода (тип + короткое название), чтобы разбор с одним
  поводом не отдавался компании с другим.
- Проверка строки (`painLineOf`, по образцу `aboutLineOf`): 12–40 слов, 1–2 законченных
  предложения, без цифр, вопросов, восклицаний, кавычек и скобок, без рекламных слов, без голоса
  «we/our», без пересказа деятельности («you provide», «you offer», «your company is/does» —
  запрещены). Не прошла — `null`, абзац удаляется.
- `about_line` / `{{about}}` в EN убираются из промпта, писем и проверок; колонка `about_line`
  остаётся (её читает RU и старые строки). Новая колонка `pain_line text` в
  `polza_outreach_companies`.
- Правка промпта меняет `SITE_PROMPT_VERSION` — профили из 30-дневного кэша один раз
  пересчитаются.

`likely_gtm_problem` и `outreach_angle` остаются как есть (Lead Score и экран).

## Цепочка

Плейсхолдеры EN: `{{company}}`, `{{trigger}}`, `{{pain}}`, `{{trigger_short}}`, `{{case}}`,
`{{segments}}`, `{{signature}}`. `{{about}}` удалён.

| Письмо | Структура | Вопрос |
|---|---|---|
| 1 | `{{trigger}}` → `{{pain}}` → что делает Polza (три пункта одной фразой) → `{{segments}}` («For X, I would probably start with: …») | лично: прислать 20 целевых компаний? / общий ящик: прислать их тому, кто отвечает за продажи? |
| 2 | конкретная проблема → чем обходится бизнесу → что сделаем для `{{company}}` (три пункта) | показать, как это может выглядеть? |
| 3 | `{{case}}` (в варианте с кейсом) → `{{segments}}` для проверки → бесплатная выборка 20–30 компаний до созвона | прислать? |
| 4 | последнее письмо → если `{{company}}` [в ситуации], выборка всё ещё может пригодиться → если не актуально, закрою переписку | оставить так? |

Тема письма 1 — «боль + компания/роль» (как у Ника: «pipeline before your new SDR ramps»,
«target accounts for {{company}}»); из плейсхолдеров в теме — только `{{company}}`.

**Длина** — новое правило `guardTemplate` (текст без плейсхолдеров): письмо 1 ≤ 60 слов,
письма 2–4 ≤ 70 слов. С подставленными болью (≤ 40) и сегментами письмо 1 выходит около
110–120 слов вместо нынешних ~150.

Изменения в правилах шаблона (`guardTemplate`):
- `{{pain}}` обязателен в обоих вариантах письма 1 и только там; отдельный абзац (как `{{about}}`
  сейчас);
- `{{segments}}` разрешён в письме 1 (оба варианта) и в письме 3; в письме 1 обязателен;
- вариант для общего ящика (`L1r:not_routing`) по-прежнему должен просить переслать/назвать
  ответственного — формулировка «send them to whoever handles sales» должна проходить
  (`ROUTING_RE` дополняется «whoever (handles|runs|owns|leads)»);
- проверка длины (`L*:too_long(<слов>)`) — с текстом замечания для повтора писателю.

## Образец писателю

`buildLetters` (образец тона и структуры для Gemini, `templateWriter.ts`) переписывается
по структуре выше; `SAMPLE_ABOUT` заменяется `SAMPLE_PAIN`; цели писем в задании писателю
(`templateWriter.ts`, описания писем 1–4 и плейсхолдеров) — по таблице выше; пример повода
Ника («Noticed {company} is hiring for {role}») совпадает с нынешними `triggerPhraseVariants`.
`SEQUENCE_ID` → `en_offer_templates_v2`.

Уже написанные шаблоны старых запусков не трогаем: новые правила — для новых шаблонов;
«Переписать цепочку» у старого запуска пишет уже по-новому.

## Цена

Лишних вызовов ИИ нет: боль пишет тот же вызов разбора сайта. Разовая доплата — пересчёт
закэшированных разборов (дешёвая модель). Писатель цепочки — прежний лимит $10 на запуск.

## Вне объёма

Русские письма, имя получателя, письмо на каждую компанию, несколько вариантов шаблона на оффер.

## Проверка

Новых тест-файлов не пишем. Существующие тесты `buildLetters`/`guardTemplate`/`siteProfile`
обновляются под новые правила. `npm run typecheck:fast`. Проверка на живом ИИ — после выкладки:
первый запуск EN, посмотреть 10–20 писем 1 глазами.
