# Автодобор базы для автоаутричей RU и EN

Дата: 06.10.2026. Ветка `dmitriy_kuladmed_new`. Решения пользователя — из переписки 06.10.2026.

Затрагивает русский (`app/src/lib/polzaRuOutreach/`) и английский (`app/src/lib/polzaOutreach/`)
автоаутричи, заливку в «Рассылку» (`app/src/lib/outreachSender/`), воркер `app/worker/polzaOutreach.ts`
и общий экран запуска (`components/outreach/run`).

## 0. Главные решения

| Вопрос | Решение |
|---|---|
| Что считаем | **Новые компании в день** = письма в день по рабочим ящикам папки ÷ 4 письма цепочки. Сейчас RU 20 ÷ 4 = 5, EN 25 ÷ 4 ≈ 6. |
| Дни | Только рабочие дни папки (`send_weekdays`, сейчас пн–пт). «Неделя» = 5 рабочих дней. |
| Когда добирать | Остатка меньше чем на **3 рабочих дня** → сбор на **неделю** (RU: 5 × 5 = 25 готовых компаний). Пустая база — тоже неделя. |
| Когда проверять | Дважды в день: **09:00 и 21:00 МСК**. |
| Насколько автоматически | Полностью: сбор → заливка в новую кампанию папки → старт рассылки, без кнопок. |
| Настройки сбора | Блок «Автодобор» на экране автоаутрича, отдельно RU и EN: выключатель + настройки как у обычного запуска (по умолчанию те же), бюджет $10 на добор. |
| Недобор | Залить, сколько собрано; остаток доберёт следующая проверка, но **не больше одного автосбора в день на язык**. |
| Сообщения | Чат техники (бот health-check, `sendWorkerAlert`), проблемы — с отметкой **@kuladmedDm**. |

Счёт ведём в компаниях, без поправки на несколько почт у компании: если почт больше одной, база
кончается чуть раньше, и проверка дважды в день просто доберёт раньше.

## 1. Расчёт

Для папки `auto_ru` / `auto_en` (`sender_folders.key`):

- **Письма в день** `capacity` = сумма `daily_campaign_limit` ящиков папки (`sender_folders.mailbox_ids`)
  со `status = 'verified'` и `enabled`. Ящики могут быть общими с другими кампаниями — это не
  учитываем, считаем лимит ящика целиком.
- **Длина цепочки** `chainLen` = 1 + число задержек в `step_delays_hours` папки (сейчас 4).
- **Скорость** `perDay` = `floor(capacity / chainLen)`, минимум 1, если `capacity > 0`.
- **Остаток** `remaining` = число различных `group_key` (строка компании) среди `sender_recipients`
  со `status = 'active'` и `last_step_sent = 0` во всех кампаниях папки (`sender_campaigns.folder_id`)
  в статусах `draft | paused | running`.
- **Дней осталось** = `remaining / perDay` (рабочих).
- **Нужен добор**, если дней осталось < 3. **Размер добора** `target` = `perDay × 5`.

Чистая функция `planAutofill({ capacity, chainLen, remaining })` → `{ perDay, daysLeft, needed, target }`
в `app/src/lib/outreachAutofill/plan.ts`; дата «база до …» считается сдвигом по рабочим дням папки.

## 2. Хранение

Миграция `supabase/migrations/20261006_00xx_outreach_autofill.sql`:

```sql
create table if not exists public.outreach_autofill (
  lang text primary key check (lang in ('ru','en')),
  enabled boolean not null default false,
  config jsonb not null default '{}'::jsonb,   -- конфиг запуска, как parser_jobs.config своего языка
  owner_id uuid references auth.users (id) on delete set null, -- кто включил: автор запусков
  last_check_at timestamptz,
  last_state jsonb,          -- {perDay, remaining, daysLeft, baseUntil, capacity} для строки состояния
  last_job_id uuid references public.parser_jobs (id) on delete set null,
  last_job_day date,         -- день (МСК) последнего автосбора: не больше одного в день
  short_streak int not null default 0, -- подряд автосборов, набравших < 50% цели
  updated_at timestamptz not null default now()
);
-- grant ... to service_role (правило grants.test.ts), select/update — админам, как вкладки автоаутрича
```

`parser_jobs.config.autofill = true` помечает автосборы — в списке запусков бейдж «Автодобор».
Автор запуска (`parser_jobs.user_id`, обязателен) — `owner_id`; если его нет, автодобор не стартует
и шлёт сообщение «включите заново».

## 3. Где работает

В воркере автоаутрича `app/worker/polzaOutreach.ts` (прод-сервер 139) — он же выполняет запуски, так что
сбор, заливка и старт в одном процессе; отдельный крон и sender-хосты не трогаем.

- Таймер раз в минуту проверяет, наступили ли 09:00 или 21:00 МСК после `last_check_at`. Пропущенная из-за
  простоя воркера проверка выполняется при старте один раз (не догоняет все пропущенные).
- Проверка на язык (`lib/outreachAutofill/check.ts`):
  1. Выключено → выход.
  2. Есть незавершённый автосбор (`last_job_id` в `pending | running`) → выход.
  3. Последний автосбор завершён, но ещё не залит → шаг «Заливка» (п. 4).
  4. Считаем п. 1, пишем `last_state`. Добор не нужен → выход.
  5. Уже был автосбор сегодня (`last_job_day`) → выход.
  6. `capacity = 0` → сообщение «в папке нет рабочих ящиков», выход.
  7. Создаём `parser_jobs` (`status 'pending'`, `config` = `outreach_autofill.config` + `limit = target`,
     `autofill: true`), пишем `last_job_id`, `last_job_day`.
- **Заливка**: по завершении автосбора (`completed` или `failed` с готовыми строками) — существующие
  `uploadJobToSender(mode 'new')` и `startJobCampaign`. Проверяется на каждом тике таймера, а не только
  в 9/21, чтобы база не ждала до вечера.
  Заливка закрыта (`smtp_unavailable`, ящики пропали) → сообщение, строки остаются для ручной заливки.
- Тот же воркер на рестарте возвращает `running` в `pending` — автосбор продолжится сам.

## 4. Экран

На странице автоаутрича своего языка (общий `components/outreach/run`, языковое — в адаптере) —
блок «Автодобор», виден админам (как вкладки «Квалификация»/«Библиотеки»):

- выключатель; при включении `owner_id` = текущий пользователь;
- настройки сбора — та же форма, что у обычного запуска, без поля «лимит» (его считает автодобор);
- строка состояния из `last_state`: «5 компаний/день · база до 09.10 · добор ~07.10» или
  «идёт добор: 12 из 25».

API: `GET/PUT /api/tools/outreach-autofill/[lang]` (админ), конфиг через существующие
`sanitizeRuOutreachConfig` / санитайзер EN.

## 5. Сообщения в чат техники

Через `sendWorkerAlert` (бот и чат health-check). Текст по-русски, коротко.

| Событие | Текст | @kuladmedDm |
|---|---|---|
| Добор залит и запущен | «RU: добрано 25 компаний, база до 14.10» | нет |
| Собрано < цели | «RU: нужно 25, собрано 12, база до 09.10, завтра доберу» | да |
| Два автосбора подряд < 50% цели | «RU: второй раз подряд меньше половины — похоже, источники иссякли, поменяйте настройки» | да |
| Автосбор упал без готовых строк | «RU: автодобор упал: <причина>» | да |
| Нет рабочих ящиков в папке | «RU: в папке нет рабочих ящиков, добор не запущен» | да |
| Заливка закрыта | «RU: не залито — <причина>» | да |
| Кончился бюджет / ключ ИИ | «RU: автодобор остановлен — <причина>» | да |

`sendWorkerAlert` сейчас оформляет всё как ошибку (🚨, `<code>`); добавить в
`lib/telegram/workerAlert.ts` простой вариант `sendWorkerNotice(text)` с тем же выбором бота и чата.

## 6. Что сознательно не делаем

- Не меняем лимиты ящиков и прогрев.
- Не повторяем сбор сразу после неудачи — следующий шанс на следующий день.
- Не учитываем несколько почт у компании и ящики, общие с другими кампаниями.
- Новых тестовых файлов не заводим (правило проекта). Проверка — проверка типов в CI и первый живой
  добор после выкладки.
