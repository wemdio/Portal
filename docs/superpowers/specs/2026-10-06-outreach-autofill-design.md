# Автодобор базы для автоаутричей RU и EN

Дата: 06.10.2026. Ветка `dmitriy_kuladmed_new`. Решения пользователя — из переписки 06.10.2026.

Затрагивает русский (`app/src/lib/polzaRuOutreach/`) и английский (`app/src/lib/polzaOutreach/`)
автоаутричи, заливку в «Рассылку» (`app/src/lib/outreachSender/`), воркер `app/worker/polzaOutreach.ts`
и общий экран запуска (`components/outreach/run`).

## 0. Главные решения

| Вопрос | Решение |
|---|---|
| Лимиты ящика (правка 06.10.2026) | Два числа у каждого ящика «Рассылки»: **«новых в день»** (первые письма, по умолчанию 5) и **«всего в день»** (все письма цепочки, по умолчанию 20 = 5 × 4), чтобы цепочки помещались полностью. Напоминания (письма 2–4) планируются раньше новых. См. §1а. |
| Что считаем | **Новые компании в день** = сумма «новых в день» по рабочим ящикам папки. Сейчас RU 4 × 5 = 20, EN 5 × 5 = 25. |
| Дни | Только рабочие дни папки (`send_weekdays`, сейчас пн–пт). «Неделя» = 5 рабочих дней. |
| Когда добирать | Остатка меньше чем на **3 рабочих дня** → сбор на **неделю** (RU: 20 × 5 = 100 готовых компаний). Пустая база — тоже неделя. |
| Когда проверять | Дважды в день: **09:00 и 21:00 МСК**. |
| Насколько автоматически | Полностью: сбор → заливка в новую кампанию папки → старт рассылки, без кнопок. |
| Настройки сбора | Вкладка «Автодобор» на странице автоаутрича, отдельно RU и EN: выключатель + настройки как у обычного запуска (по умолчанию те же), бюджет $10 на добор. |
| Недобор | Залить, сколько собрано; остаток доберёт следующая проверка, но **не больше одного автосбора в день на язык**. |
| Сообщения | Чат техники (бот health-check, `sendWorkerAlert`), проблемы — с отметкой **@kuladmedDm**. |

Счёт ведём в компаниях, без поправки на несколько почт у компании: если почт больше одной, база
кончается чуть раньше, и проверка дважды в день просто доберёт раньше.

## 1а. «Рассылка»: два лимита ящика и сначала напоминания

Найдено 06.10.2026 на рассылке «RU · 04.10 · 100 компаний»: за два дня ушло 40 первых писем и ни
одного второго. Лимит ящика (5) общий на все шаги, планировщик берёт получателей по `next_step_at`,
а непочатые адреса ждут дольше, чем напоминания, — первые письма выбирают весь лимит, вторые ждут,
пока не кончатся новые (≈ неделя вместо суток).

- `sender_mailboxes.daily_campaign_limit` — теперь **«новых в день»**: только письма шага 1.
- `sender_mailboxes.daily_total_limit` (был в схеме, кодом не читался, default 100) — **«всего в день»**:
  все шаги. Миграция: всем ящикам `daily_total_limit = daily_campaign_limit * 4`, default 20.
- Планировщик (`lib/sender/planner.ts`): `remainingQuota` возвращает два остатка — всего
  (`daily_total_limit` − отправленное сегодня − в очереди) и новых (то же по `step_no = 1`).
  Шаг 1 требует оба, шаги 2+ — только «всего».
- `planSenderMessages` идёт по кампаниям **два раза**: сначала только получатели с
  `last_step_sent > 0` (напоминания всех рассылок), потом с `last_step_sent = 0` (новые). Остатки
  читаются из базы на каждый проход кампании, поэтому запланированное в первом проходе учтено во втором.
- Экран ящиков: столбец «Лимит/день» → два поля «Новых/день» и «Всего/день»; PATCH ящика принимает
  `dailyTotalLimit` (1–500).
- Выкладка — sender-хосты (воркер `app/worker/sender.ts`), отдельно от 139.

## 1. Расчёт

Для папки `auto_ru` / `auto_en` (`sender_folders.key`):

- **Скорость** `perDay` = сумма `daily_campaign_limit` («новых в день») ящиков папки
  (`sender_folders.mailbox_ids`) со `status = 'verified'` и `enabled`. Ящики могут быть общими с другими
  кампаниями — это не учитываем, считаем лимит ящика целиком.
- **Остаток** `remaining` = число различных компаний (`coalesce(group_key, id)`) среди `sender_recipients`
  со `status = 'active'` и `last_step_sent = 0` во всех кампаниях папки (`sender_campaigns.folder_id`)
  в статусах `running | paused`. Черновики не считаем: они не шлют, и не запущенная рассылка не должна
  выглядеть как запас базы.
- **Дней осталось** = `remaining / perDay` (рабочих).
- **Нужен добор**, если дней осталось < 3. **Размер добора** `target` = `perDay × 5`, не больше 1000
  (потолок запуска).

Скорость и остаток считает одна RPC `outreach_autofill_folder_state(p_folder_key text)` →
`{ folder_id, per_day, remaining, weekdays, timezone }`. Чистая функция
`planAutofill({ perDay, remaining })` → `{ daysLeft, needed, target }` и `addWorkdays(...)` для даты
«база до …» — в `app/src/lib/outreachAutofill/plan.ts`.

## 2. Хранение

Миграция `supabase/migrations/20261006_0020_outreach_autofill.sql` (там же лимиты ящиков из §1а и RPC):

```sql
create table if not exists public.outreach_autofill (
  lang text primary key check (lang in ('ru','en')),
  enabled boolean not null default false,
  config jsonb not null default '{}'::jsonb,   -- конфиг запуска, как parser_jobs.config своего языка
  owner_id uuid references auth.users (id) on delete set null, -- кто включил: автор запусков
  last_check_at timestamptz,
  last_state jsonb,          -- {perDay, remaining, daysLeft, baseUntil, checkedAt} для строки состояния
  last_job_id uuid references public.parser_jobs (id) on delete set null,
  last_job_day date,         -- день (МСК) последнего автосбора: не больше одного в день
  last_job_handled boolean not null default true, -- итог последнего автосбора разобран (залит / сообщён)
  last_job_target int,
  short_streak int not null default 0, -- подряд автосборов, набравших < 50% цели
  updated_at timestamptz not null default now()
);
insert into public.outreach_autofill (lang) values ('ru'), ('en') on conflict do nothing;
-- RLS: select/update — админам (profiles.role = 'admin'); grant ... to service_role (правило grants.test.ts)
```

`parser_jobs.config.autofill = true` помечает автосборы — в списке запусков бейдж «Автодобор».
Автор запуска (`parser_jobs.user_id`, обязателен) — `owner_id`; если его нет, автодобор не стартует
и шлёт сообщение «включите заново». У автосбора `include_previously_exported` всегда `false`:
иначе он брал бы компании, которым уже писали.

## 3. Где работает

В воркере автоаутрича `app/worker/polzaOutreach.ts` (прод-сервер 139) — он же выполняет запуски, так что
сбор, заливка и старт в одном процессе; отдельный крон и sender-хосты не трогаем.

- Таймер раз в минуту (`lib/outreachAutofill/check.ts`, `runAutofillTick`):
  - **Разбор автосбора** — на каждом тике: `last_job_handled = false` и запуск закончился (`completed` /
    `failed`, аренда воркера снята) → заливка `uploadJobToSender(mode 'new', userId = owner)` и
    `startJobCampaign`, сообщение, `last_job_handled = true`. Так база не ждёт следующих 9/21.
  - **Проверка базы** — когда после `last_check_at` наступило 09:00 или 21:00 МСК. Пропущенная из-за
    простоя воркера проверка выполняется один раз при старте (все пропущенные не догоняются).
- Проверка на язык:
  1. Выключено → выход (`last_check_at` всё равно пишется).
  2. Есть неразобранный автосбор (`last_job_handled = false`) → выход.
  3. Считаем §1, пишем `last_state`. Добор не нужен → выход.
  4. Уже был автосбор сегодня (`last_job_day` = сегодня МСК) → выход.
  5. `perDay = 0` → сообщение «в папке нет рабочих ящиков», выход.
  6. Нет `owner_id` → сообщение «включите автодобор заново», выход.
  7. Создаём `parser_jobs` (`status 'pending'`, `config` = санитайзер языка(`outreach_autofill.config` +
     `limit = target`, `include_previously_exported = false`) + `autofill: true`), пишем `last_job_id`,
     `last_job_day`, `last_job_target`, `last_job_handled = false`. Ключ ИИ языка не задан → сообщение, выход.
- Итог разбора: `companies` из результата заливки против `last_job_target`:
  - ≥ цели → «добрано N, база до …», `short_streak = 0`;
  - < цели → «нужно X, собрано N, база до …, завтра доберу» (+ причина остановки из
    `progress_detail.stop_reason`: бюджет, кончились кандидаты, потолок просмотра); < 50% → `short_streak + 1`,
    при `short_streak ≥ 2` — «источники иссякли»;
  - заливка отказала (`SenderOpError`: нет готовых, `smtp_unavailable`, нет ящиков) → сообщение с текстом
    отказа; «нет готовых» считается сбором 0.
- Тот же воркер на рестарте возвращает `running` в `pending` — автосбор продолжится сам.

## 4. Экран

Вкладка **«Автодобор»** на странице автоаутрича своего языка, рядом с «Квалификацией» (общий
`OutreachTabs`, как и они — только админам):

- выключатель; при включении `owner_id` = текущий пользователь;
- кнопка «Настройки сбора» открывает ту же панель, что и обычный запуск (`LaunchPanel` RU /
  `PolzaOutreachLaunchPanel` EN в режиме `autofill`: заголовок «Настройки автодобора», кнопка «Сохранить»,
  без полей «сколько компаний» и «брать уже выгруженные»);
- строка состояния из `last_state`: «20 компаний/день · в базе 64 · хватит до 09.10» и, если идёт сбор,
  ссылка-строка «идёт добор: запуск от 06.10».

API: `GET/PUT /api/tools/outreach-autofill/[lang]` (админ, `requireAdmin`); конфиг через
`sanitizeRuOutreachConfig` / `sanitizePolzaOutreachConfig`.

## 6. Что сознательно не делаем

- Не управляем прогревом ящиков; лимиты меняет человек на экране ящиков.
- Не повторяем сбор сразу после неудачи — следующий шанс на следующий день.
- Не учитываем несколько почт у компании и ящики, общие с другими кампаниями.
- Новых тестовых файлов не заводим (правило проекта). Проверка — проверка типов в CI и первый живой
  добор после выкладки.
