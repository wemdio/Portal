# «Рассылка»: контрольные ящики — входящие или спам

Дата: 07.10.2026. Статус: согласовано с пользователем, ждёт плана.

## 1. Зачем

Сейчас «Рассылка» видит только отказы (`sender_bounce_category`), молчание
доменов и DNS-здоровье (`sender_domain_health`). Куда легло письмо, которое
дошло, во «Входящие» или в «Спам», не видно никому.

Решение пользователя: купить свои контрольные ящики у четырёх почтовых
сервисов и раз в день слать на них короткое письмо с каждого рабочего ящика.
Портал сам заходит в контрольные ящики и смотрит, в какой папке письмо.

Это пересматривает решение от 02.10.2026 «без контрольных ящиков»: нагрузка
оказалась маленькой (4 письма в день на рабочий ящик).

## 2. Решения пользователя

| Вопрос | Решение |
|---|---|
| Сервисы | Яндекс, Gmail, Mail.ru, Outlook / Microsoft 365 |
| Сколько контрольных ящиков | по 5 на сервис, всего 20 |
| Какие ящики проверяем | только привязанные к идущим рассылкам (`sender_campaigns.status = 'running'`) |
| Сколько писем | каждый проверяемый ящик раз в день шлёт **4 письма, по одному на сервис**; ящик из пятёрки сервиса выбирается по очереди |
| Текст | нейтральное короткое деловое письмо без ссылок (не копия боевого) |
| Где показываем | вкладка «Статистика», блок «Доставляемость» и разрез «Ящики» |
| Реакция | только экран: без сообщений в чат и без автопаузы ящика |

Отвергнуто: слать на все 20 сразу (260 писем в день, контрольные ящики
быстро начнут резать холодную почту и искажать результат); платные сервисы
(GlockApps, MailReach): $50–100 в месяц, а российских почт у них почти нет.

## 3. Как работает

### 3.1 Контрольные ящики

Новая таблица `sender_seed_boxes`:

- `provider`: `yandex` | `gmail` | `mailru` | `outlook`;
- `email`, `imap_host`, `imap_port`, `imap_user` (host/port по умолчанию
  подставляются по сервису: imap.yandex.ru, imap.gmail.com, imap.mail.ru,
  outlook.office365.com, порт 993);
- `secret`: пароль приложения, запечатан тем же `sealMailboxSecret`, что и
  пароли боевых ящиков (`lib/byoMailbox/credentials`);
- `enabled`, `status` (`pending` | `ok` | `failed`), `last_error`,
  `checked_at`, `junk_folder` (найденная папка спама);
- RLS включён, `grant all ... to service_role`.

При добавлении и по кнопке «Проверить» портал входит по IMAP и ищет папку
спама: сначала по отметке `\Junk`, затем по именам `Spam`, `Спам`, `Junk`,
`[Gmail]/Spam`, `[Gmail]/Спам`, `Нежелательная почта`. Нет входа или нет
папки → `failed` с понятной причиной, ящик в проверку не берётся.

**Outlook — второй этап.** Microsoft не пускает почтовые программы по
паролю: нужна регистрация нашего приложения у Microsoft (Entra ID) и разовый
вход через их окно (OAuth2, IMAP через XOAUTH2, обновляемый токен в
`secret`). Первый этап — Яндекс, Gmail, Mail.ru по паролю приложения.
Outlook-ящики можно завести в списке сразу; до второго этапа у них статус
«нужен вход через Microsoft», и в рассылку проб они не попадают.

### 3.2 План на день

Ведущий sender-воркер (`runFleetJobs` в `worker/sender.ts`) раз в рабочий
день (пн–пт по Москве), в начале окна отправки:

1. Берёт ящики, привязанные к идущим рассылкам (`sender_campaign_mailboxes` →
   `sender_campaigns.status = 'running'`), `status = 'verified'`, `enabled`.
2. Для каждого ящика и каждого сервиса, где есть хоть один контрольный ящик
   в статусе `ok`, выбирает контрольный ящик **по очереди**: тот, на который
   за последние 7 дней пришло меньше всего проб; при равенстве — не тот,
   что был у этого ящика вчера.
3. Ставит время отправки случайно в окне 10:00–17:00 МСК, чтобы письма не
   уходили пачкой.

Новая таблица `sender_seed_probes`: `day` (дата МСК), `mailbox_id`,
`seed_box_id`, `provider`, `subject`, `message_id`, `scheduled_at`,
`sent_at`, `status`, `folder`, `checked_at`, `attempts`, `error`.
Уникальность `(day, mailbox_id, provider)`: повторный запуск планировщика
дублей не даёт. Хранение 90 дней.

Статусы: `planned` → `sent` → `inbox` | `spam` | `missing`; ошибки:
`send_failed` (SMTP отказал), `check_failed` (не вошли в контрольный ящик:
проба не засчитывается ни в «входящие», ни в «спам»).

### 3.3 Отправка

Тик sender-воркера своего адреса (рядом с `sendPendingProbes`) берёт пробы
с наступившим `scheduled_at` для ящиков, закреплённых за его адресом, и
шлёт через `sendSenderMail` с `buildMessageId`. Так письмо уходит с того же
IP и с теми же заголовками, что и боевое.

Письмо: одна из 5–6 заготовок короткого делового текста на языке ящика
(RU/EN по папке, по умолчанию RU), без ссылок, картинок и счётчиков открытий,
подпись — имя отправителя ящика. Тема и текст выбираются случайно.

Пробы **не тратят** дневные лимиты ящика («новых в день» / «всего в день») и
не пишутся в `sender_messages`: в статистике писем и отбоев их нет.

### 3.4 Проверка папки

Ведущий воркер каждые несколько минут берёт пробы `sent` старше 30 минут,
группирует по контрольному ящику и на одно IMAP-подключение ищет каждую по
заголовку `Message-ID` во «Входящих» и в папке спама.

- нашлась во «Входящих» → `inbox`; в спаме → `spam`;
- не нашлась → повтор через 15 минут; через 2 часа после отправки →
  `missing`.

Письма **только ищутся**: не открываются, не помечаются прочитанными, не
переносятся и не удаляются. Иначе сервис решит, что человек достал письмо
из спама, и следующие результаты будут врать. Вкладку «Промоакции» Gmail
по IMAP не отличить от «Входящих»: считается «Входящими».

## 4. Экран

### 4.1 «Статистика» → «Доставляемость»

Под нынешними строками — подблок «Контрольные ящики · 7 дней», строка на
сервис:

> Яндекс — во входящих 52 из 65 · спам 12 · не дошло 1

Красным, если в спаме больше трети; жёлтым, если «не дошло» больше 10%.
Сервис без рабочих контрольных ящиков — серая строка «нет ящиков».
При фильтре по кампании считаются пробы только ящиков этой кампании.

Ссылка «Контрольные ящики (N)» открывает список: сервис, адрес, статус
входа, сколько проб принял за 7 дней; добавить (сервис, адрес, пароль
приложения), проверить, выключить, удалить.

### 4.2 «Где работает, а где нет» → «Ящики»

Колонка «Контроль»: результат последнего дня по сервисам буквами
«Я G M O» — зелёная (входящие), красная (спам), серая (не дошло /
не проверялось). Подсказка при наведении — дата и папка.

Подписи — одной строкой (правило «короткие подписи на экранах»).

## 5. Права и доступ

Список контрольных ящиков и статистика — у тех же, кто видит «Рассылку».
Пароли наружу не отдаются: роут списка возвращает только адрес и статус.

## 6. Чего не делаем

- не проверяем выключенные ящики и ящики вне идущих рассылок;
- не шлём копию боевого письма (решение пользователя: нейтральное);
- не ставим ящики на паузу и не пишем в чат;
- не трогаем старую проверочную отправку на один адрес
  (`sender_send_probes`): у неё другая задача — сверка заголовков.

## 7. Проверка

Новых тестовых файлов не заводим (правило проекта). Выбор контрольного
ящика по очереди и разбор «какая папка спама» — чистые функции; проверка
типов (`npm run typecheck:fast`) в CI. Вживую после выкладки: завести по
одному ящику каждого сервиса, дождаться дня, сверить статусы проб с тем,
что видно в самих ящиках.

## 8. Что нужно от пользователя

- завести по 5 ящиков Яндекс, Gmail, Mail.ru; включить двухфакторный вход
  и создать **пароль приложения** (Gmail — только так; Яндекс и Mail.ru —
  «пароли приложений» в настройках безопасности);
- для Outlook — 5 ящиков и, на втором этапе, доступ к Microsoft Entra
  для регистрации приложения.
