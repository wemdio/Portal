# «Наш автоаутрич» v2 — роутер типов цепочек (по RU_OUTREACH_HANDOFF CEO)

Дата: 2026-09-23. Ветка: `polza-ru-outreach`. Заменяет модель трёх ручных офферов из
`2026-09-22-polza-ru-outreach-design.md`; остальное (журнал, дословные цитаты, почта,
библиотеки, загрузки, экран) сохраняется.

Решения пользователя 23.09.2026: автоматический выбор типа цепочки заменяет ручные
офферы; во всех цепочках 4 письма; тексты шести цепочек и кейсов — черновики Claude
на согласование CEO.

## Поток

1. **Сбор** из выбранных источников: hh.ru (вакансии продаж), Яндекс.Директ
   (`yandex_direct_results`), AMO (старые отказы), загрузки (выставки, госконтракты,
   списки грантов/акселераторов), новости сайтов (компании прошлых запусков), общая база
   (`companies_directory`: сайт, выручка, сотрудники, не розница/общепит/гостиницы/быт).
   Склейка по ИНН → домен → hh employer → название.
2. **AMO/стоп-лист до генерации.** Индекс AMO по домену сайта/почты и ИНН (все воронки):
   открытая сделка → `AMO_OPEN_DEAL`, клиент → `AMO_CLIENT`, отказ < 30 дней →
   `CRM_RECENT_CONTACT`, отказ с записанным разговором → reactivation.
3. **Обогащение до поиска почты:** домен, один обход сайта, один вызов LLM (B2B, бренд со
   страницы, продукт, клиенты, исключения, события сайта, ЦА-балл 0–10 + причина по брифу
   Polza, отраслевая группа для кейса), счётчик Директа на главной, для hh — карточка и
   цитата продаж.
4. **Скоринг 0–100 (pre-LPR rerank):** сила сигнала 0–30, свежесть 0–15, ЦА-балл 0–20,
   B2B 0–10, размер (выручка/сотрудники) 0–10, сайт 0–5, кейс 0–5, почта 0–5.
   Пороги (форма, по умолчанию CEO): ≥90 пишем; 70–89 пишем при почте и кейсе;
   50–69 ручная проверка без поиска почты; <50 пропуск.
5. **Роутер цепочки** по приоритету: reactivation → hiring → ad_budget → event →
   growth_event → icp_only (ЦА ≥ 7) → review.
6. **Роутер кейса** по отраслевой группе: it_saas, manufacturing, hr_education, horeca,
   auto_logistics, digital_agency. Кейс только утверждённый; нет — письмо 3 без кейса.
7. **4 письма:** 1 повод (или routing на общий ящик), 2 боль + что делает Polza,
   3 доказательство (кейс / гипотеза сегментов при подтверждённом рынке / механика),
   4 мягкое закрытие.
8. **QA + выгрузка** с полями CEO: chain_type, signal_type, signal_evidence, signal_url,
   ta_score, ta_reason, amo_status, recipient_email, email_verification, case_id,
   case_match_reason, case_text_approved, campaign_hypothesis, subject_a/b, email_1..4,
   qa_status, qa_errors. QA дополнительно запрещает служебные слова (score, pipeline,
   validation, pre-scoring…) и цепочку при открытой сделке/клиенте.

## Сигналы и доказательства

- hiring: вакансия продаж жива в hh, цитата функции продаж (A) или название (B).
- ad_budget: домен найден в выдаче Директа (B, запрос и дата). Счётчик Директа на сайте —
  только баллы скоринга, в письмо не попадает.
- event: строка загруженного каталога выставки (B).
- growth_event: событие на сайте с датой (A), загруженный список грантов/акселераторов (B),
  госконтракт (B), партнёрская/дилерская программа (A).
- icp_only: без события; письмо не называет повод, только цитату сайта о клиентах (если есть).
- Российского источника грантов/инвестиций в портале нет — только загрузка файла.
