# «Наш автоаутрич» — русский сигнальный аутрич Polza

Дата: 2026-09-22. Ветка: `polza-ru-outreach`. Статус: дизайн утверждён пользователем.

Источник требований — комплект ТЗ `G:\polza-manual-outreach-3-specs-2026-09-22\`
(00_START_HERE, LAUNCH_INSTRUCTIONS_INDEX, INSTRUCTION_02/03, SOURCE_CONNECTORS,
POLZA_SIGNAL_OUTREACH_SPEC, CASE_LIBRARY_INPUT_TEMPLATE) и
`polza_ru_правила_генерации_цепочек.txt`. При конфликте приоритет у файлов от
22.09 (три письма в SDR/автоматизации), четыре письма — только у оффера «по
сигналам» (SPEC §12, строка «прочий подтверждённый realtime-сигнал»).

## 1. Что делаем

Новый инструмент «Наш автоаутрич» (`/tools/polza-ru-outreach`, группа «Аутрич»,
под `InDevelopmentGate`). Оператор выбирает оффер, задаёт свежесть, лимит
**готовых** компаний и источники; движок волнами собирает компании, отсеивает,
находит почту, собирает цепочку, прогоняет QA и отдаёт Excel. Писем не отправляет.

| Оффер (`profile_code`) | Писем | Источники в этой версии |
|---|---:|---|
| Найм SDR (`sdr_hiring_v1`) | 3 | hh.ru |
| Автоматизация аутрича (`automated_outreach_v1`) | 3 | AMO (прошлые лиды/клиенты), hh.ru (≥2 вакансии продаж), сайты компаний |
| По сигналам (`signals_v1`) | 4 | hh.ru (вакансии продаж шире SDR), госконтракты, выставки (загрузка каталога файлом), новости и разделы «Партнёрам/Дилерам» на сайтах |

Широкий ICP (`broad_icp_v1`) — вне этой версии.

Профиль фиксируется точкой запуска. Неподходящая строка получает `rejected` или
`manual_review` с кодом причины и никогда не переводится в другой оффер.

## 2. Архитектура

Отдельный модуль `app/src/lib/polzaRuOutreach/` рядом с английским
`polzaOutreach/` (английский не трогаем). Переиспользуем: `parser_jobs` +
`claimParserJob`, волновой раннер (лимит считает готовые строки),
`scrapeEmails(locale:'ru')`, `callOpenRouterChat`, `extractNumberFacts`.

Задача — строка `parser_jobs` с `parser_type='polza_ru_outreach'`. Выполняет её
существующий контейнер `worker-polza-outreach`: воркер держит отдельный слот под
каждый тип, русский запуск не ждёт английский и наоборот. Новый контейнер и
правки compose не нужны.

```
polzaRuOutreach/
  types.ts           профили, конфиг, статусы, коды причин, санитайзер
  runner.ts          общий волновой конвейер + диспетчер по профилю
  profiles/sdr.ts, automation.ts, signals.ts   источник, ICP, выбор режима, сборка
  sources/hhPool.ts        кандидаты из hh_vacancies (словари должностей)
  sources/hhCard.ts        полный текст и статус вакансии из api.hh.ru
  sources/amo.ts           прошлые лиды из amo_leads
  sources/uploads.ts       загруженные каталоги выставок и выгрузки контрактов
  sources/siteSignals.ts   обход сайта + LLM-классификация фактов с цитатой
  analyze.ts         LLM-разбор вакансии (функция SDR, рынок, B2B, агентство)
  evidence.ts        дословная сверка цитат, нормализация текста
  company.ts         бренд без ООО/АО, домен, дедуп
  findEmail.ts       корпоративная почта, RU-приоритет ящиков, routing-флаг
  libraries.ts       активные офферы/кейсы/подписи
  letters/*.ts       фиксированные шаблоны трёх офферов
  qa.ts              автоматический QA
  export.ts          колонки Excel (готовые строки и журнал)
```

## 3. Данные

Миграция `supabase/migrations/20260922_0008_polza_ru_outreach.sql`:

- `polza_ru_outreach_companies` — строка на компанию в запуске (журнал). Поля:
  профиль, источник (`source_type`, `source_record_id`, `source_url`), компания
  (`company_name`, `company_brand`, `inn`, `normalized_domain`, `company_website`,
  `hh_employer_id`, `crm_lead_id`), отношения (`prior_contact`,
  `prior_contact_date`), сигнал (`signal_type`, `signal_date`, `signal_title`,
  `evidence_quote`, `evidence_level`, `market_evidence_quote`, `target_market`,
  `signals jsonb` — все найденные), `generation_mode`, `fit_reasons jsonb`,
  `signal_score`, почта (`recipient_email`, `email_type`, `email_source_url`,
  `recipient_role`, `is_routing`), письма (`letters jsonb`, `subject_b`),
  версии (`case_id`, `offer_version`, `offer_claim_ids`, `sender_id`,
  `template_version`), QA (`qa_status`, `qa_flags`), конвейер (`row_status`,
  `pipeline_stage`, `reason_code`, `reason_detail`).
- `polza_ru_offer_claims` — утверждённые коммерческие утверждения
  (`profile_code`, `claim_key`, `claim_text`, `status draft/approved/expired`,
  `approved_at`, `expires_at`, `approved_by`).
- `polza_ru_cases` — библиотека кейсов по шаблону CASE_LIBRARY_INPUT_TEMPLATE.
  В письмо попадает только `status='approved'` и `legal_publication_approved`
  и не истёкший.
- `polza_ru_senders` — подписи; сид: Егор, Коммерческий директор, Polza Agency,
  +7 (495) 120-29-71, https://polzaagency.ru, @ROP_PolzaAgency.
- `polza_ru_signal_uploads` + `polza_ru_signal_rows` — загруженные файлы
  сигналов двух видов: `exhibitors` (событие, даты, официальный URL каталога,
  год; строки — компания, сайт, ИНН, стенд, категория) и `contracts` (строки —
  номер, дата, предмет, сумма, заказчик, поставщик, ИНН поставщика, ссылка).

RLS как у английской таблицы (видимость через `parser_jobs.user_id`),
библиотеки — чтение/запись любому авторизованному пользователю инструмента;
`grant ... to service_role` на все таблицы.

«Ранее выгружена» = есть `ready`-строка в любом прошлом запуске с тем же доменом
или ИНН; такие компании исключаются (`PREVIOUSLY_EXPORTED`), если оператор не
включил `include_previously_exported`. Дедуп общий для всех трёх офферов.
Почта в `sender_suppressions` → `SUPPRESSED_CONTACT`.

## 4. Конвейер

Общий порядок стадий (коды стадий = `pipeline_stage`):
`candidates_loaded → source_checked → company_resolved → deduplicated →
icp_checked → evidence_classified → recipient_resolved → sequence_assembled →
qa_checked → ready`. Падение строки не останавливает запуск; сбой источника или
библиотеки переводит запуск в `failed`.

### 4.1 Найм SDR

1. Кандидаты: `hh_vacancies` за окно свежести (по умолчанию 45 дней), название
   по словарю SDR/BDR/менеджер по развитию/активных продаж/B2B/РОП/коммерческий
   директор/партнёрства/дилерская сеть/экспорт; группировка по `employer_id`,
   сохраняются все URL, берётся свежайшая.
2. Карточка из `api.hh.ru/vacancies/{id}` через `fetchWithRetry` из
   `lib/parsers/hhParser.ts` (OAuth `HH_ACCESS_TOKEN` и RU-прокси `PROXY_URLS`,
   без них hh отвечает 403): полный текст, `archived`. Архив или
   404 → `VACANCY_CLOSED`.
3. LLM-разбор (JSON, temperature 0): цитата SDR-функции, цитата рынка, B2B,
   кадровое агентство/конкурент/B2C. Цитаты сверяются дословно с нормализованным
   текстом; не сверилась → считается отсутствующей.
4. Нет подтверждённой SDR-функции → `SDR_EVIDENCE_MISSING` (отсев). Нет цитаты
   рынка → `generic_market` (не отсев).
5. Домен: сайт работодателя из hh (`company_site_url`, иначе `api.hh.ru/employers/{id}`).
6. Почта; общий ящик → routing-вариант письма 1.
7. Письма — шаблоны INSTRUCTION_02 дословно; кейс только из библиотеки (LLM
   выбирает из списка активных кейсов по тегам или «нет», код проверяет id).

### 4.2 Автоматизация аутрича

Источники (выбирает оператор): `crm` (AMO), `hh_multi` (≥2 активные вакансии
продаж с outbound-функцией за окно). Фильтр отношений: cold / prior_contact / mixed.

- `prior_contact=true` только по AMO: сделка с совпадающим доменом сайта или
  почты и хотя бы одним примечанием (разговор был); дата — последнее обновление.
  Остальные строки — cold, «мы с вами уже общались» им запрещено.
- Сайт: главная и разделы продуктов/решений/отраслей/регионов/партнёров/дилеров;
  LLM возвращает факты с дословной цитатой и URL: `b2b_product`,
  `multiple_products`, `multiple_regions`, `partner_program`.
- Допуск: CRM — B2B подтверждён; cold — ≥2 независимых средних признака
  (`multiple_sales_vacancies`, `multiple_products`, `multiple_regions`,
  `partner_program`), иначе `AUTOMATION_FIT_TOO_WEAK`.
- Режим: `relationship` / `evidence` / `generic_fit`. Шаблоны INSTRUCTION_03
  дословно; `verified_signal_block` — одна фраза по сигналу с цитатой.

### 4.3 По сигналам

Источники (выбирает оператор):
- `hh_sales` — вакансии продаж по расширенному словарю; сильный сигнал по SPEC §3.4
  (≥2 вакансии за 30 дней, РОП/коммерческий, прямо указан холодный поиск/новый
  рынок/дилеры, названа B2B-аудитория).
- `contracts` — заключённые госконтракты за окно свежести выше порога суммы;
  сигнал `contract_won` (предмет, заказчик, дата, ссылка ЕИС). Проверено
  22.09.2026: бесплатного API нет (GosPlan требует ключ, ClearSpending не отдаёт
  свежие данные, zakupki.gov.ru недоступен из-за рубежа), поэтому контракты
  загружаются файлом — выгрузкой результатов поиска ЕИС (CSV/Excel), как и
  каталоги выставок. Адаптер GosPlan — позже, при появлении ключа.
- `exhibitors` — строки загруженных каталогов (событие в окне T−90…T+14).
- `site_news` — новости/пресс-центр/«Партнёрам»/«Дилерам» у компаний, уже
  встречавшихся в прошлых запусках, и как второй сигнал для кандидатов из
  других источников. Событие считается свежим только с датой на странице.
  Типы: `product_launch`, `new_region`, `new_office`, `new_production`,
  `partner_program`, `dealer_search`, `export_launch`, `new_case`.

Сигналы компании объединяются, выбирается один сильнейший и свежий; скоринг
SPEC §10 (ICP, intent, бюджет, свежесть, второй сигнал, evidence, контакт),
порог по умолчанию 8, задаётся в форме.

Четыре письма (template_version `signals_v1`): 1 — сигнал по шаблону типа
сигнала + что делает Polza + низкопороговый CTA, две темы; 2 — механика,
утверждённый кейс или блок без кейса, CTA; 3 — гипотеза: LLM даёт два сегмента,
2–3 признака отбора и исключения (JSON), код собирает текст с формулировками
гипотезы; при неподтверждённом рынке — только общие формулировки; 4 — короткое
закрытие с бинарным CTA. Письмо 4 короче писем 2 и 3.

## 5. Evidence и режимы

A — дословная цитата из первоисточника; B — структурное поле источника
(должность, событие, контракт); C/NONE — вывод или только ICP. Персонализация
только по A/B, одна основная мысль. Любая несверившаяся цитата → строка
пересобирается в generic, не переписывается.

## 6. QA (qa.ts)

Для каждой строки: ровно N писем профиля; нет `{{…}}` и служебного текста;
подпись совпадает с sender; кейс совпадает с библиотекой дословно; каждое число
в тексте есть в утверждённом claim или кейсе (`extractNumberFacts`); ≤1 вопроса
в письме (CTA); тема не похожа на отклик кандидата; нет запрещённых слов
(срочно, уникальн, гарантир, последний шанс, мы лучшие, восклицательные знаки,
эмодзи); «уже общались» только при `prior_contact`; рынок упомянут только при
цитате рынка; evidence-цитата найдена в источнике. Провал → `manual_review` с
флагами; строка не редактируется свободной генерацией.

## 7. Экран

Страница по образцу английской: вкладки «Запуск» и «Библиотеки».
- Форма: оффер, источники оффера, свежесть, лимит готовых, фильтр отношений
  (автоматизация), порог сигнала (сигналы), «включать ранее выгруженные», подпись.
- История запусков, воронка по стадиям с причинами отсева, разворот строки с
  письмами, цитатой и ссылкой.
- Выгрузка Excel: «Готовые» (колонки из инструкций профиля) и «Журнал» (все
  строки с этапом и причиной).
- «Библиотеки»: таблицы кейсов, утверждений оффера, подписей — добавить,
  изменить, утвердить/снять, срок действия; загрузка каталога выставки или
  выгрузки контрактов ЕИС (Excel/CSV).

hh (read-only) и на сборке писем всех развилок. Локальный dev-сервер не
поднимаем.
