# Квалификация ответов «Рассылки» и лиды в ТГ-чат — дизайн

Дата: 29.09.2026. Ветка: `dmitriy_kuladmed_new`.

## Зачем

Английский автоаутрич готов к запуску и шлёт письма через «Рассылку» (`lib/sender`).
Ответы портал уже забирает из ящиков (`sender_replies`) и показывает на вкладке
«Письма», но никто не решает, лид это или нет, и никому не сообщает.

Существующие механизмы не подходят:
- клиентские кабинеты (`/client/replies`, бот в личку) и автопередача коллеги
  (`lib/instantly/leadQualificationWorker.ts`) работают только с ответами Instantly;
- ходить по кабинетам неудобно — всё должно быть видно на портале, лиды — в одном ТГ-чате.

## Решения пользователя

- Оцениваются **все** ответы «Рассылки»: папки `auto_en`, `auto_ru` и ручные рассылки.
- Критерии лида — **правила коллеги целиком** (`qualifyReply` из `lib/instantly/leadQualifier.ts`)
  плюс своё правило «что считать лидом» у папки, с приоритетом (как `projects.lead_criteria`).
- После оценки — **только оповещение** в ТГ. Отвечает человек сам с портала. Готовых ответов
  лиду и кнопки «Отправить» нет.
- **Один общий чат**: группа «Продажи Polza» (`-1001852890744`), подчат General.
  Бот — существующий «Polza Site Feedback».
- В AMO сделки **не заводим** автоматически — менеджер заводит сам.
- Оцениваются только ответы, пришедшие после запуска. Старые не трогаем.

## Как работает

1. Воркер «Рассылки» (хосты 144 / 77.239.125.235) как сейчас забирает ответ по IMAP,
   регулярками отсекает автоответы, отбойники, прогрев и отписки (`sender_replies.kind`).
2. Новый цикл **в воркере `worker-instantly-leads` на 139** раз в минуту берёт живые ответы
   (`kind = 'human'`, `recipient_id is not null`), у которых ещё нет оценки.
   Почему здесь: у этого воркера уже есть ключ и модель, на которых обкатаны правила коллеги
   (`OPENROUTER_INSTANTLY_LEAD_API_KEY`, `INSTANTLY_LEAD_QUAL_MODEL`). Хосты «Рассылки»
   намеренно изолированы и ключей ИИ не имеют. Новый контейнер не нужен.
   Цикл отдельный, со своей обработкой ошибок: его падение не должно ронять циклы Instantly.
   Включается переменной `SENDER_LEADS_ENABLED=true`.
3. Цикл собирает переписку из нашей базы и приводит её к `ThreadContext`:
   - `threadEmails` — отправленные письма получателю (`sender_messages`, `status = 'sent'`)
     и его ответы (`sender_replies`) по времени;
   - `replyEmail` — оцениваемый ответ; `lastOutbound` — последнее наше письмо до него.
   Вызывает `qualifyReply` с готовым контекстом (`prefetchedContext`) — к Instantly
   за перепиской он не ходит. Бриф передаётся пустой строкой (не `null`), чтобы не искать
   бриф кампании в Instantly-базе; контекст оффера — наши собственные письма.
   `leadCriteria` — правило папки рассылки, если задано.
4. Результат пишется в новую таблицу оценок (ниже).
5. Если лид и по этой переписке в чат ещё не писали — бот шлёт сообщение.

Ответы без привязки к получателю («Непривязанные ответы») не оцениваются: без наших писем
нет контекста. Они остаются на вкладке как сейчас.

Если в одной переписке несколько живых ответов, оценивается каждый, но в чат по переписке
пишем **не больше одного раза**.

## Данные

Новая таблица `sender_reply_qualifications` (основная БД, `supabase/migrations/`):

| колонка | смысл |
|---|---|
| `reply_id` uuid PK → `sender_replies(id)` on delete cascade | один ответ — одна оценка |
| `recipient_id` uuid → `sender_recipients(id)` on delete cascade | переписка |
| `status` text | `pending` / `lead` / `not_lead` / `error` / `skipped` |
| `ai_reason` text | объяснение ИИ (по-русски) |
| `interest_signals` text[] | сигналы интереса |
| `criteria_used` boolean | было ли правило папки |
| `model` text | какой моделью оценено |
| `attempts` int, `next_attempt_at` timestamptz, `last_error` text | повторы при сбоях |
| `qualified_at` timestamptz | когда оценено |
| `tg_sent_at`, `tg_message_id`, `tg_error` | доставка в чат |
| `created_at`, `updated_at` | |

`grant ... to service_role` обязателен (правило `tests/migrations/grants.test.ts`).

Итог по переписке и ручная правка — колонки в `sender_recipients`:
- `lead_verdict` text null — `lead` / `not_lead`: последнее решение ИИ или человека;
- `lead_verdict_source` text null — `ai` / `manual`;
- `lead_verdict_at` timestamptz, `lead_verdict_by` uuid null.

Ручная правка имеет приоритет: если человек поставил «Не лид», новая оценка ИИ по той же
переписке метку не перебивает.

Правило папки: `sender_folders.lead_criteria text` (до 2000 символов, проверка в БД).

**Старые ответы:** миграция создаёт строки `status = 'skipped'` для всех уже существующих
`kind = 'human'` ответов — цикл берёт только ответы без строки оценки, поэтому в работу
попадают лишь новые.

Представление `sender_threads` дополняется `lead_verdict`, `lead_verdict_source` для
метки и фильтра на вкладке.

## Сбои

- ИИ недоступен или вернул мусор → `attempts + 1`, `next_attempt_at` с растущей паузой
  (1, 5, 15, 60 мин), после 5 попыток — `error`, ответ виден на портале без метки.
- ТГ недоступен → оценка сохраняется, отправка повторяется отдельно до 5 раз, ошибка — в `tg_error`.
- Две копии цикла не должны оценить одно и то же: строка оценки создаётся вставкой
  `on conflict do nothing` до вызова ИИ; кто не вставил — пропускает.

## ТГ-сообщение

Переменные прода (в `.env` на 139 и `environment` у `worker-instantly-leads`):
`SENDER_LEADS_TELEGRAM_BOT_TOKEN` (токен «Polza Site Feedback»),
`SENDER_LEADS_TELEGRAM_CHAT_ID=-1001852890744`, `SENDER_LEADS_TELEGRAM_THREAD_ID` —
пусто = General (номер подчата не передаётся).

Бот только **отправляет** сообщения: никаких кнопок и `setWebhook` — обновления бота
принимает сторонний сервис лидмагнита, трогать их нельзя. Соседний бот проверки передачи
проектов (`app/worker/handoffCheckBot.ts`) слушает только ветку 3781 и наши сообщения
не затрагивает.

Формат (HTML, в пределах 4096 символов):

```
📨 Новый лид из Рассылки
Папка: Автоаутрич EN · Рассылка: <название>
Контакт: <имя> (<email>)
Компания: <recipient.name>
Тема: <тема ответа>

Ответ:
<pre>текст ответа, до 1200 символов</pre>

ИИ: <объяснение>

🔗 Открыть переписку  → <PORTAL_PUBLIC_URL>/tools/sender?tab=threads&thread=<recipient_id>
```

## Портал

- «Рассылка» → «Письма»: метка «Лид» / «Не лид» у переписки, фильтр «Только лиды».
- Окно переписки: объяснение ИИ и кнопки «Это лид» / «Не лид» (ставят ручную метку,
  в чат ничего не шлют).
- Ссылка `?tab=threads&thread=<id>` сразу открывает переписку.
- Настройки папки: поле «Что считать лидом» (текст до 2000 символов, пусто — общие правила).
