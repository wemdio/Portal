# LinkedIn Outreach: создание баз окном и очередь баз в кампании

Дата: 24.10.2026. Заказчик: Дмитрий К. (по образцу создания базы в TG Outreach).

## Зачем

Сегодня во вкладке «Базы» кампании: длинное поле «Название новой базы», кнопки «Создать базу» и
«Новая база из CSV с инвайтами», а скрапер живёт отдельной вкладкой. Кампания рассылает ровно одну базу
(`li_campaigns.lead_list_id`), переключать её приходится руками.

Нужно: базу создают одним окном, а несколько баз выстраиваются в очередь — закончилась первая, кампания
сама начала вторую, потом третью.

## Цели

1. Одна кнопка «+ Создать базу» вместо поля и двух кнопок.
2. В окне создания два способа: собрать скрапером (параметры задаются здесь же, результат виден здесь же)
   или загрузить CSV (простой или с персональными инвайтами; подсказка с колонками).
3. У баз кампании есть порядок. Когда рассылаемая база закончилась, воркер сам берёт следующую.
4. Порядок видно и меняется на вкладке «Базы» (номер, стрелки вверх/вниз).

## Не цели

- Пополнять уже сохранённую базу. База после сохранения неизменна, поэтому пункт «Загрузить CSV» в
  существующую базу и ссылка «Собрать скрапером» из карточки убираются.
- Вкладку «Скрапер» верхнего уровня не трогаем.
- Параллельная рассылка нескольких баз. Одновременно рассылается одна.

## Окно «Создать базу»

- Поле «Название» + выбор способа: «Собрать скрапером» / «Загрузить CSV».
- **Скрапер.** Поля как на вкладке «Скрапер»: тип (поиск по URL / реакции на пост), URL, аккаунт, сколько
  собрать. «Собрать» создаёт черновую базу (без кампании, чтобы не светиться на вкладке) и запускает задачу
  с `lead_list_id` этой базы. В окне идёт прогресс (опрос задачи), по готовности — список собранных людей.
  Кнопки: «Пересобрать» (удаляет черновую базу, создаёт новую с тем же именем, запускает заново) и
  «Использовать эту» (привязывает базу к кампании — она встаёт в конец очереди). Закрытие окна без
  «Использовать» отменяет идущую задачу и удаляет черновую базу.
- **CSV.** Переключатель «Простой» / «С персональными инвайтами». Подсказка с колонками под переключателем:
  - простой: `name` (или `first_name` и `last_name`) и ссылка на профиль `profile_url`
    (допустимо `public_identifier` или `linkedin_id`); необязательно `position`, `company`;
  - с инвайтами: `LinkedIn ID` (имя лида) и `Invite` (текст инвайта); необязательно `position`, `company`,
    `profile_url`.
  «Сохранить» создаёт базу, заливает файл и показывает итог (сколько загружено/пропущено).
- Первая база кампании сразу становится рассылаемой (как сейчас).

## Очередь баз

- Колонка `li_lead_lists.queue_position` (int). Триггер БД проставляет следующий номер в рамках кампании,
  когда у базы появляется `campaign_id`. Миграция раздаёт номера существующим базам: рассылаемая — первой,
  остальные по дате создания.
- API: `PUT /lead-lists/[id]` принимает `queue_position`; перестановка стрелками меняет номера соседей.
- Воркер (`campaignRunner`, начало тика, после `enrollActiveBase`): если у рассылаемой базы есть люди, все они
  уже в рассылке и ни у кого нет статуса `pending`/`in_progress`/`waiting` — база закончилась. Берётся база
  кампании со следующим по порядку `queue_position`, где есть люди; её id пишется в `lead_list_id`,
  в журнал кампании — запись «База закончилась, начата следующая: …». Если следующей нет — ничего не меняем.
  Кампания без рассылаемой базы берёт первую по порядку.
- Пустая рассылаемая база не считается закончившейся (в неё могут ещё лить).
- Кампании с одной базой работают как раньше.

## Решения, принятые без заказчика (можно поменять)

- «Закончилась» = нет лидов в `pending`/`in_progress`/`waiting`; лид в ожидании следующего шага цепочки
  считается незавершённым.
- Порядок по умолчанию — по созданию, переставляется стрелками.
- Черновая база скрапера не привязана к кампании, пока не нажато «Использовать».

## Порядок реализации

1. Окно создания базы (скрапер и CSV), упрощённый верх вкладки «Базы», убрать «Загрузить CSV» из меню.
2. Колонка очереди, триггер, API перестановки.
3. Переключение баз в воркере.
4. Номера и стрелки в списке баз.

Новых тестов не пишем (правило проекта).
