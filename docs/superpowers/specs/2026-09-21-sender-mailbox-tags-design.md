# Теги ящиков рассылки — дизайн

Дата: 2026-09-21. Ветка: `dmitriy_kuladmed_new`.

## Зачем

На вкладке «Ящики» инструмента «Рассылка» лежит 218 ящиков одним постраничным
списком по 30 строк. Найти в нём конкретный адрес или группу доменов нельзя:
поиска на экране нет, признака принадлежности у ящика тоже. Теги дают то же,
что они дают в Instantly, — разбиение пула на осмысленные группы, по которым
список фильтруется.

Ограничение принято владельцем: **один ящик — один тег**. Это не метки, а
категория; отсюда колонка в таблице ящиков, а не связь «многие ко многим».

## Что делает пользователь

1. Открывает окошко тегов, жмёт «+ Тег», вводит название, сохраняет — тег
   появляется в списке сразу, без перезагрузки страницы.
2. Отмечает галочками ящики в таблице, в панели выделения выбирает
   «Под тег → <название>». Если у части выделенных тег уже стоит, портал
   спрашивает подтверждение с числом: «у 3 из 10 уже есть тег, заменить?».
3. Фильтрует список: в окошке тегов отмечает один или несколько тегов
   (или «Без тега») — в таблице остаются только они.
4. Ищет ящик по адресу строкой поиска слева от кнопки тегов.
5. Правит опечатку в названии тега карандашом, ненужный тег удаляет корзиной.
   Удаление тега снимает метку с ящиков; сами ящики остаются.

## Экран

Полоса над таблицей ящиков, под блоком «Подключить ящики файлом»:

```
[ Поиск по адресу…                    ]   [ Теги (2) ▾ ]
```

Окошко «Теги» (поповер под кнопкой):

- пункт «Без тега» — ящики без метки;
- список тегов: галочка фильтра, название, счётчик ящиков, карандаш, корзина;
- внизу «+ Тег» — открывает модалку с одним полем названия.

Таблица: новая колонка «Тег» между «Провайдер» и «В рассылке» — серый чип с
названием или прочерк.

Панель выделения: новая кнопка «Под тег ▾» рядом с «Проверить / Не
использовать / Использовать / Удалить». В меню первым пунктом «Без тега»,
дальше теги по алфавиту.

## Данные

Новая миграция `20260921_0001_sender_mailbox_tags.sql`:

- таблица `public.sender_mailbox_tags` — `id`, `name`, `created_at`,
  `created_by`. Уникальность имени без учёта регистра (уникальный индекс по
  `lower(name)`): два тега «Wolly» и «wolly» — это ошибка ввода, а не два тега;
- колонка `sender_mailboxes.tag_id` → `references sender_mailbox_tags(id) on
  delete set null`. Удаление тега обнуляет метку у ящиков одним действием базы,
  без обхода строк в коде;
- индекс по `sender_mailboxes (tag_id)` — под фильтр;
- RLS включён, `grant all ... to service_role`, как у остальных `sender_*`
  таблиц: пользователи ходят только через `/api/tools/sender/**`.

## API

- `GET /api/tools/sender/tags` — список тегов со счётчиком ящиков.
- `POST /api/tools/sender/tags` — создать. Дубль имени → 409 с понятным текстом.
- `PATCH /api/tools/sender/tags/[id]` — переименовать.
- `DELETE /api/tools/sender/tags/[id]` — удалить.
- `GET /api/tools/sender/mailboxes` — добавляются параметры `tagIds` (список
  через запятую) и `noTag=1`. Отбор делает база, а не браузер: на экране лежит
  30 строк из 218, фильтрация на клиенте показала бы только совпадения текущей
  страницы. Поиск `search` уже поддержан, на экран выводится впервые.
- `PATCH /api/tools/sender/mailboxes` — к массовым действиям добавляется
  `action: 'tag'` с полем `tagId` (`null` — снять тег).

Ответ ящика получает `tag: { id, name } | null`.

## Решения и риски

**Список сам перезагружается раз в 15 секунд** — опрос статусов проверки
ящиков. Три места, где это ломает новый экран: опрос не должен терять
набранный поиск, гасить открытое окошко тегов и сбрасывать выделение. Поиск
уходит на сервер с задержкой 300 мс, чтобы каждая буква не стоила запроса.

**Смена поиска или фильтра возвращает на первую страницу и снимает галочки.**
Выделение в этом экране уже привязано к номеру страницы; после смены фильтра
те же строки означают других ящиков.

**Цветов у тегов нет** — серые чипы, как статусы рядом.

## Вне scope

Выбор ящиков в кампанию сразу по тегу (в Instantly теги нужны прежде всего для
этого) — отдельная задача, здесь не делается. Несколько тегов на ящик — прямо
отвергнуто владельцем.

Тесты не пишутся по правилу проекта («Правило: тесты пишем скупо» в CLAUDE.md).
Проверка — типы и сборка.
