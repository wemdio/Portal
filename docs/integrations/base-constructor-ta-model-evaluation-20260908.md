# Оценка ЦА: DeepSeek Flash и Gemini 3.8 Flash — 08.09.2026

## Решение и границы

Gemini 3.8 Flash (`vertex/gemini-3.8-flash`, `reasoning_effort=low`) в пилоте
оказался **в 7,8 раза быстрее, но в 2,1 раза дороже** текущего маршрута.
Это кандидат для ускорения, а не подтвержденная экономия или улучшение точности.
Продовую модель, общую Requesty policy, конфигурацию воркеров и данные заданий
не меняли. Деплой не выполняли.

В этом же изменении исправлена независимая проблема персонализации: пустые и
обрезанные HTTP 200 больше не принимаются как готовый текст. Этот исправленный
путь не использовался для модельного теста ЦА и не переключает никакие модели.

## Методика

- 120 компаний: по 40 различных пар «компания/сайт» из трех текущих заданий,
  с тремя настоящими брифами. Кандидаты строк выбраны равномерно по матрице,
  затем устранены повторы компании/сайта. Это пилот, не месячная статистика.
- Матрицы взяты на этапах ЦА, персонализации и обогащения. Последний источник
  обогащен лишь частично; второй уже проходил ЦА. Выборка не является случайной
  представительной выборкой всех пользователей. Прежние оценки и объяснения
  удалены из входа, чтобы исключить возобновление готовых оценок и подсказки.
- Основные email/телефонные колонки очищены. Это **не полностью обезличенные
  данные**: брифы и свободный текст могут содержать контакты. Полные входы,
  ответы и сопоставления хранятся только локально вне Git с правами 0700/0600.
- Исполнялся настоящий `stepTAScore` из `processingSteps.ts`, а не переписанный
  промпт: пачки по 10 компаний, две пачки одновременно, JSON, temperature 0.2,
  max_tokens 8000, тот же парсер, дедупликация и восстановление неполных пачек.
  У кандидата изменены только модель и `reasoning_effort=low`.
- Для каждого брифа оба профиля запускались одновременно. Итоговое время ниже —
  сумма трех отдельных прогонов данного профиля, без ожидания другого профиля.
- Baseline: запрос `policy/gemini-flash` тем же BRIEF-ключом; фактическая модель
  во всех ответах `deepseek-v4-flash`. Gemini отвечал как `gemini-3.8-flash`.
- Импорты БД, скраперов и других обработчиков заблокированы. Запросы только на
  endpoint Requesty chat completions; никаких обновлений рабочих заданий.
- Источник TA-кода: `f413496432e10cc41b2ceb9fc0d2f88a486c5cf3`; незакоммиченные
  изменения персонализации не меняли TA-функцию. Manifest содержит SHA-256
  фактического исходника, bundle, harness, fixture и каждого входного case.
  SHA-256 файла fixture: `c2c6431eb292a2c20b6f12c0ee9f722a8f921c7a652c36b4e2aaea104268bad7`.

## Цена токена и цена готовой оценки

На дату теста каталог Requesty сообщил за 1 млн входных/выходных токенов:

- `vertex/gemini-3.8-flash`: $0,75 / $3,75;
- `deepseek/deepseek-v4-flash-0731`: $0,44 / $1,32;
- `deepinfra/deepseek-v4-flash-0731`: $0,09 / $0,18.

Alias сам цену не публикует, а имя модели в ответе не определяет провайдера.
Поэтому для итогового сравнения использована реальная `usage.cost`, а не цена
угадываемого маршрута. Gemini дороже за токен; уменьшение reasoning не сделало
его дешевле за готовую оценку в данном прогоне.

[Google: Gemini 3.8, режимы reasoning и вводный тариф](https://ai.google.dev/gemini-api/docs/latest-model).
Для 3.8 поддерживаются low/medium/high; minimal не поддерживается. Вводный тариф
Google действует до конца 2026 года; будущие цены надо перепроверять.
[Requesty: API chat completions](https://docs.requesty.ai/api-reference/endpoint/chat-completions-create).

## Качество: не путать полноту с точностью

- Все оценки прочитаны настоящим парсером; порядок и исходные поля сохранены.
- Решение относительно текущего порога **7+ совпало у 104/120 (86,7%)**.
  У 16 компаний решение различается: 1/40, 7/40 и 8/40 в трех брифах.
- Точный балл совпал у 33/120; средняя абсолютная разница — 1,05 балла.
  DeepSeek пропустил 42 компании, Gemini — 38. Это различие калибровки, не
  доказательство, что одна модель точнее или что другая ошибается.
- Независимый агент до чтения ответов просмотрел 12 фиксированных строк:
  9 предположительно подходящих, 1 неподходящая, 2 неоднозначные. Это суждение
  второго AI-ревьюера, **не экспертная эталонная разметка** и не accuracy score.
  Есть расхождения с обеими моделями даже при согласии моделей между собой.
- Во входах обнаружено противоречие описания работодателя и описания сайта.
  Также текущий `brief.slice(0, 4000)` теряет часть продуктового GEO/AEO-контекста
  одного из брифов. Основные отраслевые критерии помещаются в префикс, но полнота
  продуктового контекста ограничена. Эти прежние особенности в тесте не менялись.

Рекомендация: проверить 16 пограничных решений со специалистом и затем отдельно
рассмотреть Gemini для ЦА ради скорости. Не менять общую policy: ее используют
персонализация и другие инструменты. «Дешевле и точнее» этим пилотом не доказано.

## Исправление персонализации

Общий helper `personalizationCompletion.ts` применяется только в трех путях:
табличный API, Base Constructor и DFYB. Первый запрос и модель прежние.

- Пустой/обрезанный ответ не является успехом. До 4 суммарных HTTP-попыток
  внутри одного вызова helper: транспортные и смысловые ошибки делят один лимит.
- Запрос с чтением тела: до 70 с; HTTP и backoff: общий бюджет 240 с.
  Внешняя проверка отмены через БД отдельно зависит от доступности БД.
- 1500 токенов сначала; только `length` повышает бюджет до 3000/6000.
  Пустой ответ сначала повторяется без повышения, последующие пустые повышают
  бюджет. Транспортные ошибки бюджет токенов не повышают.
- При постоянном `length` максимум запрошенных output-токенов за строку:
  1500 + 3000 + 6000 + 6000 = 16 500. Повторы могут увеличить стоимость и время;
  это защита полноты, а не обещание ускорения персонализации.
- В worker-результате ошибочный текст пустой; причина — в отдельной колонке
  «Ошибка персонализации», чтобы диагностика не стала текстом письма. При полном
  успехе структура результата прежняя. Успехи соседних строк и порядок сохранены.
- API после исчерпания попыток возвращает `retryable:false`; клиент учитывает его.
  После деплоя уже открытую таблицу нужно обновить: прежняя версия клиента этот
  флаг не знает и может повторить полный запрос.
  Неоднозначный сетевой обрыв/прокси-ответ по-прежнему допускает прежний повтор
  браузером: межзапросная идемпотентность здесь не добавлена.
- Обнаруженная отмена DFYB не превращается в `failed`.
- OutreachOS/GIS не запускают этот шаг; AutoPipeline использует отдельный путь.
  Настройки TA, генерации писем и глобальные routing policies не менялись.

Это **не** checkpoint персонализации при редеплое; такую гарантию изменение не дает.

Скрипт требует приватный fixture указанной схемы и новый каталог вне Git:

```sh
node app/scripts/base-constructor-ta-model-eval.mjs \
  --fixtures /absolute/private/fixtures.json \
  --out /absolute/private/new-dry-run
```

Для осознанного платного запуска добавить `--live --max-calls 40 --budget-usd 5`,
передав ключ только через `TA_MODEL_EVAL_API_KEY` во внешнем окружении процесса.
Скрипт не читает `.env`, не хранит ключ и не пишет в production. Перед повтором
проверить актуальную цену и полномочия на расход; клиентский резерв не заменяет
бюджет на стороне провайдера. Последняя защитная правка harness запрещает HTTP
redirect; live-пилот был выполнен до этой правки. Логика TA-запросов и парсера
после пилота не менялась.
