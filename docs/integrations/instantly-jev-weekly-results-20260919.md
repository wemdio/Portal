# Jev: недельный изолированный прогон, 19 сентября 2026

Продолжение: [настройка адаптера v2 и повторные проверки](instantly-jev-v2-evaluation-20260919.md).
Ниже сохранён исходный v1-результат без ретроспективной подмены метрик.

## Вывод

На 2 118 ответах за **12–18 сентября 2026, UTC+4** получены ответы
`jev-1.13.0`. Requesty для inference не использован. В этой конфигурации
замена рабочего классификатора на Jev **пока не рекомендована**: есть
подтверждённые по тексту ложные лиды и пропуски, а пример сарказма,
помеченный пользователем, снова принят за лид.

Это результат конкретного экспериментального контракта, не доказательство,
что Jev нельзя настроить лучше. Рабочий классификатор, БД, очередь,
Telegram, настройки моделей и deployment не менялись.

**Уточнение пользователя во время теста:** последние фиксы ещё не в prod.
Сохранённые старые решения нельзя использовать для оценки исправленного
обработчика или утверждения, что последние исправления не помогли.
Нового прогона действующей модели с исправленным кодом не было.

## Дизайн и воспроизводимость

- Источник и ограничения выборки: [подготовка](instantly-weekly-evaluation-20260919.md).
- Скрипт: `app/scripts/instantly-jev-weekly-eval.mjs`.
- Только прямой TypeSafe API, версия `jev-1.13.0`, concurrency 2.
- В запросах нет исторического статуса, причины старого ИИ или эталонной метки.
- Восемь независимых вопросов: общий бинарный вердикт, автор, назначение
  ответа, раскрытие оффера, действие, самостоятельность запроса, тон,
  выполнение кастомного критерия. Ответ на один вопрос не передаётся другому.
- Правила заморожены до массового прогона; 20 smoke-ответов использованы
  повторно из кеша, без повторного вызова. Порогов после просмотра не меняли.
- `questions_sha256`:
  `a6952bbbd6c20e23a3dc600384f168ecbb45748ab213dc0b67d8f4f61a1bf117`.
- Manifest хранит хеши исходных JSON, кода, правил и всех запросов. Журнал
  запроса пишется **до** API-вызова; незавершённый запрос нельзя молча повторить.
- Ограничения запуска: 2 200 исходных строк максимум, резерв бюджета $5,
  без автоматического повтора сетевых запросов. Эти ограничения — для
  разового теста, не политика рабочего обработчика.
- Email/телефон/URL минимизируются согласованными заменами внутри кейса.
  Это не полная анонимизация: имена/названия в естественном тексте остаются.

Два разных результата сохраняются отдельно:

1. **Прямой Jev** — его бинарный ответ на весь контракт.
2. **Экспериментальная сборка признаков** — решение локального кода из
   остальных ответов Jev. Это не голосование и не независимая модель.
   Улучшения/ошибки сборки нельзя целиком приписывать Jev.

Это расчёт, не сверка биллинга; у HTTP 400 нет usage. Время — длительность

Всего 2 121 HTTP POST: 2 118 первых попыток, один диагностический повтор
**отклонённого** запроса для получения error body и два исправленных входа.
Ошибки HTTP 400: `max_tokens_exceeded`. В двух цепочках текст содержал
огромные `data:image/...;base64,...`, которые исходный byte cap не устранил.
Был выполнен отдельный, явно отмеченный вариант: удалить только встроенные
бинарные данные **до** подготовки контекста и восстановить полный текст
из исходной выборки. Правила и модель не менялись. Оба запроса успешны.
Первоначальные ошибки сохранены, а не затёрты успешными результатами.

При первом HTTP 400 тест приостановился. Продолжение запускало только
не начатые запросы, проверяя frozen manifest; известные ошибки не повторялись.
Для первого ошибочного кейса выполнен один отдельный диагностический повтор.
Transport/diagnostic scripts и их журналы сохранены приватно рядом с отчётом.
Проверка размера в байтах **не гарантирует** соблюдения token budget;
до production нужны корректная обработка длинных цепочек и бинарного мусора.
Два других успешно обработанных входа были обрезаны исходным лимитом;
результаты таких входов не доказывают отсутствие оффера в полной переписке.

## Количество решений — не точность

| Вариант | lead | not_lead | Диагностически не разрешён |
|---|---:|---:|---:|
| Исторический снимок | 284 | 1 725 | 66 objection + 43 pending |
| Прямой Jev | 153 | 1 965 | 0 |
| Сборка признаков Jev | 189 | 1 899 | 30 |

30 диагностических случаев: 28 с неподтверждённой политикой проекта,
2 с неизвестным контекстом оффера. Это **не новая очередь** и не изменения
в production. Прямой бинарный ответ Jev имеется для всех этих писем.

Из 284 старых `lead` прямой Jev оставил 137 и отклонил 147.
Из 1 725 старых `not_lead` принял 13, отклонил 1 712.
Ещё 3 положительных пришлись на старые `objection`; все 43 `pending`
получили отрицательный ответ Jev. Эти изменения не равны исправленным
ошибкам: среди них есть и улучшения, и пропуски.

Сборка признаков отличается от прямого Jev в 130 случаях: 75 повышений,
25 понижений, 30 диагностических неопределённостей. Это показывает,
что атомарные ответы не являются логически согласованным объяснением
общего вердикта. Сборка тоже требует проверки, а не автоматического доверия.

## Слепая проверка случайных совпадений и расхождений

До просмотра предсказаний на выбранных письмах ассистент разметил 40 кейсов:
первые 40 по SHA-256 `blind-audit-v1:<id>` из holdout без известных coverage
warnings. Метки и причины зафиксированы отдельным файлом. Это предварительная
оценка ассистента, **не разметка специалистами**, и только один слой покрытия.

- 34 предварительно отрицательных, 6 положительных.
- Прямой Jev и сборка совпали с разметкой в 39 случаях; пропустили один
  положительный из-за неверного определения автора (`08036bf6...`).
- Старый снимок: 31/34 отрицательных были not_lead, 2 lead, 1 objection;
  5/6 положительных были lead, один not_lead. Обе системы пропустили один
  и тот же положительный — совпадение не доказывает правильность.
- Один кейс процедурного повторного запроса отсутствующего вложения помечен
  пограничным. Его метка не использовалась для донастройки.
- Эти 40 не дают точность/precision/recall по всем 2 118: мало положительных,
  нет экспертного gold и исключён слой с неполным покрытием. Никаких
  «97.5% точности на неделе» или «ошибок больше нет» из этого не следует.

## Что дальше

1. Не переключать production по одному снижению количества лидов.
2. Для следующей **новой** версии исправить роль автора, разделение нового
   текста и цитат, покупку/встречную продажу, расширяющие кастомные критерии
   и подготовку длинных входов. Высокий confidence не заменяет этих проверок.
3. Разобранные здесь holdout-кейсы стали видимыми. Не выдавать повторную
   настройку на них за независимую контрольную проверку новой версии.
4. Для сравнения именно с последними фикcами нужен отдельно разрешённый replay
   исправленного обработчика на сопоставимом контексте. Исторический снимок
   его не заменяет. В текущем запросе пользователь выбрал Jev-only.
