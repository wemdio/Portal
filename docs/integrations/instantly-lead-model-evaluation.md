# Instantly: изолированное сравнение моделей

## Пилот 7 сентября 2026

Предварительный кандидат для следующей проверки — **GPT-4o mini с сохранением текущих фильтров и постобработки**. Это результат диагностического пилота, а не основание автоматически переключать production или утверждать 100% точность на живом потоке.

Новая политика `policy/portal-instantly-lead-qualification` создана отдельно от общей `policy/gemini-flash`. В этом прогоне модели вызывались напрямую через Requesty: скрытый fallback не должен подменять сравниваемого кандидата. Подключение политики к production, изменение действующих политик, деплой и уведомления не выполнялись.

### Методика и ограничения

- 40 обезличенных реконструкций жалоб и синтетических контрастных примеров. Это **не случайная выборка реальных писем и не независимый hold-out**.
- 38 оцениваемых случаев: 17 основаны на явно согласованных пользователем правилах/примерах; 21 — на действующей политике. Пользователь не размечал заново каждую реконструированную формулировку. Эти группы сохраняются раздельно.
- Два спорных случая исключены из точности: неопределённый запрос материалов без восстановленного оффера и «Вы попали по адресу. Рассказывайте))» после запроса контакта.
- Для каждого кандидата использованы одинаковые контекст, production-промпты и параметры: `temperature=0.1`, `max_tokens=2000`, `response_format=json_object`. Один внешний вызов на случай; повторные попытки отключены для сравнения. Это не замер задержки всей очереди/Telegram.
- Ответ модели, приведение JSON, приоритет кастомных критериев и итог `qualifyReply` записаны отдельно. Итоговый статус вычисляется с порядком приоритетов рабочего обработчика, без запуска самого worker.
- На технических ответах ИИ намеренно проверяется даже там, где production-фильтр остановился бы раньше: это измерение дополнительной защиты. Успех фильтра не приписывается модели.
- Брифы пустые, контексты короткие: длинные реальные треды, длинные кастомные критерии, восстановление владельца, доставка уведомлений и очередь этим пилотом не проверялись.

Подход соответствует рекомендации проверять задачу на предметных примерах и отделять человеческие метки от модельных оценок: [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

### Результат

«ИИ» — содержательное решение из JSON до бизнес-правил, с проверкой типов без приведения строк к boolean. Отсутствующий JSON не засчитывается как правильный ответ. «Итог» — квалификатор с фильтрами и постобработкой.

| Запрошенная модель | Завершение | ИИ: верно | Итог: верно | p50 / p95 одного вызова | Сумма возвращённого `usage.cost`, USD |
|---|---|---:|---:|---:|---:|
| `openai/gpt-4o-mini` | 40/40 ответов | 34/38 | 38/38 | 1,612 / 2,317 с | 0,0152577 |
| `deepseek/deepseek-v4-flash-0731` | 40 HTTP 200, из них 5 без JSON | 33/38 | 36/38 | 5,075 / 15,012 с | 0,027237792 |
| `anthropic/claude-haiku-4-5` | 40/40 ответов в Markdown | 35/38 | 36/38 | 2,420 / 3,377 с | 0,242877 |
| `google/gemini-2.5-flash` | 21 ответ, затем HTTP 429; остановлен | 20/21 | 20/21 | 5,358 / 8,478 с | 0,0788614 |

Gemini не прошёл весь набор: 20/21 — правильность среди полученных ответов, не результат полного прогона. На общих 21 случае, для которых ответили все модели, GPT дал 21/21 верных исходных и итоговых решений; остальные — 20/21. Это маленький, специально подобранный набор, не рейтинг моделей вообще.

Раздельно по происхождению меток:

| Модель | Пользовательские правила: ИИ → итог | Политика: ИИ → итог |
|---|---:|---:|
| GPT-4o mini | 15/17 → 17/17 | 19/21 → 21/21 |
| DeepSeek | 16/17 → 17/17 | 17/21 → 19/21 |
| Haiku | 14/17 → 15/17 | 21/21 → 21/21 |
| Gemini, неполный прогон | 10/10 → 10/10 | 10/11 → 10/11 |

Фактически выполнено 142 запроса, без повторной оплаты уже полученных ответов. Сумма сообщённых Requesty затрат — $0,364233892; стоимость ошибочного 429 не сообщена. Это не сверка биллинга. Консервативный учёт скрипта составил $2,24569533: ответы возвращали короткие/датированные имена моделей, не совпадающие с ключами прайс-файла, поэтому скрипт оставил резерв вместо подстановки предполагаемой цены. Общий установленный для пилота предел оценки — $3.

### Что выявили

1. **DeepSeek пять раз не дошёл до ответа:** `finish_reason=length`, все 2000 выходных токенов заняли `reasoning_tokens`, содержимое пустое. Два оцениваемых случая остались `needs_review`, другие частично спасли фильтры. В production `classifyWithAI` повторяет такой запрос до двух дополнительных раз. Это подтверждённый механизм возможной задержки, но не доказательство причины конкретного исторического инцидента.
2. **GPT-4o mini сам ошибся четыре раза:** запрос материалов без истории отправил на проверку; после оффера не признал запрос материалов лидом; цитату запроса контакта принял за оффер; проигнорировал кастомное «поделились почтой». Код исправил все четыре результата.
3. **Все три полностью проверенные модели проигнорировали кастомное правило передачи почты** на одном и том же примере. Детерминированная защита исправила итог у всех. Замена модели не позволяет убрать защитные правила.
4. **Haiku пропустил два лида даже после постобработки:** запрос КП с адресом для отправки и имя с телефоном при соответствующем кастомном критерии. В последнем случае модель добавила отсутствующее обязательное условие просьбы созвониться.
5. **Gemini выдумал подтверждённый оффер по теме `Re: Offer`** и признал одиночное «Интересно» лидом без исходящего контекста. Тема в этом случае синтетическая; это проблема вывода в пилоте, не утверждение о конкретном письме из production. Затем провайдер вернул 429 `Resource has been exhausted` — повторять запросы и менять провайдера для обхода лимита не стали.
6. В production `buildUserMessage` при отсутствии API-исходящих объявляет любую найденную цитату длиннее 50 символов подтверждением оффера. Это противоречит системному правилу «запрос контакта — не оффер». GPT ошибся на таком примере, итоговый фильтр исправил результат. **Промпт в ходе сравнения не менялся**; исправление и отдельный A/B-прогон — следующая задача.

Haiku во всех 40 ответах использовал Markdown-обёртку. Первые три ответа первоначально остановили строгую проверку формата; после обнаружения этого различия тестовый скрипт научен снимать **только внешнюю обёртку** для оценки содержания, сохраняя нарушение формата отдельно. Оставшиеся 37 случаев запущены с `--start-index 3`. Первые три ответа не запрашивались заново; их содержание пересчитано локально. Production-парсер, промпты и метки не менялись.

### Воспроизводимость и безопасный запуск

Файлы:

- `app/scripts/instantly-lead-model-eval.mjs` — opt-in runner, **не входит в Jest/CI**.
- `app/scripts/fixtures/instantly-lead-eval-pilot.json` — версии примеров, метки и их происхождение.
- `app/scripts/fixtures/instantly-lead-eval-prices.json` — цены из авторизованного Requesty `/v1/models` на 07.09.2026; перед последующими live-прогонами обновить.

Из корня worktree, Node 22 и установленные `app/node_modules`:

```sh
node app/scripts/instantly-lead-model-eval.mjs \
  --fixtures app/scripts/fixtures/instantly-lead-eval-pilot.json \
  --models openai/gpt-4o-mini \
  --out /tmp/lead-eval-unique-dry-run
```

По умолчанию сеть не используется. Для платного прогона нужны явные `--live`, `--prices`, `--key-env` и ключ в окружении. Например, к команде выше добавляются:

```sh
--live --key-env REQUESTY_API_KEY \
--prices app/scripts/fixtures/instantly-lead-eval-prices.json \
--budget-usd 0.75 --max-calls 40 --timeout-ms 45000
```

Каталог `--out` должен быть новым, с существующим родителем. Ключ загружается отдельно из локального секретного окружения, не передаётся аргументом и не коммитится. Результаты и промпты — только в приватных файлах 0600, каталог 0700; внутри worktree разрешён только Git-ignored путь. Лимит скрипта — консервативная клиентская оценка, **не жёсткий лимит биллинга Requesty**. Таймаут может тарифицироваться провайдером; окончательная финансовая защита — лимит API-ключа.

Runner собирает исходный классификатор в изолированном контексте. Импорты БД и Instantly заменены запретом, worker не импортируется, единственный live-endpoint — Requesty chat completions, перенаправления запрещены. Сохранённый ответ проигрывается повторно локально, без второго сетевого вызова. Новые зависимости production, миграции и конфигурация worker не добавлялись.

Проверены: полный dry-run 40 × 4; локальная симуляция сетевого участка и Markdown; `node --check`; 81 существующий тест квалификатора/парсера; независимое сопоставление входных и prompt-хешей всех кандидатов.

### До решения о переключении

1. Заморозить отдельные 150–200 реальных ответов с полными исходящими до ответа, брифом и применимым кастомным критерием. В квалификационной БД исходящее сохраняется лишь как 300-символьный preview — его недостаточно для честного восстановления входа модели.
2. Включить обычные лиды, отказы, review и автоответы разных проектов/языков. Разделять выборку по треду/контакту, держать контрастные дубли вместе. Исторический вердикт бота — не эталонная метка.
3. Зафиксировать человеческие метки до просмотра модельных ответов. Неоднозначные границы согласовать отдельно, не включать в accuracy по предположению.
4. Проверить GPT-4o mini против основного кандидата на этой независимой выборке, затем отдельно исследовать изменение противоречивого контекста/промпта. Не смешивать замену модели и исправление промпта в одном сравнении.
5. Только после решения пользователя — настройка отдельной политики и отдельное разрешение на production-подключение. Общая политика других инструментов остаётся нетронутой.
